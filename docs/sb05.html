Spring Boot 版 · 第 5 章 · 项目二：图片书签社交网站

社交登录

这一章给用户系统补上三块：操作后的提示消息、用邮箱登录、用 Google 账号登录，最后让开发服务器跑在 HTTPS 上。 Django 靠 messages 框架、自定义认证后端和 python-social-auth 完成；Spring 对应的是闪存属性、多个 AuthenticationProvider 和 Spring Security 自带的 OAuth2 客户端 —— 后两者正是 Spring Security 最擅长的地方。

本章目标

  • 用闪存属性（flash attributes）实现 Django 的 messages 框架，并采用 PRG 模式
  • 理解 ProviderManager 按顺序尝试多个认证提供者，实现“用户名或邮箱都能登录”
  • 给注册和编辑资料加上“邮箱不能重复”的校验
  • 走通 OAuth2 / OpenID Connect 的授权码流程，把 Google 账号映射成本站用户
  • 让一个主体类同时支持表单登录和 OIDC 登录
  • 用自签名证书在本地跑 HTTPS

对应的 Django 讲解见 Django 版第 5 章；本章代码在 springboot/Chapter05/。

消息：闪存属性

Django 的 messages 框架把一次性提示存进会话（或 cookie），下一个请求在模板里读出来就删掉。 Spring MVC 有同样的底层机制 —— 闪存属性：RedirectAttributes.addFlashAttribute() 存进会话，重定向后的那个请求读到后自动清除。 我们在它上面包了一层小工具，让用法接近 Django：

Django
from django.contrib import messages

messages.success(request, 'Profile updated successfully')
messages.error(request, 'Error updating your profile')
Spring · common/Messages.java 的用法
// 重定向前：放进闪存，下一个请求可见一次
Messages.success(redirect, "Profile updated successfully");

// 直接渲染页面：放进当前模型
Messages.error(model, "Error updating your profile");

public final class Messages {

    public static final String ATTRIBUTE = "messages";

    /** 对应 Django 的 message.tags（debug/info/success/warning/error） */
    public record Message(String level, String text) { }

    public static void success(RedirectAttributes redirect, String text) {
        add(redirect.getFlashAttributes(), redirect::addFlashAttribute, "success", text);
    }

    public static void error(Model model, String text) {
        add(model.asMap(), model::addAttribute, "error", text);
    }

    // add(...)：取出已有的列表，追加一条，再放回去 —— 一个请求里可以有多条消息
}
Django · base.html
{% if messages %}
  <ul class="messages">
    {% for message in messages %}
      <li class="{{ message.tags }}">
        {{ message|safe }}
        <a href="#" class="close">x</a>
      </li>
    {% endfor %}
  </ul>
{% endif %}
Thymeleaf · base.html
<ul class="messages" th:if="${messages}">
  <li th:each="message : ${messages}" th:class="${message.level}">
    <span th:text="${message.text}">message</span>
    <a href="#" class="close"
       onclick="this.parentElement.remove(); return false;">x</a>
  </li>
</ul>
⚠ {{ message|safe }} 的隐患

书中用 |safe 输出消息，以便在消息里放链接。一旦消息里拼进了用户输入（比如“图片 标题 已保存”），就是 XSS。Spring 版用 th:text，一律转义。

顺手改成 PRG

第 4 章的编辑页保存后直接渲染页面，刷新会弹出“重新提交表单”。有了闪存消息，就可以改成 Post/Redirect/Get：

if (!userErrors.hasErrors() && !profileErrors.hasErrors()) {
    try {
        accounts.updateAccount(me.id(), userForm, profileForm);
        Messages.success(redirect, "Profile updated successfully");
        return "redirect:/account/edit/";                 // 成功：重定向，消息跟着闪存走
    } catch (InvalidImageException e) {
        profileErrors.rejectValue("photo", "invalid_image", e.getMessage());
    }
}
Messages.error(model, "Error updating your profile");     // 失败：直接渲染，保留用户输入和错误
return renderEdit(me, model);

用邮箱登录：多个认证提供者

Django 的 AUTHENTICATION_BACKENDS 是一个列表，authenticate() 依次尝试每个后端，第一个返回用户的生效。Spring Security 的 ProviderManager 做的是一模一样的事：

Django · account/authentication.py
class EmailAuthBackend:
    def authenticate(self, request,
                     username=None, password=None):
        try:
            user = User.objects.get(email=username)
            if user.check_password(password):
                return user
            return None
        except (User.DoesNotExist,
                User.MultipleObjectsReturned):
            return None

    def get_user(self, user_id):
        ...
Spring · EmailUserDetailsService.java
@Service
public class EmailUserDetailsService implements UserDetailsService {

    @Override
    @Transactional(readOnly = true)
    public UserDetails loadUserByUsername(String email) {
        List<User> matches = users.findByEmailIgnoreCase(email);
        // 找不到或找到多个都视为失败
        if (email.isBlank() || matches.size() != 1) {
            throw new UsernameNotFoundException(email);
        }
        return CurrentUser.from(matches.getFirst());
    }
}
// 比对密码交给 DaoAuthenticationProvider，不用自己写 check_password

@Bean
AuthenticationManager authenticationManager(JpaUserDetailsService byUsername,
                                            EmailUserDetailsService byEmail,
                                            PasswordEncoder passwordEncoder,
                                            AuthenticationEventPublisher eventPublisher) {
    DaoAuthenticationProvider usernameProvider = new DaoAuthenticationProvider(byUsername);
    usernameProvider.setPasswordEncoder(passwordEncoder);
    DaoAuthenticationProvider emailProvider = new DaoAuthenticationProvider(byEmail);
    emailProvider.setPasswordEncoder(passwordEncoder);
    ProviderManager manager = new ProviderManager(usernameProvider, emailProvider);
    manager.setAuthenticationEventPublisher(eventPublisher);   // 否则收不到登录成功事件
    return manager;
}

// 过滤器链里显式使用它
http.authenticationManager(authenticationManager) ...
⚠ 自己定义 AuthenticationManager 时别忘了事件发布器

Spring Boot 自动配置的认证管理器会发布登录成功/失败事件；自己 new ProviderManager(...) 时默认是“不发布”。 第 4 章的 LastLoginListener 依赖这个事件，所以这里要把 Boot 提供的 AuthenticationEventPublisher 设置进去 —— 测试里“登录后 last_login 不为空”的断言会帮你发现这个问题。

邮箱唯一

允许邮箱登录后，邮箱就必须唯一。书中给两个表单加了 clean_email：

Django
# UserRegistrationForm
def clean_email(self):
    data = self.cleaned_data['email']
    if User.objects.filter(email=data).exists():
        raise forms.ValidationError('Email already in use.')
    return data

# UserEditForm：排除自己
def clean_email(self):
    data = self.cleaned_data['email']
    qs = User.objects.exclude(id=self.instance.id
                              ).filter(email=data)
    if qs.exists():
        raise forms.ValidationError('Email already in use.')
    return data
Spring
// 注册
if (!errors.hasFieldErrors("email") && !form.getEmail().isBlank()
        && users.existsByEmailIgnoreCase(form.getEmail())) {
    errors.rejectValue("email", "unique", "Email already in use.");
}

// 编辑资料：方法名里的 IdNot ≈ exclude(id=...)
if (!userErrors.hasFieldErrors("email") && !userForm.getEmail().isBlank()
        && users.existsByEmailIgnoreCaseAndIdNot(userForm.getEmail(), me.id())) {

}
ⓘ 书中代码的一个边界问题

Django 的 User.email 可以为空。注册时不填邮箱，filter(email='') 会匹配所有同样没填邮箱的用户，于是第二个不填邮箱的人就注册不了了。Spring 版只检查非空邮箱，并且忽略大小写。

用 Google 登录：OAuth2 / OpenID Connect

书中用 python-social-auth。Spring Security 内置了完整的 OAuth2 客户端，只需一个 starter 和几行配置， 授权码流程、state 防 CSRF、令牌交换、校验 ID Token 签名都由框架完成。整个流程如下：

管道：把 Google 账号映射成本站用户

python-social-auth 用 SOCIAL_AUTH_PIPELINE 里的一串函数完成“查找或创建用户”；书中还插入了自定义的 create_profile。Spring 里继承 OidcUserService，在 loadUser 里做同样的事：

@Service
public class SocialUserService extends OidcUserService {

    @Override
    public OidcUser loadUser(OidcUserRequest request) {
        OidcUser oidc = super.loadUser(request);   // social_details / social_uid：向 Google 取用户信息
        return link(request.getClientRegistration().getRegistrationId(), oidc);
    }

    /** 与网络无关的部分单独成方法，方便测试 */
    @Transactional
    public CurrentUser link(String provider, OidcUser oidc) {
        User user = socialAuths.findByProviderAndUid(provider, oidc.getSubject())   // social_user
                .map(UserSocialAuth::getUser)
                .orElseGet(() -> createUser(provider, oidc));
        if (!user.isActive()) {                                                   // auth_allowed
            throw new DisabledException("User is disabled");
        }
        user.setLastLogin(OffsetDateTime.now(ZoneOffset.UTC));
        return CurrentUser.from(user, oidc);
    }

    private User createUser(String provider, OidcUser oidc) {
        // get_username + create_user：邮箱前缀做用户名，重名加数字
        ...
        User user = new User(username, passwordEncoder.encode(UUID.randomUUID().toString()), email);
        user.setFirstName(oidc.getGivenName());                                  // user_details
        user.setLastName(oidc.getFamilyName());
        users.save(user);
        profiles.save(new Profile(user));                                         // create_profile
        socialAuths.save(new UserSocialAuth(user, provider, oidc.getSubject()));  // associate_user
        return user;
    }
}

💡 用 sub 识别用户，不要用邮箱

OIDC 的 sub（subject）是 Google 给这个账号的永久唯一标识；邮箱可能改变，也可能被别的账号“接手”。所以绑定表存的是 (provider, uid=sub)，并加了唯一约束。测试 secondLoginReusesTheSameUser 验证了邮箱变了仍然识别为同一个人。

一个主体类，两种登录方式

表单登录时，会话里的主体是 UserDetails；OIDC 登录时是 OidcUser。如果两者类型不同，控制器里的 @AuthenticationPrincipal CurrentUser me 在 Google 登录后就会是 null。解决办法是让 CurrentUser 同时实现两个接口： 

public record CurrentUser(Long id, String username, String password, boolean enabled,
                          List<GrantedAuthority> authorities, OidcUser oidc)
        implements UserDetails, OidcUser {

    /** Authentication.getName() 最终返回它：两种方式下都是本站用户名 */
    @Override
    public String getName() { return username; }

    @Override
    public Map<String, Object> getClaims() { return oidc == null ? Map.of() : oidc.getClaims(); }

    @Override
    public OidcIdToken getIdToken() { return oidc == null ? null : oidc.getIdToken(); }
    ...
}

这相当于 Django 里无论用哪个后端登录，request.user 都是同一个 User 模型 —— 在 Spring 里需要我们自己保证这一点。

本地 HTTPS

Google 要求回调地址使用 HTTPS（localhost 除外）。书中用 django-extensions 的 runserver_plus --cert-file；Spring Boot 的内嵌 Tomcat 直接支持 SSL，只需要一个证书：

keytool -genkeypair -alias dev -keyalg RSA -keysize 2048 -validity 365 \
  -storetype PKCS12 -keystore certs/dev.p12 -storepass changeit \
  -dname "CN=mysite.com" -ext "SAN=dns:mysite.com,dns:localhost,ip:127.0.0.1"

---
spring:
  config:
    activate:
      on-profile: https          # --spring.profiles.active=https
server:
  port: 8443
  ssl:
    key-store: file:certs/dev.p12
    key-store-password: ${SSL_KEYSTORE_PASSWORD:changeit}
    key-store-type: PKCS12

./scripts/dev-cert.sh
echo "127.0.0.1 mysite.com" | sudo tee -a /etc/hosts
mvn spring-boot:run -Dspring-boot.run.profiles=https
# 访问 https://mysite.com:8443/ （浏览器会提示证书不受信任，开发时手动信任即可）
💡 想要浏览器不报警告

用 mkcert 生成一个本机受信任的证书（它会把自己的根证书装进系统信任库），再导出成 PKCS12 使用。生产环境一般由 Nginx 终止 TLS，应用本身仍然跑 HTTP（第 17 章）。

ⓘ ALLOWED_HOSTS 呢？

书中为 mysite.com 修改了 ALLOWED_HOSTS，这是 Django 防御 Host 头攻击的机制。Spring Boot 没有同名设置。 而我们的代码确实依赖 Host 头：ServletUriComponentsBuilder 用它生成找回密码邮件里的链接。 如果不加限制，攻击者可以伪造 Host 头，让受害者收到指向恶意域名的重置链接。 生产环境应该在 Nginx 里只接受已知域名（第 17 章配置），或者把站点地址写进配置而不是从请求里取。

差异点评

🔍 第 5 章 Spring 版点评 springboot/Chapter05

做得好 OAuth2 是 Spring Security 的“主场”

不需要第三方库，state 参数、授权码换令牌、ID Token 签名校验都由框架处理。换成 GitHub 登录只需再加一个 registration（GitHub 是 OAuth2 而非 OIDC，要实现 OAuth2UserService）。

做得好 消息默认转义、采用 PRG

避免了 |safe 的 XSS 风险，也消除了刷新重复提交。

注意 按邮箱前缀生成用户名可能暴露信息

用户名会出现在个人主页 URL 里（第 7 章），用邮箱前缀当用户名等于公开了半个邮箱地址。python-social-auth 默认也这么做。可以改为随机用户名，让用户首次登录后自己设置。

注意 已有本站账号的人用 Google 登录会得到第二个账号

和书中的管道一样，没有“邮箱相同就自动关联”。自动关联需要确认 Google 已验证该邮箱（email_verified 声明），否则可能被人用未验证的邮箱接管账号。更稳妥的是让已登录用户在设置页主动绑定。

补充知识 为什么 client-id 有一个“占位默认值”

Spring Boot 校验 OAuth2 注册时要求 client-id 非空，否则启动失败。给一个明显的占位值，让没有配置 Google 的开发者也能启动项目；真正登录时 Google 会报 “invalid_client”。

小结

  • 闪存属性 ≈ messages：重定向前存进会话，下一个请求读完即删；配合 PRG 使用。
  • ProviderManager ≈ AUTHENTICATION_BACKENDS：依次尝试多个提供者。自定义管理器时记得设置事件发布器。
  • OAuth2 登录：配置 registration、开启 oauth2Login()、在 OidcUserService 里把第三方账号映射成本站用户。
  • 让主体类同时实现 UserDetails 和 OidcUser，控制器就不必关心用户是怎么登录的。
  • 内嵌 Tomcat 配置 server.ssl.* 即可跑 HTTPS。
