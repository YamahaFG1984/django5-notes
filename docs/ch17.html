第 17 章 · 项目四：在线学习平台

上线部署

一直以来我们都在用 runserver 和 SQLite 做开发。这一章把 Educa 平台搬进一个“像生产环境”的环境： 设置按环境拆分，用 Docker Compose 同时运行 PostgreSQL、Redis、uWSGI、Daphne 和 Nginx， 配置静态文件和 HTTPS，最后再学两个很实用的扩展点：自定义中间件和自定义管理命令。

本章目标

  • 把 settings.py 拆成 base / local / prod，用环境变量读取机密信息
  • 理解 Dockerfile 与 docker-compose.yml，把多个服务编排在一起
  • 理解 Nginx → uWSGI（HTTP）与 Nginx → Daphne（WebSocket）的分工
  • 用 collectstatic 收集静态文件并交给 Nginx
  • 用 check --deploy 检查安全设置，配置 SSL/TLS 和 HTTPS 重定向
  • 编写函数式中间件（子域名跳转）和带参数的管理命令

按环境拆分设置

开发环境和生产环境有很多共同的设置（已安装应用、中间件、模板……），也有一些必须不同（DEBUG、数据库、域名、密钥）。常见做法是“一个基础文件 + 每个环境一个文件”：

from decouple import config

from .base import *

DEBUG = False
ADMINS = [('Antonio M', 'email@mydomain.com')]    # 出错时 Django 会给这些人发邮件
ALLOWED_HOSTS = ['.educaproject.com']              # 前导点：匹配主域名和所有子域名

DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': config('POSTGRES_DB'),              # python-decouple 从环境变量读取
        'USER': config('POSTGRES_USER'),
        'PASSWORD': config('POSTGRES_PASSWORD'),
        'HOST': 'db',                               # Compose 里的服务名就是主机名
        'PORT': 5432,
    }
}

REDIS_URL = 'redis://cache:6379'
CACHES['default']['LOCATION'] = REDIS_URL
CHANNEL_LAYERS['default']['CONFIG']['hosts'] = [REDIS_URL]

# Security
CSRF_COOKIE_SECURE = True
SESSION_COOKIE_SECURE = True
SECURE_SSL_REDIRECT = True

python manage.py runserver --settings=educa.settings.local
# 或者设一次环境变量
export DJANGO_SETTINGS_MODULE=educa.settings.local

Docker Compose：一次启动所有服务

镜像（image）是一个打包好的“文件系统 + 运行环境”，容器（container）是镜像跑起来的实例。 Dockerfile 描述怎样构建我们自己的 Django 镜像；docker-compose.yml 描述要同时运行哪些容器、它们如何连接。 

# Pull official base Python Docker image
FROM python:3.12.3

# Set environment variables
ENV PYTHONDONTWRITEBYTECODE=1     # 不生成 .pyc
ENV PYTHONUNBUFFERED=1            # 日志立即输出，不缓冲

WORKDIR /code

RUN pip install --upgrade pip
COPY requirements.txt .
RUN pip install -r requirements.txt   # 先装依赖：requirements 不变时这一层可以复用缓存

COPY . .

services:
  db:
    image: postgres:16.2
    restart: always
    volumes:
      - ./data/db:/var/lib/postgresql/data
    environment:
      - POSTGRES_DB=postgres
      - POSTGRES_USER=postgres
      - POSTGRES_PASSWORD=postgres

  web:
    build: .
    command: ["./wait-for-it.sh", "db:5432", "--",
              "uwsgi", "--ini", "/code/config/uwsgi/uwsgi.ini"]
    restart: always
    volumes:
      - .:/code
    environment:
      - DJANGO_SETTINGS_MODULE=educa.settings.prod
      - POSTGRES_DB=postgres
      - POSTGRES_USER=postgres
      - POSTGRES_PASSWORD=postgres
    depends_on:
      - db
      - cache
⚠ depends_on 只保证“先启动”，不保证“已就绪”

PostgreSQL 第一次启动要初始化数据库，可能要好几秒。书中用 wait-for-it.sh db:5432 等端口可连接后再启动 Django。现代 Compose 还可以给 db 加 healthcheck（pg_isready），再写 depends_on: {db: {condition: service_healthy}}。

docker compose up                                              # 启动全部服务
docker compose exec web python /code/educa/manage.py migrate   # 在容器里执行命令
docker compose exec web python /code/educa/manage.py createsuperuser
docker compose exec web python /code/educa/manage.py collectstatic

uWSGI、Nginx 与 Daphne

runserver 只为开发设计：单进程、不够安全、不擅长发静态文件。生产环境要分工：

  1. Nginx 面向互联网：终结 TLS、直接发送静态/媒体文件、按路径把请求转给后端。
  2. uWSGI 是 WSGI 应用服务器：管理多个 worker 进程，通过 Unix socket 接收 Nginx 转来的普通 HTTP 请求。
  3. Daphne 是 ASGI 服务器：处理以 /ws/ 开头的 WebSocket 连接。
[uwsgi]
socket=/code/educa/uwsgi_app.sock   # 通过 Unix socket 和 Nginx 通信
chdir = /code/educa/
module=educa.wsgi:application
master=true
chmod-socket=666
uid=www-data
gid=www-data
vacuum=true                           # 退出时清理 socket 文件

upstream uwsgi_app { server unix:/code/educa/uwsgi_app.sock; }
upstream daphne    { server daphne:9001; }

server {
    listen       80;
    server_name  *.educaproject.com educaproject.com;
    return 301 https://$host$request_uri;          # HTTP 一律跳到 HTTPS
}

server {
    listen       443 ssl;
    ssl_certificate      /code/educa/ssl/educa.crt;
    ssl_certificate_key  /code/educa/ssl/educa.key;
    server_name  *.educaproject.com educaproject.com;

    location / {
        include      /etc/nginx/uwsgi_params;
        uwsgi_pass   uwsgi_app;
    }
    location /ws/ {
        proxy_pass          http://daphne;
        proxy_http_version  1.1;
        proxy_set_header    Upgrade $http_upgrade;      # WebSocket 握手需要这两个头
        proxy_set_header    Connection "upgrade";
        proxy_redirect      off;
    }
    location /static/ { alias /code/educa/static/; }
    location /media/  { alias /code/educa/media/; }
}
💡 静态文件的一条流水线

每个应用的 static/ 目录 → collectstatic → STATIC_ROOT（一个目录）→ Nginx 的 location /static/。DEBUG=False 时 Django 不再替你发静态文件，这就是第一次启动时后台“没有样式”的原因。

自定义中间件

中间件是包在视图外面的一层层“洋葱皮”：请求按 MIDDLEWARE 列表的顺序从外往里走，响应按相反顺序从里往外走。任何一层都可以直接返回响应，让请求不再往里走（短路）。

from django.shortcuts import get_object_or_404, redirect
from django.urls import reverse

from .models import Course


def subdomain_course_middleware(get_response):     # 工厂：启动时调用一次
    """
    Subdomains for courses
    """
    def middleware(request):                        # 每个请求调用一次
        host_parts = request.get_host().split('.')
        if len(host_parts) > 2 and host_parts[0] != 'www':
            course = get_object_or_404(Course, slug=host_parts[0])
            course_url = reverse('course_detail', args=[course.slug])
            url = '{}://{}{}'.format(request.scheme, '.'.join(host_parts[1:]), course_url)
            return redirect(url)                     # 短路，不再调用视图
        response = get_response(request)
        return response

    return middleware

自定义管理命令

放在应用的 management/commands/ 目录下的每个模块，都会成为一个 manage.py 子命令，模块名就是命令名。

students/
    management/
        __init__.py
        commands/
            __init__.py
            enroll_reminder.py   # → python manage.py enroll_reminder

class Command(BaseCommand):
    help = 'Sends an e-mail reminder to users registered more' \
           'than N days that are not enrolled into any courses yet'

    def add_arguments(self, parser):
        parser.add_argument('--days', dest='days', type=int)    # argparse 语法

    def handle(self, *args, **options):
        emails = []
        subject = 'Enroll in a course'
        date_joined = timezone.now().today() - datetime.timedelta(days=options['days'] or 0)
        users = User.objects.annotate(
            course_count=Count('courses_joined')
        ).filter(course_count=0, date_joined__date__lte=date_joined)
        for user in users:
            message = f"""Dear {user.first_name},
            We noticed that you didn't enroll in any courses yet.
            What are you waiting for?"""
            emails.append((subject, message, settings.DEFAULT_FROM_EMAIL, [user.email]))
        send_mass_mail(emails)                       # 一次 SMTP 连接发送所有邮件
        self.stdout.write(f'Sent {len(emails)} reminders')

代码点评

🔍 第 17 章代码点评 Chapter17/

做得好 设置分层、限定主机、Nginx 分工清晰

设置拆成 base/local/prod，数据库凭据用 python-decouple 从环境变量读取；ALLOWED_HOSTS 收紧到自己的域名；静态文件由 Nginx 直接发送，HTTP→HTTPS 在 Nginx 层重定向；WebSocket 补上了 AllowedHostsOriginValidator 与 wss://；提醒邮件用 send_mass_mail 复用一条 SMTP 连接。

有问题 子域名中间件把“用 IP 访问”全部变成 404 Chapter17/educa/courses/middleware.py:13

中间件写在 base.py 里，本地环境同样生效。按书上说的打开 http://127.0.0.1:8000/： '127.0.0.1:8000'.split('.') 得到 4 段，第一段 '127' 被当成课程 slug —— 每一个页面都 404。 负载均衡器、容器编排平台用 IP 做健康检查时也会失败。 判断“是不是子域名”应该和配置好的主域名比较，而不是数点号： 

# settings/base.py
SITE_DOMAIN = 'educaproject.com'          # local.py 中可以改成 'localhost'

# courses/middleware.py
def subdomain_course_middleware(get_response):
    base = settings.SITE_DOMAIN

    def middleware(request):
        host = request.get_host().split(':')[0].lower()
        if host.endswith('.' + base):
            subdomain = host.removesuffix('.' + base)
            if subdomain != 'www':
                course = get_object_or_404(Course, slug=subdomain)
                return redirect(f'{request.scheme}://{base}{course.get_absolute_url()}')
        return get_response(request)

    return middleware

另外，只做重定向的中间件放在列表靠前的位置（SecurityMiddleware 之后）即可，没必要先走完会话、CSRF、认证。需要更完整的子域名路由时可以用 django-hosts。

有问题 机密信息都在版本库里 TSD：设置与环境变量

① SECRET_KEY 仍然写死在 base.py，生产也用这一个；② TLS 私钥 educa/ssl/educa.key 被提交进仓库； ③ 数据库密码 postgres 明文写在 docker-compose.yml 里。 Two Scoops 的原则是：机密只来自环境（或密钥管理服务），缺失时立即报错，而不是悄悄用一个默认值。 

SECRET_KEY = config('DJANGO_SECRET_KEY')            # 没设置就抛异常，启动失败
DATABASES = {'default': {
    'ENGINE': 'django.db.backends.postgresql',
    'NAME': config('POSTGRES_DB'),
    'USER': config('POSTGRES_USER'),
    'PASSWORD': config('POSTGRES_PASSWORD'),
    'HOST': config('POSTGRES_HOST', default='db'),
    'PORT': config('POSTGRES_PORT', default=5432, cast=int),
    'CONN_MAX_AGE': 60,
    'CONN_HEALTH_CHECKS': True,
}}

Compose 里改用 env_file: .env.prod，把 .env*、ssl/*.key、data/ 加进 .gitignore 和 .dockerignore。已经提交过的密钥要视为泄露，重新生成。

有问题 拆分设置后，默认设置模块指向了空文件 educa/manage.py、wsgi.py、asgi.py

三个入口文件都还是 os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'educa.settings')。拆分后 educa.settings 是一个空的 __init__.py， 忘了写 --settings 时会报 “SECRET_KEY setting must not be empty” 这类让初学者摸不着头脑的错误。 建议 manage.py 默认 educa.settings.local，wsgi.py/asgi.py 默认 educa.settings.prod（或者不给默认值，强制要求设置环境变量）。

建议改进 开发工具混进了生产设置 TSD：多份 requirements

debug_toolbar（应用、排在第一位的中间件、__debug__/ URL）、redisboard，以及 EMAIL_BACKEND = console 都在 base.py 里。 最后一项影响最大：生产环境的 ADMINS 报错邮件和提醒邮件都只会打印到容器日志里，没人收得到。 把它们移进 local.py；prod 配置真正的 SMTP 或邮件服务。依赖也按 Two Scoops 拆成 requirements/base.txt、local.txt、production.txt，生产镜像就不必安装调试工具。

建议改进 Docker 镜像与 Compose 的生产化

① 生产环境仍然 volumes: - .:/code 把宿主机源码挂进容器 —— 这是开发模式，镜像里 COPY . . 的内容被覆盖，部署的并不是构建出来的那个镜像； ② 没有 .dockerignore，data/db、SQLite 文件、私钥都会被复制进镜像； ③ 容器以 root 运行，可以 RUN useradd 后 USER app； ④ 基础镜像可换成 python:3.12-slim，pip install --no-cache-dir； ⑤ collectstatic 放进构建步骤，migrate 作为独立的发布步骤，而不是手工 exec； ⑥ 仓库里的 web 服务仍然映射了 8000 端口，但 uWSGI 只监听 socket，这个映射是多余的（书中正文已要求删除）。

建议改进 还缺的几项生产配置

① Nginx 默认 client_max_body_size 1m，讲师上传超过 1 MB 的课程图片/文件会得到 413，需要显式调大； ② Daphne 在代理后面要加 --proxy-headers，Nginx 的 /ws/ 块补上 X-Forwarded-For、X-Forwarded-Proto，否则拿不到真实 IP 和协议； ③ 没有 LOGGING 配置，生产排错困难（见专题 3）； ④ 静态文件建议用 STORAGES["staticfiles"] 配置 ManifestStaticFilesStorage，文件名带哈希，可以放心设置长缓存； ⑤ 用真实证书后设置 SECURE_HSTS_SECONDS； ⑥ 把 manage.py check --deploy --fail-level WARNING 放进 CI。

建议改进 提醒命令的日期计算与幂等性 students/management/commands/enroll_reminder.py:21

timezone.now().today() 看起来是“带时区的今天”，实际上 today() 是类方法，返回的是服务器本地时间的 naive datetime，与 TIME_ZONE 无关（书中正文说的 .date() 才是本意）。 此外 help 字符串拼接漏了空格（“morethan”）；直接导入 User 而不是 get_user_model()；没有排除停用账号和空邮箱； 更重要的是，每天用 cron 跑一次，同一个人会每天都收到一封 —— 需要记录“已提醒”的时间。 

def handle(self, *args, days, **options):
    cutoff = timezone.localdate() - datetime.timedelta(days=days)
    users = (get_user_model().objects
             .filter(is_active=True, courses_joined__isnull=True,
                     date_joined__date__lte=cutoff)
             .exclude(email='')
             .only('first_name', 'email'))
    messages = [(subject, render_to_string('students/email/reminder.txt', {'user': u}),
                 None, [u.email]) for u in users.iterator()]
    sent = send_mass_mail(messages)
    self.stdout.write(self.style.SUCCESS(f'Sent {sent} reminders'))
# add_arguments 里：parser.add_argument('--days', type=int, default=0)

补充知识 uWSGI 之外的选择

uWSGI 官方文档已声明项目处于维护模式（只修 bug）。新项目更常见的组合是 Gunicorn（WSGI）+ Daphne/Uvicorn（ASGI）， 或者干脆只跑一个 ASGI 服务器同时处理 HTTP 和 WebSocket（例如 gunicorn -k uvicorn_worker.UvicornWorker），少维护一套进程。 如果不想自己维护 Nginx 发静态文件，WhiteNoise 也是 Django 社区的常用方案。 至于平台，Docker Compose 适合单机；多机伸缩再考虑 Kubernetes，或者直接用 PaaS（Render、Fly.io、Railway 等）。

小结

  • 设置按环境拆分；机密从环境变量读取；用 --settings 或 DJANGO_SETTINGS_MODULE 选择。
  • Docker Compose 用一个文件编排 Nginx、uWSGI、Daphne、PostgreSQL、Redis；服务名即主机名。
  • Nginx 负责 TLS、静态文件、HTTP→HTTPS 重定向，并按路径分流到 uWSGI（HTTP）和 Daphne（WebSocket）。
  • check --deploy 能发现大部分安全设置遗漏；Secure Cookie、SSL 重定向、HSTS 一起用。
  • 中间件是请求/响应的洋葱层，函数式写法是“返回函数的函数”；管理命令放在 management/commands/。
