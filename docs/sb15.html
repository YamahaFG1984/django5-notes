Spring Boot 版 · 第 15 章 · 项目四：在线学习平台

构建 API

平台要开放一个 RESTful API：列出学科和课程、选课、读取课程的全部内容。书中用的是 Django REST framework（DRF）—— 序列化器、ViewSet、Router、分页类、认证类、权限类，一整套约定。Spring MVC 本身就是为这件事设计的： @RestController 的返回值直接写成 JSON。没有 DRF 那样的“框架中的框架”，每一部分都更显式； 我们会让响应格式和 DRF 保持一致（分页的 count/next/previous/results、错误的 {"detail": ...}），这样书中的客户端脚本原样可用。

本章目标

  • 用 record 作为 DTO，替代 DRF 的序列化器；嵌套序列化器 = 嵌套 record
  • 实现 DRF 风格的分页，理解分页与集合抓取的冲突
  • 为 /api/** 配置第二条 Security 过滤器链：HTTP Basic、无状态、JSON 错误
  • 把 DRF 的对象级权限（IsEnrolled）写进服务层
  • 用 springdoc-openapi 生成接口文档；用 JDK HttpClient 写 API 客户端

对应的 Django 讲解见 Django 版第 15 章；本章代码在 springboot/Chapter15/。

Spring · ApiDtos.java
public record ModuleDto(int order, String title, String description) {
    static ModuleDto of(Module m) {
        return new ModuleDto(m.getOrder(), m.getTitle(), m.getDescription());
    }
}

/** subject、owner 输出主键（≈ PrimaryKeyRelatedField） */
public record CourseDto(Long id, Long subject, String title, String slug,
                        String overview, OffsetDateTime created,
                        Long owner, List<ModuleDto> modules) {
    public static CourseDto of(Course c) {
        return new CourseDto(c.getId(), c.getSubject().getId(), ...,
                c.getModules().stream().map(ModuleDto::of).toList());
    }
}
  • 为什么不直接返回实体：实体有懒加载关联（序列化时触发 LazyInitializationException 或 N+1）、有双向关联（无限递归）、有不该公开的字段（密码哈希）。DTO 明确写出“接口长什么样”，也让接口和表结构解耦。
  • 字段命名：Java 用驼峰（totalCourses），DRF 输出下划线（total_courses）。一行配置 spring.jackson.property-naming-strategy: SNAKE_CASE 让 JSON 与书中一致。
  • 日期：Jackson 3 默认把 OffsetDateTime 写成 ISO-8601 字符串，和 DRF 相同。
  • 计算字段：DRF 用 SerializerMethodField（get_popular_courses）；DTO 里就是一个普通字段，由服务层算好传进来。

条目：HTML 字符串还是结构化数据

书中的 ItemRelatedField 调用 item.render()，把渲染好的 HTML 放进 JSON。这里改为返回结构化数据： {"type": "video", "title": "...", "url": "..."}，图片和文件给出完整的 /media/ 地址。 API 的客户端可能是手机 App，不一定能显示 HTML；由客户端决定怎么展示更合理。

ViewSet + Router 用约定一次生成 list、retrieve 两个端点和 URL；Spring 每个端点一个方法。代码多几行，但一眼能看到全部 URL 和参数。 DefaultRouter 还提供一个 API 根视图（GET /api/ 列出各资源地址），这里也加了一个。 只读 ViewSet 对 POST /api/courses/ 返回 405；Spring 没有对应的映射时同样返回 405 Method Not Allowed。

分页：DRF 格式

public record PageResponse<T>(long count, String next, String previous, List<T> results) {

    public static <T> PageResponse<T> of(Page<T> page) {
        int current = page.getNumber() + 1;   // Spring Data 的页码从 0 开始，API 从 1 开始
        return new PageResponse<>(page.getTotalElements(),
                page.hasNext() ? pageUrl(current + 1) : null,
                page.hasPrevious() ? pageUrl(current - 1) : null,
                page.getContent());
    }

    /** 保留当前请求的其他参数（比如 page_size），只替换 page；上一页是第 1 页时去掉 page 参数 */
    private static String pageUrl(int page) {
        var builder = ServletUriComponentsBuilder.fromCurrentRequest();
        return (page == 1 ? builder.replaceQueryParam("page") : builder.replaceQueryParam("page", page))
                .build().toUriString();
    }
}
  • page_size 默认 10、最大 50（≈ page_size_query_param、max_page_size）；页码不是数字或超出范围时返回 404 {"detail": "Invalid page."}，和 DRF 一样。
  • 直接返回 Spring Data 的 Page 也可以，但它的 JSON 结构（content、totalElements、pageable……）既冗长又和实现细节绑定，Spring Data 自己也不建议直接序列化它。
  • next / previous 是绝对地址，取自当前请求的 Host —— 部署在反向代理后面时要正确转发 Host 和协议（第 17 章）。
⚠ 分页查询不要抓取集合

直觉写法是 @EntityGraph("modules") Page<Course> findAll(Pageable)。但对集合做 join fetch 后，SQL 的一行不再对应一门课程， 数据库层面的 LIMIT 就不对了 —— Hibernate 只好把所有数据查回内存再分页，并打印警告 HHH90003004。 正确做法是分页查询只抓取单值关联（subject、owner），模块在访问时由 default_batch_fetch_size=50 一次批量加载 （一条 where course_id in (...)），效果等同于 prefetch_related('modules')。

热门课程：消除 N+1

SubjectSerializer.get_popular_courses 对每个学科查一次“按学生人数排序的前 3 门课”，一页 10 个学科就是 10 条查询。 这里对一页里的学科只查一次（where s.id in :subjectIds group by ... order by count(st) desc），再在 Java 里按学科分组、各取前 3。

认证：第二条过滤器链

网页部分用会话 + 表单登录；API 用 HTTP Basic，而且应该是无状态的。Spring Security 允许多条过滤器链， 用 securityMatcher 划分地盘、@Order 决定先后： 

@Bean
@Order(1)
SecurityFilterChain apiFilterChain(HttpSecurity http) throws Exception {
    http
        .securityMatcher("/api/**")
        .authorizeHttpRequests(auth -> auth
                .requestMatchers(HttpMethod.POST, "/api/courses/*/enroll/").authenticated()
                .requestMatchers(HttpMethod.GET, "/api/courses/*/contents/").authenticated()
                .anyRequest().permitAll())                   // ≈ DjangoModelPermissionsOrAnonReadOnly
        .httpBasic(basic -> basic.authenticationEntryPoint(unauthorized))
        .exceptionHandling(ex -> ex.authenticationEntryPoint(unauthorized))
        .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .csrf(csrf -> csrf.disable());
    return http.build();
}

@Bean
@Order(2)
SecurityFilterChain securityFilterChain(HttpSecurity http, ...) { ... }   // 网页
  • 无状态：不创建、也不读取会话。浏览器里登录后的会话 cookie 不能用来调用 API。
  • 为什么可以关闭 CSRF：CSRF 攻击利用的是“浏览器自动带上 cookie”。这条链只认 Authorization 头，浏览器不会自动为跨站请求加上它，所以没有 CSRF 风险。反过来，如果 API 也接受会话认证（DRF 默认的 SessionAuthentication），就必须保留 CSRF —— DRF 在这种情况下同样会检查 CSRF。
  • 401 的格式：自定义 AuthenticationEntryPoint 返回 WWW-Authenticate: Basic realm="api" 和 {"detail": "Authentication credentials were not provided."}；密码错误时是 "Invalid username/password."，与 DRF 相同。
  • HTTP Basic 每个请求都带着明文（Base64）密码，生产环境必须走 HTTPS；更正式的 API 通常用令牌（Spring Security 的 OAuth2 Resource Server 支持 JWT）。

对象级权限：只有选了课才能看内容

Django · permissions.py
class IsEnrolled(BasePermission):
    def has_object_permission(self, request, view, obj):
        return obj.students.filter(
            id=request.user.id).exists()

@action(detail=True, methods=['get'],
        serializer_class=CourseWithContentsSerializer,
        permission_classes=[IsAuthenticated, IsEnrolled])
def contents(self, request, *args, **kwargs):
    return self.retrieve(request, *args, **kwargs)
Spring · CourseApiService
public CourseWithContentsDto contents(Long courseId, Long studentId,
                                      String mediaUrl) {
    Course course = courses.findById(courseId)
            .orElseThrow(NotFoundException::new);        // 404
    if (!courses.existsByIdAndStudentsId(courseId, studentId)) {
        throw new NotEnrolledException();                 // 403
    }
    return CourseWithContentsDto.of(course, mediaUrl);
}

// ApiExceptionHandler：@RestControllerAdvice
@ExceptionHandler(NotEnrolledException.class)
@ResponseStatus(HttpStatus.FORBIDDEN)
public Map<String, String> forbidden(NotEnrolledException e) {
    return Map.of("detail", e.getMessage());
}
  • 先 404 后 403 的顺序和 DRF 相同：get_object() 找不到对象时 404，找到了再检查对象权限。
  • @RestControllerAdvice(basePackageClasses = CourseApiController.class) 只作用于 API 包，网页部分出错仍然显示 HTML 错误页。
  • 课程 → 模块 → 内容 → 条目，三层集合都在事务里转换成 DTO，各层由批量抓取加载；条目是懒加载的代理，转换前 Hibernate.unproxy()（第 12 章讲过）。

接口文档：springdoc-openapi

DRF 的“可浏览 API”为每个端点渲染一个 HTML 页面，可以直接在浏览器里点。Spring 生态的做法是生成 OpenAPI 文档： 加入 springdoc-openapi-starter-webmvc-ui 依赖后，/v3/api-docs 是机器可读的 JSON 描述，/swagger-ui.html 是交互式页面， 可以填参数、带上 Basic 认证直接发请求。OpenAPI 文档还能生成各种语言的客户端代码，这是可浏览 API 做不到的。

差异点评

🔍 第 15 章 Spring 版点评 springboot/Chapter15

做得好 与 DRF 兼容的响应格式

分页结构、错误结构、字段命名都和书中一致，书中的客户端改一下端口就能用。

做得好 没有 N+1

分页查询不抓取集合，模块批量加载；热门课程一页只查一次。DRF 版的 get_popular_courses 每个学科一条查询。

注意 代码比 DRF 多

DRF 的 ViewSet + Router + ModelSerializer 用很少的代码生成完整的 CRUD 接口。Spring 这边每个端点、每个 DTO 都要手写。换来的是完全可见的接口定义；如果接口很多，可以考虑 Spring Data REST（按仓库自动生成接口）或从 OpenAPI 文档生成代码。

注意 没有限流

DRF 有 throttle_classes（书中没用）；Spring 没有内置限流，公开 API 通常在网关/Nginx 层做（limit_req），或者用 Bucket4j 之类的库。

补充知识 为什么参数用 String 接收页码

如果写成 @RequestParam Integer page，?page=abc 会在绑定阶段失败，返回 Spring 默认的 400 错误体。用 String 接收、自己解析，才能按 DRF 的约定返回 404 {"detail": "Invalid page."}。

小结

  • 序列化器 → record DTO；SNAKE_CASE 命名策略让 JSON 与 DRF 一致。
  • ViewSet → 显式映射的控制器方法；@RestControllerAdvice 统一 JSON 错误。
  • DRF 式分页：Pageable + 自定义 PageResponse；分页查询不要 join fetch 集合。
  • API 单独一条过滤器链：securityMatcher("/api/**")、HTTP Basic、无状态、关闭 CSRF。
  • 对象级权限写在服务层，先 404 后 403。
  • springdoc 生成 OpenAPI 文档和 Swagger UI；客户端用 JDK HttpClient。
