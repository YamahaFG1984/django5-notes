测试：让代码自己证明它是对的

前面 17 章的点评里，“写一个测试”出现了很多次，可配套仓库里一个测试都没有，每个应用的 tests.py 都只有一行注释。 这一篇从 Django 自带的 TestCase 讲起，再换到社区更常用的 pytest-django + factory_boy， 用书里真实的博客和支付代码写测试。其中有两个测试一写出来就会失败，因为它们正好撞上了仓库里的 bug。

本篇目标

  • 理解测试数据库、事务回滚，以及“准备 → 执行 → 断言”的结构
  • 用测试客户端测试视图：状态码、模板、内容、重定向、邮件
  • 用 pytest-django 的 fixture 和参数化写出更短的测试
  • 用 factory_boy 造测试数据，告别手写一长串 objects.create()
  • 用 Mock 隔离 Stripe、Celery 等外部服务；用查询计数防止 N+1 回归
  • 统计覆盖率，用 GitHub Actions 在每次推送时自动运行测试

为什么写测试、写哪些测试

手动测试是：改完代码，打开浏览器点一遍。它的问题是不会重复：改第 10 章的优惠券时，你不会再回去点一遍第 9 章的支付。 自动化测试把“点一遍”写成代码，几秒钟内把所有功能重新验证一次。

✅

一定要测

你写的业务规则（只显示已发布文章、优惠券有效期）、权限（未登录、非作者）、表单校验、边界情况（不存在的 ID、空列表）、外部回调（Webhook）。

🐛

每个 bug 一个测试

修 bug 前先写一个能复现它的失败测试，修好后它变绿，并且以后永远守着这里。

🚫

不必测

Django 和第三方库自己的功能（max_length 是否生效、Admin 页面能否打开），以及函数内部的调用顺序这类实现细节。

from django.contrib.auth import get_user_model
from django.test import TestCase

from .models import Post

            title='Draft', slug='draft', author=cls.author, body='...',

    def test_published_manager_excludes_drafts(self):

    def test_absolute_url_ends_with_slug(self):
        self.assertTrue(self.published.get_absolute_url().endswith('/hello/'))

测试视图：测试客户端

测试客户端像一个不联网的浏览器：请求直接交给 Django 处理，响应对象上还多了 context、templates 等只有测试里才有的信息。

from django.core import mail
from django.urls import reverse


class PostViewTests(TestCase):
    @classmethod
    def setUpTestData(cls):
        cls.author = get_user_model().objects.create_user('ada', password='pw')
        cls.post = Post.objects.create(title='Hello', slug='hello', author=cls.author,
                                       body='...', status=Post.Status.PUBLISHED)

    def test_detail_shows_published_post(self):
        response = self.client.get(self.post.get_absolute_url())
        self.assertContains(response, 'Hello')                 # 同时检查状态码 200
        self.assertTemplateUsed(response, 'blog/post/detail.html')

    def test_detail_hides_draft(self):
        self.post.status = Post.Status.DRAFT
        self.post.save()
        response = self.client.get(self.post.get_absolute_url())
        self.assertEqual(response.status_code, 404)

    def test_share_sends_one_email(self):
        url = reverse('blog:post_share', args=[self.post.id])
        self.client.post(url, {'name': 'Ada', 'email': 'ada@example.com',
                               'to': 'bob@example.com', 'comments': 'Nice'})
        self.assertEqual(len(mail.outbox), 1)                   # 测试时邮件进内存，不会真的发出
        self.assertEqual(mail.outbox[0].to, ['bob@example.com'])

    def test_comment_rejects_get(self):
        url = reverse('blog:post_comment', args=[self.post.id])
        self.assertEqual(self.client.get(url).status_code, 405)  # @require_POST

factory_boy：造测试数据

每个测试都手写 Post.objects.create(title=..., slug=..., author=..., body=...) 又长又脆：模型加一个必填字段，所有测试都要改。工厂把“一个合法对象长什么样”写在一个地方，测试里只写和本测试有关的字段。

import factory
from django.contrib.auth import get_user_model
from django.utils import timezone
from django.utils.text import slugify

from blog.models import Comment, Post


class UserFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = get_user_model()
        django_get_or_create = ('username',)

    username = factory.Sequence(lambda n: f'user{n}')          # user0, user1, ...
    email = factory.LazyAttribute(lambda o: f'{o.username}@example.com')
    password = factory.django.Password('secret')               # 自动 set_password


class PostFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = Post

    title = factory.Sequence(lambda n: f'Post number {n}')
    slug = factory.LazyAttribute(lambda o: slugify(o.title))
    author = factory.SubFactory(UserFactory)                    # 自动创建作者
    body = factory.Faker('paragraph')
    status = Post.Status.PUBLISHED                              # 大多数测试需要已发布的文章
    publish = factory.LazyFunction(timezone.now)

    @factory.post_generation
    def tags(self, create, extracted, **kwargs):               # PostFactory(tags=['django'])
        if create and extracted:
            self.tags.add(*extracted)


class CommentFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = Comment

    post = factory.SubFactory(PostFactory)
    name = factory.Faker('name')
    email = factory.Faker('email')
    body = factory.Faker('sentence')

隔离外部服务：Mock

测试里不能真的去调 Stripe、真的发邮件、真的把任务交给 Celery：会慢、会不稳定、会花钱。做法是在系统边界把外部服务换成替身。

ⓘ 任务在事务提交后才派发时怎么测

第 8 章点评建议把 order_created.delay(order.id) 改成 transaction.on_commit(lambda: order_created.delay(order.id))。 测试运行在一个最终会回滚的事务里，on_commit 回调默认永远不会执行。用 fixture 捕获并执行它们： 

def test_order_create_queues_email(client, django_capture_on_commit_callbacks):
    # ... 准备购物车 ...
    with patch('orders.views.order_created.delay') as delay, \
         django_capture_on_commit_callbacks(execute=True) as callbacks:
        client.post(reverse('orders:order_create'), form_data)
    assert len(callbacks) == 1
    delay.assert_called_once()

TestCase 里对应的是 self.captureOnCommitCallbacks(execute=True)。

有问题 17 章里一个测试都没有 TSD：测试

每个应用的 tests.py 都只有 startapp 生成的那行注释。前面各章点评里列出的 42 个“有问题”，几乎每一个都可以写成一个会失败的测试，修好之后它就一直守着那里。

有问题 测试一写就发现：Webhook 缺少签名头时是 500 Chapter09/myshop/payment/webhooks.py:13

request.META['HTTP_STRIPE_SIGNATURE'] 在请求没有这个头时抛出 KeyError。任何人随便 POST 一下这个公开地址，就能制造一条 500 错误和一封报错邮件。改成 .get(..., '') 后，Stripe 库会以签名无效为由拒绝，返回 400。

建议改进 逻辑写在视图里，就只能通过 HTTP 来测 TSD：Fat models

下单逻辑（建订单、写订单项、清购物车、派发任务）全在 order_create 视图里，想测它就得先在会话里造一个购物车再 POST 表单。把它抽成 create_order_from_cart() 服务函数（见附录）后，可以直接调用函数来测，视图测试只需验证“表单错误时重新显示、成功时重定向”。

补充知识 端到端测试

第 6 章的书签小工具、第 13 章的拖拽排序、第 16 章的聊天室都依赖浏览器里的 JavaScript，测试客户端覆盖不到。可以用 StaticLiveServerTestCase 配合 Playwright 写几个端到端测试，只覆盖最关键的流程。

小结

  • 测试数据库独立于真库，每个测试在事务里运行并回滚，测试之间互不影响。
  • 测试客户端能完整走一遍 URL → 视图 → 模板；断言状态码、内容、模板、重定向和邮件。
  • pytest-django 用 fixture 和参数化让测试更短；factory_boy 让测试只写和自己有关的数据。
  • 在系统边界 Mock 外部服务；用查询计数防止 N+1 回归；on_commit 回调要显式捕获。
  • CI 在每次推送时跑检查、迁移检查和测试，覆盖率用来发现没有被测到的代码。
