第 14 章 · 项目四：在线学习平台

渲染与缓存内容

讲师能发课了，这一章轮到学生：浏览课程目录、注册账号、选课、按模块学习内容。 由于课程内容很少变化、访问量却很大，正好用来学习 Django 缓存框架的四个层级，以及 Memcached 和 Redis 两种缓存后端。

本章目标

  • 构建公开的课程目录与课程详情页
  • 用 UserCreationForm + CreateView 实现学生注册并自动登录
  • 用多对多关系实现选课，限制只有已选课学生能看内容
  • 用“每种内容一个模板”的方式统一渲染多态内容
  • 掌握底层 API、模板片段、视图、全站四种缓存方式
  • 配置 Memcached / Redis 缓存后端，用 Debug Toolbar 观察缓存命中

from django.db.models import Count
from django.views.generic.detail import DetailView


class CourseListView(TemplateResponseMixin, View):
    model = Course
    template_name = 'courses/course/list.html'

    def get(self, request, subject=None):
        subjects = Subject.objects.annotate(total_courses=Count('courses'))
        courses = Course.objects.annotate(total_modules=Count('modules'))
        if subject:
            subject = get_object_or_404(Subject, slug=subject)
            courses = courses.filter(subject=subject)
        return self.render_to_response({'subjects': subjects, 'subject': subject, 'courses': courses})


class CourseDetailView(DetailView):
    model = Course                                   # 按 URL 里的 pk 或 slug 取对象
    template_name = 'courses/course/detail.html'

学生注册与选课

from django.contrib.auth import authenticate, login
from django.contrib.auth.forms import UserCreationForm


class StudentRegistrationView(CreateView):
    template_name = 'students/student/registration.html'
    form_class = UserCreationForm                    # 自带两次密码比对与强度校验
    success_url = reverse_lazy('student_course_list')

    def form_valid(self, form):
        result = super().form_valid(form)            # 先保存用户
        cd = form.cleaned_data
        user = authenticate(username=cd['username'], password=cd['password1'])
        login(self.request, user)                    # 注册完直接登录
        return result

选课是课程与用户的多对多关系：

class Course(models.Model):
    # ...
    students = models.ManyToManyField(User, related_name='courses_joined', blank=True)


class CourseEnrollForm(forms.Form):
    course = forms.ModelChoiceField(queryset=Course.objects.none(), widget=forms.HiddenInput)

    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.fields['course'].queryset = Course.objects.all()

class StudentCourseDetailView(LoginRequiredMixin, DetailView):
    model = Course
    template_name = 'students/course/detail.html'

    def get_queryset(self):                          # 只有选了课的学生才能看
        qs = super().get_queryset()
        return qs.filter(students__in=[self.request.user])

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        course = self.get_object()
        if 'module_id' in self.kwargs:
            context['module'] = course.modules.get(id=self.kwargs['module_id'])
        else:
            context['module'] = course.modules.all()[0]
        return context

四种内容长得完全不同：文字要换行，图片要 <img>，文件要下载链接，视频要嵌入播放器。给基类加一个统一的 render() 方法，按模型名找对应的模板：

后端特点适用
memcached.PyMemcacheCache纯内存、极快，满了淘汰旧数据生产
redis.RedisCache（4.0+ 内置）内存、可持久化、还能兼做消息代理和计数生产（本书最终选择）
db.DatabaseCache存在数据库表里没有缓存服务时的折中
filebased.FileBasedCache每个值一个文件单机小站
locmem.LocMemCache进程内存，默认后端，多进程之间不共享开发、测试
dummy.DummyCache什么都不缓存开发时关掉缓存

四个缓存层级

from django.core.cache import cache

subjects = cache.get('all_subjects')
if not subjects:
    subjects = Subject.objects.annotate(total_courses=Count('courses'))
    cache.set('all_subjects', subjects)

all_courses = Course.objects.annotate(total_modules=Count('modules'))
if subject:
    subject = get_object_or_404(Subject, slug=subject)
    key = f'subject_{subject.id}_courses'           # 动态数据 → 动态键
    courses = cache.get(key)
    if not courses:
        courses = all_courses.filter(subject=subject)
        cache.set(key, courses)
else:
    courses = cache.get('all_courses')
    if not courses:
        courses = all_courses
        cache.set('all_courses', courses)
⚠ 缓存的是“结果”，不是“查询”

把 QuerySet 放进缓存时，它会先被求值、序列化成结果列表。取出来的东西不能再 .filter() 出正确的新查询，所以上面的代码总是从 all_courses 这个未求值的 QuerySet 出发再过滤。另外，不要缓存 None 值，否则分不清“值为空”还是“未命中”。

代码点评

🔍 第 14 章代码点评 Chapter14/educa

做得好 注册用 UserCreationForm，内容用模板多态渲染

与第 4 章自定义注册表单相比，这里直接用内置 UserCreationForm，自动获得密码强度校验；ItemBase.render() + 按模型名选模板，新增一种内容类型只需加模型和模板，不用改视图，符合“开闭原则”。

有问题 模板片段缓存的键会“串课” Chapter14/educa/students/templates/students/course/detail.html

{% cache 600 module_contents module %} 用 str(module) 作为区分依据，而 Module.__str__ 返回的是 "0. Introduction" 这样的“顺序号 + 标题”。 两门不同课程只要都有一个叫 “Introduction” 的第一模块，缓存键就完全相同 —— 先访问的课程内容会被展示给另一门课的学生，持续 10 分钟。 缓存键必须用唯一标识，并且内容修改时要失效：

（Module 目前没有 updated 字段，可以加一个，或者在内容保存时用 make_template_fragment_key() + cache.delete() 主动失效。）

有问题 课程没有模块、模块 ID 不对时直接 500 students/views.py:63

course.modules.all()[0] 在课程还没有模块时抛 IndexError；course.modules.get(id=…) 在 ID 不属于该课程时抛 DoesNotExist。另外 DetailView 已经取过对象（self.object），再调用 self.get_object() 会多查一次：

def get_context_data(self, **kwargs):
    context = super().get_context_data(**kwargs)
    modules = self.object.modules.all()
    if 'module_id' in self.kwargs:
        context['module'] = get_object_or_404(modules, id=self.kwargs['module_id'])
    else:
        context['module'] = modules.first()          # 没有模块时为 None，模板里处理
    return context

建议改进 缓存没有失效策略

讲师新建课程后，首页的课程数最多要 5 分钟才更新；空列表 [] 被缓存后因为是“假值”，if not courses 会让每次请求都重新查询。 可以用 cache.get_or_set(key, callable, timeout) 简化读取逻辑，并在课程/模块保存时（在 service 函数或信号里）cache.delete_many([...]) 主动清除相关键。 缓存的难点从来不是“存”，而是“什么时候删”。

建议改进 为登录用户的页面做整页缓存收益很低

StudentCourseDetailView 需要登录，会访问会话，SessionMiddleware 因而给响应加上 Vary: Cookie，cache_page 生成的缓存键里就包含了整个 Cookie 头 —— 等于每个会话各缓存一份，命中率低还占内存（也正因为如此才没有把 A 的页面发给 B）。对于“内容相同、用户不同”的页面，片段缓存（修正键之后）才是正确的工具。

建议改进 其他细节

① filter(students__in=[self.request.user]) 可以直接写 filter(students=self.request.user)； ② CourseEnrollForm 里 super(CourseEnrollForm, self) 是 Python 2 写法，而且先 none() 再在 __init__ 里设为 all() 并没有带来实际好处 —— 真正有用的是在这里限定“可选课程”，比如排除已选的课； ③ URL 中的 <pk>、<module_id> 应使用 <int:…>； ④ 课程详情模板里 object.modules.count、object.owner.get_full_name 各触发一次查询，可用 select_related('owner', 'subject') 和 annotate； ⑤ requirements 里为 django-embed-video 固定了 setuptools（它仍依赖 pkg_resources），这是依赖老化的信号，选型时要留意。

小结

  • 公开目录、学生区、讲师区的缓存策略各不相同。
  • UserCreationForm + CreateView 实现注册；多对多字段记录选课。
  • “每种类型一个模板 + 统一的 render()”是渲染多态内容的简洁方式。
  • 缓存有底层 API、模板片段、单视图、全站四个层级；键要唯一，失效要设计。
  • 生产环境用 Memcached 或 Redis 等共享内存缓存，本地内存缓存不跨进程。
