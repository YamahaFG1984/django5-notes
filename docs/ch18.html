代码点评总览

前面 17 章，每章末尾都有一段“代码点评”。这份附录把它们汇总起来：先看问题分布在哪里， 再给出最值得养成的 10 个习惯，然后按专题整理成可逐项核对的清单， 最后对照 Django 5.x 新特性与《Two Scoops of Django》的核心原则，给出一个“如果今天重新开始”的项目骨架。

ⓘ 先说清楚：这不是在挑原书的错

《Django 5 By Example》是一本教学书，为了让每一章聚焦一个知识点，示例代码有意省略了权限、事务、测试等“生产级”细节，这完全合理。 这里的点评是在回答另一个问题：当你把学到的东西用到真实项目里时，还需要补上什么？

问题分布

17 章里共标出了 42 个“有问题”（会造成安全漏洞、数据错误或 500 的缺陷）和 54 个“建议改进”。 按主题归类后，可以看到几条贯穿全书的主线：

🔒

安全

XSS（|safe、mark_safe、innerHTML）、GET 改数据、缺少登录/权限检查、SSRF、机密入库。

🗃

数据完整性

缺少数据库约束与事务、级联删除历史数据、Webhook 不幂等、迁移与模型不一致。

⚡

性能

列表页 N+1、每个请求重复统计、缓存没有失效策略、API 查询数随数据线性增长。

💥

健壮性

非法输入、对象不存在、大小写差异等边界情况直接变成 500。

🏗

结构与规范

没有自定义用户模型、业务逻辑写在视图里、没有测试、开发工具混入生产。

最值得养成的 10 个习惯

  1. 新项目第一天就建自定义用户模型。 哪怕只是 class User(AbstractUser): pass。以后要加字段、改用邮箱登录都不必动迁移；到处用 settings.AUTH_USER_MODEL / get_user_model() 引用它，不要 add_to_class 打补丁。
    TSD：用户模型 见 第 4 章、第 7 章、第 12 章
  2. 机密只来自环境，设置按环境拆分。 SECRET_KEY、数据库密码、API 密钥、TLS 私钥都不进版本库；缺失时启动即失败；上线前跑 check --deploy。
    TSD：设置 见 第 1 章、第 3 章、第 17 章
  3. 修改数据只用 POST，并且先检查“是谁、能不能”。 @require_POST + CSRF + @login_required / 权限；查询里带上 owner 过滤；WebSocket 端点也一样。可以考虑 5.1 的 LoginRequiredMiddleware 默认全站需要登录。
    见 第 1 章、第 13 章、第 16 章
  4. 永远不要把用户输入当 HTML 输出。 模板默认转义，别用 |safe / mark_safe 包裹用户内容；Markdown 渲染后要用 nh3 清洗；前端插入用 textContent；Python 值交给 JS 用 json_script。
    见 第 3 章、第 5 章、第 16 章
  5. 让数据库守住数据的规则。 唯一性、互斥关系用 UniqueConstraint / CheckConstraint；多步写入包在 transaction.atomic() 里；任务在提交之后再发（transaction.on_commit 或 Celery 5.4 的 delay_on_commit）；历史数据的外键用 PROTECT / SET_NULL。
    见 第 2 章、第 7 章、第 8 章
  6. 外部回调必须幂等，状态检查要在最后一刻再做一次。 Webhook 会重复投递，记录已处理的事件 ID；优惠券、库存、支付状态在结账时再验证，而不是只在“添加”时验证。
    见 第 9 章、第 10 章
  7. 对每个页面的 SQL 数量保持敏感。 列表页用 select_related / prefetch_related，统计用 annotate；开发时开 Debug Toolbar，测试里用 assertNumQueries 把查询数固定下来。
    见 第 3 章、第 6 章、第 13 章、第 15 章
  8. 不信任任何输入，别让用户看到 500。 用表单/序列化器校验，get_object_or_404 取对象，大小写用 __iexact，空 slug、空列表、非法类型名都要有分支；成功的 POST 一律重定向（PRG）。
    见 第 2 章、第 4 章、第 6 章、第 14 章
  9. 业务逻辑放在模型、QuerySet 或服务函数里。 视图只负责“解析请求 → 调用逻辑 → 返回响应”。例如 Order.objects.create_from_cart(cart, user)，同一段逻辑 Web、API、管理命令都能复用，也更好测。
    TSD：Fat models 见 第 1 章、第 8 章
  10. 从第一个模型开始写测试。 pytest-django + factory_boy 造数据；每修一个 bug 先写一个会失败的测试。本书的仓库只有第 15 章有 API 测试，这是最值得补的一块。
    TSD：测试 见 第 1 章、第 15 章

Two Scoops of Django 原则对照

原则本书示例的做法建议
每个项目都用自定义 User直接用 auth.User，Profile 一对一扩展，第 7 章用 add_to_class 打补丁第一天建 users.User(AbstractUser)；Profile 只放真正“可选”的资料
设置拆分、机密走环境变量前 16 章单一 settings；第 17 章拆分但 SECRET_KEY 仍写死一开始就拆分；用 django-environ / python-decouple，缺失即报错
应用小而专，一个应用做一件事基本做到（blog、cart、orders、coupons、payment……）保持；公共模型与工具放 core 应用
Fat models, thin views下单、支付、选课等逻辑写在视图中模型方法 / QuerySet 方法 / services.py
表单显式列出字段大多显式；第 13 章个别地方用了 exclude一律 fields = [...]
模板里不写逻辑，不用 locals()第 9 章用了 locals()显式构建 context
谨慎使用信号第 7 章用 m2m_changed 维护计数能在模型方法/服务里显式调用就不要用信号
API 版本化、认证、限流未版本化，Basic 认证见第 15 章点评
测试：每个应用有 tests 包、用工厂造数据几乎没有测试（第 15 章 API 测试除外）pytest-django + factory_boy + coverage
挑选维护良好的第三方包django-parler、django-braces 等更新变慢评估活跃度；能用 Django 内置功能就少一个依赖

如果今天重新开始：推荐的项目骨架

from django.db import models
from django.db.models.functions import Now


class TimeStampedModel(models.Model):
    created = models.DateTimeField(db_default=Now(), editable=False)
    updated = models.DateTimeField(auto_now=True)

    class Meta:
        abstract = True

from django.contrib.auth.models import AbstractUser


class User(AbstractUser):
    pass          # 先空着也行，重要的是“有”

from django.db import transaction

from .models import Order, OrderItem
from .tasks import order_created


@transaction.atomic
def create_order_from_cart(*, cart, user, form) -> Order:
    order = form.save(commit=False)
    order.user = user
    order.save()
    OrderItem.objects.bulk_create([
        OrderItem(order=order, product=item['product'],
                  price=item['price'], quantity=item['quantity'])
        for item in cart
    ])
    cart.clear()
    order_created.delay_on_commit(order.id)     # 事务提交后才派发
    return order

import pytest

from apps.orders.services import create_order_from_cart
from .factories import ProductFactory, UserFactory


@pytest.mark.django_db
def test_create_order_copies_price(cart_with, order_form):
    product = ProductFactory(price='10.00')
    cart = cart_with(product, quantity=2)
    order = create_order_from_cart(cart=cart, user=UserFactory(), form=order_form)

    product.price = '99.00'
    product.save()

    item = order.items.get()
    assert item.price == 10          # 价格快照不随商品改价变化
    assert order.get_total_cost() == 20

怎样用这份清单

  1. 先把书里的项目跑通 —— 教学代码的价值在于清晰，不要一开始就按清单全部改写。
  2. 每学完一章，回到该章的“代码点评”，挑一两条有问题动手修复，并为它写一个测试。
  3. 开始自己的项目时，从上面的“项目骨架”和“10 个习惯”起步。
  4. 上线前逐项核对“安全”和“部署与运维”两张表，并运行 python manage.py check --deploy。
