社交登录

用户系统能用了，这一章让它更好用：操作后给出提示（消息框架）、允许用邮箱登录（自定义认证后端）、 支持“用 Google 账号登录”（OAuth 2.0）。为了模拟真实环境，我们还会在本地用自定义域名和 HTTPS 运行开发服务器。

自定义认证后端：用邮箱登录

authenticate() 会按顺序询问 AUTHENTICATION_BACKENDS 里的每个后端，第一个返回用户的后端胜出。 默认只有 ModelBackend（用户名 + 密码）。一个后端只需实现两个方法：

  • authenticate(request, **credentials)：凭据有效返回用户，否则返回 None。
  • get_user(user_id)：会话期间，Django 用它根据会话里存的 ID 取回用户。
from django.contrib.auth.models import User


class EmailAuthBackend:
    """Authenticate using an e-mail address."""

    def authenticate(self, request, username=None, password=None):
        try:
            user = User.objects.get(email=username)      # 参数仍叫 username，才能复用 LoginView
            if user.check_password(password):
                return user
            return None
        except (User.DoesNotExist, User.MultipleObjectsReturned):
            return None

    def get_user(self, user_id):
        try:
            return User.objects.get(pk=user_id)
        except User.DoesNotExist:
            return None

AUTHENTICATION_BACKENDS = [
    'django.contrib.auth.backends.ModelBackend',
    'account.authentication.EmailAuthBackend',
    'social_core.backends.google.GoogleOAuth2',
]

阻止重复邮箱

既然邮箱能当登录名，它就必须唯一。内置 User 的 email 字段并不唯一，所以在表单里校验：

class UserRegistrationForm(forms.ModelForm):
    # ...
    def clean_email(self):
        data = self.cleaned_data['email']
        if User.objects.filter(email=data).exists():
            raise forms.ValidationError('Email already in use.')
        return data


class UserEditForm(forms.ModelForm):
    # ...
    def clean_email(self):
        data = self.cleaned_data['email']
        qs = User.objects.exclude(id=self.instance.id).filter(email=data)   # 排除自己
        if qs.exists():
            raise forms.ValidationError('Email already in use.')
        return data

Chapter05/bookmarks/account/forms.py 顶部只导入了 get_user_model，没有导入 User，所以注册或编辑资料时会抛 NameError: name 'User' is not defined。书中正文的表单写的是 model = User（假定导入了 User）。修复方法见点评。

OAuth 2.0 与 Google 登录

“用 Google 登录”背后是 OAuth 2.0：你的网站不接触用户的 Google 密码， 而是让用户去 Google 那边同意授权，Google 再给你一个临时凭证，你用它换取用户信息。

在 Google Cloud 控制台创建凭据

  2. “APIs & Services → OAuth consent screen”：用户类型选 External，填应用名、支持邮箱，授权域名填 mysite.com，把自己加为测试用户。

  5. 把得到的 Client ID 和 Client secret 写进 .env。

代码点评

🔍 第 5 章代码点评 Chapter05/bookmarks

有问题 forms.py 使用了未导入的 User Chapter05/bookmarks/account/forms.py:34

两个 clean_email 都引用 User，但文件只导入了 get_user_model。一执行就是 NameError。修复并顺便保持“不硬编码 User”的原则：

from django.contrib.auth import get_user_model

User = get_user_model()

这类错误用最简单的测试（提交一次注册表单）就能发现 —— 又一个“为什么要写测试”的例子。ruff/flake8 这类 linter 也会直接报 F821 未定义名称。

有问题 模型与迁移不一致：photo 被改成了 CharField Chapter05/bookmarks/account/models.py:11

仓库第 5 章的 Profile.photo 被改成 CharField(max_length=250)，但迁移文件仍是 ImageField，第 6 章又改了回去。 这会让 makemigrations --check 失败，表单变成文本框（头像上传失效），模板里的 photo.url 也会报错。 建议在 CI 里加一步 python manage.py makemigrations --check --dry-run，自动发现“改了模型忘了生成迁移”。

有问题 {{ message|safe }} 可能导致 XSS account/templates/base.html:40

消息里一旦拼进了用户输入（比如 f'已关注 {user.first_name}'），|safe 就会让名字里的 <script> 原样执行。去掉 |safe；确实需要在消息里放链接时，用 format_html() 构造，它会转义参数：

from django.utils.html import format_html

messages.success(request, format_html('Saved. <a href="{}">View profile</a>', url))

建议改进 让邮箱后端继承 ModelBackend

手写的后端少了内置 ModelBackend 的几项保护：① 不检查 is_active，被停用用户的已有会话仍有效（get_user 照样返回他）； ② 用户不存在时立即返回，响应明显更快，攻击者可以通过响应时间判断某邮箱是否注册；③ 邮箱区分大小写，A@b.com 登录不了。改成： 

from django.contrib.auth import get_user_model
from django.contrib.auth.backends import ModelBackend


class EmailAuthBackend(ModelBackend):
    def authenticate(self, request, username=None, password=None, **kwargs):
        User = get_user_model()
        try:
            user = User.objects.get(email__iexact=username)
        except (User.DoesNotExist, User.MultipleObjectsReturned):
            User().set_password(password)      # 故意跑一次哈希，抹平时间差
            return None
        if user.check_password(password) and self.user_can_authenticate(user):
            return user
        return None
    # get_user() 继承自 ModelBackend，已包含 is_active 检查

建议改进 邮箱唯一性只靠表单校验

“先查询、再插入”在并发下有竞态；Admin、shell、社交登录创建的用户也不经过这个表单。唯一性应当由数据库保证 —— 这正是第 4 章点评说的“自定义用户模型 + email = EmailField(unique=True)”。如果还要大小写不敏感，可以加 UniqueConstraint(Lower('email'), name='unique_lower_email')。

补充知识 另一个选择：django-allauth TSD：第三方包

Python Social Auth 专注于“第三方登录”。如果你还需要邮箱验证、邮箱登录、账号绑定/解绑、多因素认证等完整的账号体系， 社区里更常用的是 django-allauth，TSD 也把它列为账号注册的首选包。选型时的原则是：优先选维护活跃、文档齐全、下载量大的包。

补充知识 社交账号关联要谨慎

pipeline 里有一个可选步骤 associate_by_email：按邮箱把社交账号自动并入已有用户。只有在提供方确认邮箱已验证时才安全，否则攻击者在某个不验证邮箱的平台注册你的邮箱，就能登录你的账号。

建议改进 编辑资料仍然没有 PRG

消息框架已经就位，edit 成功时就可以 messages.success(...) 后 return redirect('edit')，而不是继续渲染。失败时渲染表单并显示字段错误即可，顶部再加一条“更新失败”的消息反而与字段错误重复。

小结

  • 消息框架提供一次性提示，最适合与“POST 成功后重定向”搭配。
  • authenticate() 按 AUTHENTICATION_BACKENDS 顺序尝试后端；后端只需 authenticate() 和 get_user()。
  • OAuth 2.0 授权码流程中，client secret 只在服务器之间使用；回调地址必须在提供方控制台登记。
  • 本地可用 hosts + runserver_plus（或 mkcert）模拟域名和 HTTPS。
  • Python Social Auth 的 pipeline 可以插入自定义步骤，例如创建 Profile。
