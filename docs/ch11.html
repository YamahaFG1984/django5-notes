Rosetta 提供一个类似 Admin 的界面，列出所有 .po 文件，可以逐条翻译、筛选“未翻译”或“模糊（fuzzy）”条目，保存时自动编译。 只有超级用户或 translators 组成员可以使用。fuzzy 是 gettext 的标记：源字符串小改后，gettext 猜测旧译文可能还能用，标记为待审核，fuzzy 条目不会被编译进 .mo。

用 django-parler 翻译模型

界面文字翻译好了，但商品名称、描述存在数据库里。Django 本身不提供模型翻译，这里用第三方包 django-parler：

from parler.models import TranslatableModel, TranslatedFields


class Product(TranslatableModel):
    translations = TranslatedFields(
        name=models.CharField(max_length=200),
        slug=models.SlugField(max_length=200),
        description=models.TextField(blank=True),
    )
    category = models.ForeignKey(Category, related_name='products', on_delete=models.CASCADE)
    image = models.ImageField(upload_to='products/%Y/%m/%d', blank=True)
    price = models.DecimalField(max_digits=10, decimal_places=2)
    available = models.BooleanField(default=True)
    created = models.DateTimeField(auto_now_add=True)
    updated = models.DateTimeField(auto_now=True)

    class Meta:
        # ordering = ['name']     # 翻译字段不在主表里，不能用于 Meta.ordering 和索引
        indexes = [models.Index(fields=['-created'])]


# settings.py
PARLER_LANGUAGES = {
    None: ({'code': 'en'}, {'code': 'es'}),
    'default': {'fallback': 'en', 'hide_untranslated': False},
}

格式本地化与 localflavor

Django 5.0 起本地化格式始终开启：同一个数字在英文页面显示 1,234.56，在西班牙语页面显示 1.234,56。输出给 JavaScript 或 JSON 的数字不能被本地化，这时关掉它：

{% load l10n %}
{% localize off %}{{ value }}{% endlocalize %}
{{ value|unlocalize }}

django-localflavor 提供各国特有的表单/模型字段（邮编、电话、身份证号……）：

from localflavor.us.forms import USZipCodeField


class OrderCreateForm(forms.ModelForm):
    postal_code = USZipCodeField()          # 只接受 XXXXX 或 XXXXX-XXXX
    class Meta:
        model = Order
        fields = ['first_name', 'last_name', 'email', 'address', 'postal_code', 'city']

做得好 惰性翻译、命名占位符、Webhook 不带语言前缀

模型、表单、settings、URL 都正确使用了 gettext_lazy；带变量的翻译用命名占位符；把 Stripe Webhook 移出 i18n_patterns，这是很多人第一次做国际化时会踩的坑。

有问题 语言切换器总是跳回首页，而且不记住选择

<a href="/{{ language.code }}/"> 无论用户在哪个页面，一切换语言就回到首页；也不会写入语言 Cookie。 Django 自带 set_language 视图：POST 语言代码和 next，它会设置 Cookie，并把 next 里的 URL 翻译成目标语言的对应地址。 

urlpatterns += [path('i18n/', include('django.conf.urls.i18n'))]   # 放在 i18n_patterns 之外

<form action="{% url 'set_language' %}" method="post">
  {% csrf_token %}
  <input type="hidden" name="next" value="{{ request.get_full_path }}">
  {% for language in languages %}
    <button name="language" value="{{ language.code }}">{{ language.name_local }}</button>
  {% endfor %}
</form>

对于 parler 翻译过 slug 的商品页，还需要用 parler 的 {% get_translated_url %} 标签生成目标语言的商品 URL。

有问题 网站提供西班牙语，却只接受美国邮编 Chapter11/myshop/orders/forms.py:9

USZipCodeField 让西班牙（5 位数字，但规则不同）、墨西哥以及其他国家的顾客都无法下单或可能被错误放行。邮编校验应该依赖“收货国家”字段动态选择（例如 localflavor 的 ESPostalCodeField、MXZipCodeField），或者只做宽松校验、把严格校验交给物流接口。

建议改进 模型翻译迁移应分三步，避免丢数据

parler 官方文档给出的做法是：① 先添加 TranslatedFields（旧字段先保留，改名避免冲突）并迁移；② 写一个数据迁移，把旧字段的值复制到默认语言的翻译行；③ 再删除旧字段。这是 Django 迁移的通用原则 —— 结构迁移和数据迁移分开，先加后删。

from django.conf import settings
from django.db import migrations


def forwards(apps, schema_editor):
    Product = apps.get_model('shop', 'Product')
    ProductTranslation = apps.get_model('shop', 'ProductTranslation')
    for p in Product.objects.all():
        ProductTranslation.objects.create(
            master_id=p.pk, language_code=settings.LANGUAGE_CODE,
            name=p.name_old, slug=p.slug_old, description=p.description_old,
        )


class Migration(migrations.Migration):
    dependencies = [('shop', '0002_add_translations')]
    operations = [migrations.RunPython(forwards, migrations.RunPython.noop)]

建议改进 翻译查询的 N+1 与排序

列表页每个商品的 product.name 都会触发一次翻译表查询；分类失去了 Meta.ordering，侧边栏顺序变得不确定。可以 Product.objects.translated().prefetch_related('translations')，排序用 .order_by('translations__name') 前先用 .translated(language) 限定语言，否则多语言的行会造成重复。

补充知识 django-parler 的维护状况与替代品 TSD：选择第三方包

书中也承认 parler 已多年未更新，这正是 TSD 提醒要评估的风险（最近一次发布、对当前 Django 版本的支持、Issue 处理情况）。 另一个常用方案是 django-modeltranslation：它在原表中为每种语言加一列（name_en、name_es），查询、排序、索引都更简单，维护也更活跃；代价是每加一种语言都要迁移。

补充知识 书中过时的地方与小技巧

① 书中说 LocaleMiddleware 会查会话中的 LANGUAGE_SESSION_KEY，该机制已在 Django 4.0 移除； ② makemessages 默认会扫描整个目录，虚拟环境放在项目里时要加 --ignore="env/*"，否则会把第三方包的字符串也收进来； ③ 不想让默认语言带前缀可以用 i18n_patterns(..., prefix_default_language=False)； ④ Rosetta 需要对 locale/ 目录有写权限，而且修改后要重启应用服务器才生效，多实例部署时各实例的文件还会不一致 —— 生产环境更推荐“在开发环境翻译、提交 .po、部署时编译”。

小结

  • 标记字符串（_()、{% translate %}）→ makemessages → 翻译 .po → compilemessages。
  • 模块级文字用 gettext_lazy；带变量用命名占位符；单复数用 ngettext / {% plural %}。
  • LocaleMiddleware 依次看 URL 前缀、Cookie、Accept-Language、LANGUAGE_CODE。
  • i18n_patterns 给 URL 加语言前缀；第三方回调地址放在外面。
  • django-parler 用翻译表存储多语言字段；改造已有模型要分步迁移避免丢数据。
