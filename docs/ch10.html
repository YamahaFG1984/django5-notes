第 10 章 · 项目三：在线商店

扩展商店

这一章给商店加两个提升销量的功能：优惠券（从购物车一路贯穿到订单、Stripe 收银台和 PDF 发票）， 以及一个基于 Redis 有序集合的“买了这个的人也买了”推荐引擎。

本章目标

  • 设计带有效期和折扣率的优惠券模型，使用字段验证器
  • 把优惠券 ID 存入会话，在购物车中计算折扣
  • 在订单上保存优惠券外键和折扣“快照”
  • 把折扣同步给 Stripe Checkout
  • 用 Redis 有序集合记录“一起购买”的次数，用 ZUNIONSTORE 聚合多商品推荐

优惠券模型

from django.core.validators import MaxValueValidator, MinValueValidator
from django.db import models


class Coupon(models.Model):
    code = models.CharField(max_length=50, unique=True)
    valid_from = models.DateTimeField()
    valid_to = models.DateTimeField()
    discount = models.IntegerField(
        validators=[MinValueValidator(0), MaxValueValidator(100)],   # 百分比 0～100
        help_text='Percentage value (0 to 100)',
    )
    active = models.BooleanField()

    def __str__(self):
        return self.code
ⓘ 验证器在哪一层生效

validators 在 ModelForm/Admin 校验和 full_clean() 时执行，不会变成数据库约束。直接 Coupon.objects.create(discount=150) 照样能存进去。需要数据库兜底时用 CheckConstraint（见点评）。

from django.utils import timezone


@require_POST
def coupon_apply(request):
    now = timezone.now()                          # 时区感知的“现在”
    form = CouponApplyForm(request.POST)
    if form.is_valid():
        code = form.cleaned_data['code']
        try:
            coupon = Coupon.objects.get(
                code__iexact=code,                # 不区分大小写的精确匹配
                valid_from__lte=now,
                valid_to__gte=now,
                active=True,
            )
            request.session['coupon_id'] = coupon.id
        except Coupon.DoesNotExist:
            request.session['coupon_id'] = None
    return redirect('cart:cart_detail')

把优惠券存进订单

class Order(models.Model):
    # ...
    coupon = models.ForeignKey(Coupon, related_name='orders', null=True, blank=True,
                               on_delete=models.SET_NULL)     # 券删了，订单还在
    discount = models.IntegerField(default=0,
                                   validators=[MinValueValidator(0), MaxValueValidator(100)])

    def get_total_cost_before_discount(self):
        return sum(item.get_cost() for item in self.items.all())

    def get_discount(self):
        total_cost = self.get_total_cost_before_discount()
        if self.discount:
            return total_cost * (self.discount / Decimal(100))
        return Decimal(0)

    def get_total_cost(self):
        return self.get_total_cost_before_discount() - self.get_discount()

推荐引擎：买了这个的人也买了

思路很朴素：同一张订单里出现的商品两两“加一分”。某商品的推荐列表，就是和它同单次数最多的那些商品。 Redis 的有序集合天生适合这种“成员 + 分数，按分数排序”的数据。 

import redis
from django.conf import settings

from .models import Product

r = redis.Redis(host=settings.REDIS_HOST, port=settings.REDIS_PORT, db=settings.REDIS_DB)


class Recommender:
    def get_product_key(self, id):
        return f'product:{id}:purchased_with'

    def products_bought(self, products):
        product_ids = [p.id for p in products]
        for product_id in product_ids:
            for with_id in product_ids:
                if product_id != with_id:
                    r.zincrby(self.get_product_key(product_id), 1, with_id)

    def suggest_products_for(self, products, max_results=6):
        product_ids = [p.id for p in products]
        if len(products) == 1:
            suggestions = r.zrange(self.get_product_key(product_ids[0]), 0, -1, desc=True)[:max_results]
        else:
            flat_ids = ''.join([str(id) for id in product_ids])
            tmp_key = f'tmp_{flat_ids}'
            keys = [self.get_product_key(id) for id in product_ids]
            r.zunionstore(tmp_key, keys)             # 合并并累加分数
            r.zrem(tmp_key, *product_ids)             # 排除购物车里已有的
            suggestions = r.zrange(tmp_key, 0, -1, desc=True)[:max_results]
            r.delete(tmp_key)
        suggested_products_ids = [int(id) for id in suggestions]
        suggested_products = list(Product.objects.filter(id__in=suggested_products_ids))
        suggested_products.sort(key=lambda x: suggested_products_ids.index(x.id))
        return suggested_products

    def clear_purchases(self):
        for id in Product.objects.values_list('id', flat=True):
            r.delete(self.get_product_key(id))

💡 为什么在“付款后”而不是“下单时”记录

下单不代表真的买了（可能放弃支付）。以付款成功为准，推荐数据更可信。这类“基于共现的推荐”简单有效，数据量大了以后可以换成协同过滤等更复杂的算法，但接口不必变。

代码点评

🔍 第 10 章代码点评 Chapter10/myshop

做得好 订单保存折扣快照，外键用 SET_NULL

优惠券被删除或修改都不影响历史订单金额；推荐数据在付款后才记录。这两个设计决策都体现了“订单是不可变的历史事实”。

有问题 优惠券只在“应用时”校验，结账时不再检查 Chapter10/myshop/cart/cart.py:84

coupon_apply 检查了有效期和 active，但 Cart.coupon 只按 ID 取券。用户在券过期前一分钟应用，一周后照样能用它下单；运营把券停用了也拦不住。 结算相关的每一步都应该重新校验： 

# coupons/models.py
class CouponQuerySet(models.QuerySet):
    def valid(self, at=None):
        at = at or timezone.now()
        return self.filter(active=True, valid_from__lte=at, valid_to__gte=at)


class Coupon(models.Model):
    ...
    objects = CouponQuerySet.as_manager()


# cart/cart.py
from functools import cached_property

@cached_property                          # 同一请求内只查一次
def coupon(self):
    if not self.coupon_id:
        return None
    return Coupon.objects.valid().filter(pk=self.coupon_id).first()

顺带解决了另一个问题：原来的 @property 每访问一次就查一次数据库，而模板里 cart.coupon、cart.coupon.code、cart.get_discount 会访问它五六次，加上上下文处理器在每个页面都会触发。

有问题 大小写不同的券码会让应用券时 500 coupons/models.py:6

code 的 unique=True 区分大小写，所以后台可以同时存在 SUMMER 和 summer；而查询用的是 code__iexact，两条都匹配时 get() 抛出 MultipleObjectsReturned。用函数唯一约束统一口径，顺便让数据库保证其他业务规则：

from django.db.models.functions import Lower


class Coupon(models.Model):
    ...
    class Meta:
        constraints = [
            models.UniqueConstraint(Lower('code'), name='coupon_code_ci_unique'),
            models.CheckConstraint(condition=models.Q(valid_to__gt=models.F('valid_from')),
                                   name='coupon_valid_range'),
            models.CheckConstraint(condition=models.Q(discount__gte=0, discount__lte=100),
                                   name='coupon_discount_0_100'),
        ]

有问题 推荐引擎的临时键会冲突 shop/recommender.py:32

临时键由商品 ID 直接拼接：购物车 [1, 23] 和 [12, 3] 都得到 tmp_123。两个用户同时浏览购物车时，一个请求可能读到另一个请求合并的结果，甚至在对方读取前把键删掉。 Redis 6.2 起有 ZUNION，直接返回合并结果而不落地存储，可以彻底去掉临时键： 

def suggest_products_for(self, products, max_results=6):
    ids = [p.id for p in products]
    keys = [self.get_product_key(i) for i in ids]
    scored = r.zunion(keys, withscores=True)                # [(b'7', 3.0), (b'9', 2.0), ...]
    ranked = sorted(scored, key=lambda kv: kv[1], reverse=True)
    exclude = {str(i).encode() for i in ids}
    top_ids = [int(m) for m, _ in ranked if m not in exclude][:max_results]
    products = Product.objects.in_bulk(top_ids)
    return [products[i] for i in top_ids if i in products]

单商品分支同样应该让 Redis 只返回前 N 个：r.zrange(key, 0, max_results - 1, desc=True)，而不是取回整个集合再切片。products_bought 里的 n² 次网络往返可以用 r.pipeline() 合并成一次。

建议改进 Webhook 里做的事越来越多

现在 Webhook 同步地：更新订单、写 Redis 推荐、触发发票任务。结合第 9 章说的“事件可能重复投递”，重复事件会让推荐分数翻倍；Redis 暂时不可用会让 Webhook 返回 500 进而被 Stripe 反复重试。 Webhook 应该只做“验签 + 幂等地记录状态”，其余工作（推荐、发票）交给一个 Celery 任务，并且只在订单第一次被标记为已付款时触发。

建议改进 每次支付都新建一个 Stripe 优惠券

用户每点一次“Pay now”（包括取消后重试）都会在 Stripe 账户里创建一个新的 Coupon 对象，时间长了会堆积成千上万个。可以在本地 Coupon 上保存一个 stripe_coupon_id，首次创建后复用；或者干脆把折扣直接体现在每个 line item 的 unit_amount 上。另外，本地按“总价 × 百分比”算折扣、Stripe 按自己的规则算，分位上的四舍五入可能不同，最终以 Stripe 实收金额（Webhook 里的 amount_total）为准对账。

建议改进 券码可以被暴力枚举

coupon_apply 不需要登录也没有限流，券码又往往是 SUMMER、VIP10 这类可猜测的单词。应加限流（如按 IP/会话每分钟 5 次），并给优惠券加“总使用次数/每人使用次数”限制（需要记录使用情况）。

补充知识 小的整洁性问题

cart_detail 里迭代了两次购物车（每次都会查一次商品表）；active = models.BooleanField() 没有默认值，用代码创建时必须显式传值；order.items.values_list('product_id') 可以更直接地写成 Product.objects.filter(order_items__order=order)。Redis 主机、端口在 settings 里写死，应与第 7 章一样改为 REDIS_URL 环境变量。

小结

  • 字段验证器只在表单/full_clean() 中生效；业务规则尽量同时用数据库约束兜底。
  • 优惠券 ID 存在会话里，折扣由 Cart 计算；关键金额在订单上保存快照。
  • 凡是影响金额的数据，在结算的每一步都要重新校验。
  • Redis 有序集合 + ZINCRBY/ZUNIONSTORE（或 ZUNION）可以实现简单实用的共现推荐。
