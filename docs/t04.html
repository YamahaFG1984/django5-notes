ORM 进阶与并发

书里用到的 ORM 大多是 filter()、get() 和偶尔一个 annotate(Count(...))。这足够做出功能，但前面各章点评里有一大类问题都出在这里： 统计把不该算的也算进去、查询数随数据量增长、两个请求同时修改同一行时数据出错。 这一篇系统地讲“让数据库替你算”的几种工具，以及并发下保证数据正确的办法。

本篇目标

  • 理解 QuerySet 的惰性：什么时候才真正执行 SQL
  • 分清 select_related、prefetch_related 与 Prefetch 对象
  • 掌握 aggregate 与 annotate，以及“多个 Count 结果翻倍”的陷阱
  • 用 F、Q、Case/When、Subquery、Exists、窗口函数把计算交给数据库
  • 理解“丢失更新”和竞态条件，用 F()、条件更新、select_for_update、唯一约束和事务解决

QuerySet 是“查询计划”，不是结果

关联查询：JOIN 还是分两次查

⚠ 预取之后别再 filter

post.comments.all() 会用上预取的结果，但 post.comments.filter(active=True) 是一个新查询，预取白做了。需要过滤就用 Prefetch(..., queryset=...) 在预取时过滤。

聚合：aggregate 与 annotate

带条件的聚合：修第 3 章的统计 bug

第 3 章的 get_most_commented_posts 用 Count('comments')，把已屏蔽（active=False）的评论也算了进去。聚合函数可以带 filter：

from django.db.models import Count, Q


@register.simple_tag
def get_most_commented_posts(count=5):
    return (
        Post.published
        .annotate(total_comments=Count('comments', filter=Q(comments__active=True)))
        .filter(total_comments__gt=0)
        .order_by('-total_comments')[:count]
    )

陷阱：两个 Count 同时出现，数字会翻倍

第 14 章的课程列表用了 annotate(total_modules=Count('modules'))，单独一个没问题。可如果再加一个学生数，结果就错了：

from django.db.models import Count, OuterRef, Subquery
from django.db.models.functions import Coalesce

# 简单做法：Count 加 distinct=True
courses = Course.objects.annotate(
    total_modules=Count('modules', distinct=True),
    total_students=Count('students', distinct=True),
)

# 通用做法：每个统计各自一个子查询，互不干扰（Sum / Avg 也适用）
module_count = (
    Module.objects.filter(course=OuterRef('pk'))
    .values('course')
    .annotate(c=Count('pk'))
    .values('c')
)
courses = Course.objects.annotate(total_modules=Coalesce(Subquery(module_count), 0))

F、Q 与条件表达式

工具作用例子
F('字段')在 SQL 里引用字段的值，而不是先读进 PythonProduct.objects.update(price=F('price') * Decimal('1.1'))
F 比较字段同一行的两个字段互相比较Coupon.objects.filter(valid_to__lt=F('valid_from'))（找出数据录错的券）
Q组合 OR、NOT 条件Post.objects.filter(Q(title__icontains=q) | Q(body__icontains=q))
Case / WhenSQL 里的 if / else见下方优惠券状态的例子
Coalesce取第一个非空值Coalesce(Subquery(...), 0)
from django.db.models import Case, CharField, Q, Value, When
from django.utils import timezone

now = timezone.now()
coupons = Coupon.objects.annotate(
    state=Case(
        When(active=False, then=Value('disabled')),
        When(valid_to__lt=now, then=Value('expired')),
        When(valid_from__gt=now, then=Value('not started')),
        default=Value('valid'),
        output_field=CharField(),
    )
)
coupons.filter(state='valid')          # 注解出来的字段也能用来过滤

子查询：Subquery、OuterRef 与 Exists

from django.db.models import Exists, OuterRef, Subquery

# 每篇文章最近一条已审核评论的时间
latest = (
    Comment.objects.filter(post=OuterRef('pk'), active=True)
    .order_by('-created')
    .values('created')[:1]
)
posts = Post.published.annotate(last_comment_at=Subquery(latest))

# 课程列表里标出“我已选修”：一条 SQL 搞定，不用在模板里逐个查
enrolled = Course.students.through.objects.filter(course=OuterRef('pk'), user=request.user)
courses = Course.objects.annotate(is_enrolled=Exists(enrolled))

# Exists 也能直接当过滤条件：有已审核评论的文章
Post.published.filter(Exists(Comment.objects.filter(post=OuterRef('pk'), active=True)))

窗口函数：分组排名

“每个分类里最便宜的 3 件商品”这类需求，用普通的 GROUP BY 做不出来。窗口函数在不合并行的前提下，给每一行算一个“在自己分组里的名次”：

from django.db.models import F, Window
from django.db.models.functions import RowNumber

products = Product.objects.filter(available=True).annotate(
    rank_in_category=Window(
        RowNumber(),
        partition_by=F('category'),          # 按分类分组
        order_by=F('price').asc(),           # 组内按价格排序
    )
).filter(rank_in_category__lte=3)            # Django 4.2 起可以直接过滤窗口函数的结果

并发：两个请求同时改一行

开发时只有你一个人点，很多问题永远不会出现。上线后，两个请求可能在同一毫秒修改同一条数据：

四种工具，按场景选

工具适用场景原理
F() 表达式更新计数器、库存加减计算在数据库里完成，不经过 Python
条件更新“库存够才扣”“未支付才标记已支付”filter(条件).update(...) 返回受影响行数，0 表示条件不满足
select_for_update()先读、再判断、再写的复杂逻辑在事务里给读到的行加锁，别的事务要等你提交
唯一约束 + 捕获 IntegrityError不允许重复（序号、关注关系、每人一票）让数据库做最终裁判，冲突时重试或提示
from django.db.models import F

updated = Product.objects.filter(pk=product_id, stock__gte=qty).update(stock=F('stock') - qty)
if updated == 0:
    raise OutOfStock()        # 库存不足，或者被别人抢先买走了

from django.db import transaction

with transaction.atomic():
    order = Order.objects.select_for_update().get(pk=order_id)   # 加锁，直到事务结束
    if order.paid:
        return                                                    # 已经处理过，幂等
    order.paid = True
    order.stripe_id = payment_intent
    order.save(update_fields=['paid', 'stripe_id'])
    transaction.on_commit(lambda: payment_completed.delay(order.id))
ⓘ SQLite 上看不出效果

SQLite 不支持 SELECT … FOR UPDATE，Django 会直接忽略 select_for_update()（SQLite 本身会锁整个数据库）。并发相关的代码和测试要在 PostgreSQL 上验证，这也是书里第 3 章起换成 PostgreSQL 的原因之一。

实例：第 12 章的 OrderField 竞态

from django.db import IntegrityError, models, transaction


class Module(models.Model):
    course = models.ForeignKey(Course, related_name='modules', on_delete=models.CASCADE)
    order = OrderField(blank=True, for_fields=['course'])
    # ...

    class Meta:
        ordering = ['order']
        constraints = [
            models.UniqueConstraint(fields=['course', 'order'], name='unique_module_order'),
        ]


def add_module(course, **fields):
    for attempt in range(3):
        try:
            with transaction.atomic():               # 失败只回滚这一次尝试
                return Module.objects.create(course=course, **fields)
        except IntegrityError:
            if attempt == 2:
                raise
💡 另一种思路：锁住“父”行

在事务里先 Course.objects.select_for_update().get(pk=course.pk)，再计算最大序号并插入。同一门课的并发添加会排队执行，不同课程之间互不影响。约束仍然建议加上，它是最后一道防线。

事务的范围

  • transaction.atomic() 里的所有写入要么全部成功，要么全部回滚；嵌套使用时内层会变成保存点（savepoint）。
  • 事务里不要调用外部服务（发邮件、调 Stripe、发 Celery 任务）：事务可能回滚，外部动作却撤不回来。用 transaction.on_commit() 在提交后再做（第 8 章点评）。
  • 事务要短：持锁期间别的请求在等，别在事务里做耗时计算或网络请求。
  • 设置 ATOMIC_REQUESTS = True 可以让每个请求自动包在一个事务里。Two Scoops 认为它对小项目是省心的默认值，但会让每个请求都持有事务，流量大时要权衡。

小结

  • QuerySet 是惰性的；要数量用 count()，要判断存在用 exists()。
  • “指向一个”用 select_related，“拥有多个”用 prefetch_related；预取时过滤用 Prefetch。
  • 聚合可以带 filter=Q(...)；多个一对多关联同时计数要 distinct=True 或用子查询。
  • F、Case/When、Subquery、Exists、窗口函数能把计算留在数据库里，一条 SQL 完成。
  • 并发下不要“读到 Python 改完再写回”：用 F 更新、条件更新、行锁或唯一约束；外部动作放在 on_commit 里。
