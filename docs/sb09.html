Spring Boot 版 · 第 9 章 · 项目三：在线商店

支付与订单

商店要能收钱了。本章接入 Stripe Checkout：顾客在 Stripe 托管的页面上付款，Stripe 通过 Webhook 通知我们付款成功， 我们把订单标记为已付款，并异步生成 PDF 发票、作为附件发给顾客。后台部分补上 Django admin 的三个进阶功能： 自定义列表列、管理动作（导出 CSV）和自定义视图（订单详情、PDF）。

本章目标

  • 用 stripe-java 创建 Checkout Session，用 303 重定向把顾客送到支付页
  • 把外部服务包在接口后面，让控制器可测试
  • 实现 Webhook：读取原始请求体、校验签名、豁免 CSRF、处理重复投递
  • 在测试里自己给 Webhook 请求签名，不依赖 Stripe 服务器
  • 用 openhtmltopdf 把 Thymeleaf 模板渲染成 PDF，用 MimeMessageHelper 发送附件
  • 在手写后台里实现管理动作、CSV 导出和自定义视图

对应的 Django 讲解见 Django 版第 9 章；本章代码在 springboot/Chapter09/。

支付流程全景

⚠ 不要在“成功页”里标记已付款

成功页的地址谁都能直接访问，顾客还可能在付款后关掉浏览器、永远不回来。只有 Stripe 服务器发来的、签名正确的 Webhook 才能作为付款成功的依据 —— 两个框架都一样。

stripe-java 推荐创建 StripeClient 实例而不是设置全局 Stripe.apiKey；注册成 Bean 后按需注入。 另一个区别：Python SDK 可以指定任意 API 版本，而 Java SDK 是强类型的，每个版本的 SDK 绑定一个 API 版本（Stripe.API_VERSION）， 升级 API 版本就是升级依赖。

把外部服务藏在接口后面

public interface StripeGateway {
    /** 创建 Checkout Session，返回 Stripe 托管支付页的地址 */

303 重定向

@PostMapping("/process/")
public ResponseEntity<Void> process(HttpSession session) {
    Order order = currentOrder(session);            // request.session.get('order_id')
    String base = ServletUriComponentsBuilder.fromCurrentContextPath().toUriString();
    String url = stripe.createCheckoutSession(order, base + "/payment/completed/", base + "/payment/canceled/");
    return ResponseEntity.status(HttpStatus.SEE_OTHER).location(URI.create(url)).build();
}

"redirect:..." 视图名发的是 302。需要 303（“POST 之后请用 GET 访问新地址”）时，直接返回 ResponseEntity 并指定状态码。

Webhook

Django · payment/webhooks.py
@csrf_exempt
def stripe_webhook(request):
    payload = request.body
    sig_header = request.META['HTTP_STRIPE_SIGNATURE']
    try:
        event = stripe.Webhook.construct_event(
            payload, sig_header,
            settings.STRIPE_WEBHOOK_SECRET)
    except ValueError:
        return HttpResponse(status=400)
    except stripe.error.SignatureVerificationError:
        return HttpResponse(status=400)

    if event.type == 'checkout.session.completed':
        session = event.data.object
        if (session.mode == 'payment'
                and session.payment_status == 'paid'):
            try:
                order = Order.objects.get(
                    id=session.client_reference_id)
            except Order.DoesNotExist:
                return HttpResponse(status=404)
            order.paid = True
            order.stripe_id = session.payment_intent
            order.save()
            payment_completed.delay(order.id)
    return HttpResponse(status=200)
Spring · StripeWebhookController
@PostMapping("/payment/webhook/")
public ResponseEntity<Void> webhook(
        @RequestBody String payload,   // 原始请求体！
        @RequestHeader(name = "Stripe-Signature",
                       required = false) String signature) {
    Event event;
    try {
        event = Webhook.constructEvent(payload, signature,
                properties.webhookSecret());
    } catch (SignatureVerificationException
             | RuntimeException e) {
        return ResponseEntity.badRequest().build();
    }
    if ("checkout.session.completed".equals(event.getType())) {
        Session session = (Session) dataObject(event);
        if ("payment".equals(session.getMode())
                && "paid".equals(session.getPaymentStatus())) {
            boolean found = payments.markPaid(
                Long.valueOf(session.getClientReferenceId()),
                session.getPaymentIntent());
            if (!found) {
                return ResponseEntity.notFound().build();
            }
        }
    }
    return ResponseEntity.ok().build();
}
  • 原始请求体：签名是对 Stripe 发出的原始字节计算的。参数写成 @RequestBody String，拿到的就是原样的 JSON；如果写成对象让 Jackson 转换，再序列化回去就不是原来的字节了，签名必然校验失败。
  • CSRF 豁免：Stripe 服务器不可能带我们的 CSRF 令牌。Spring 里在安全配置中写 csrf.ignoringRequestMatchers("/payment/webhook/") ≈ @csrf_exempt。安全性由签名保证。
  • 缺少签名头：书中 request.META['HTTP_STRIPE_SIGNATURE'] 在没有这个头时抛 KeyError（500）。这里设为 required = false，交给签名校验返回 400。

重复投递与 API 版本

@Transactional
public boolean markPaid(Long orderId, String paymentIntentId) {
    return orders.findById(orderId).map(order -> {
        if (!order.isPaid()) {                      // Stripe 可能重复投递同一个事件
            order.setPaid(true);
            order.setStripeId(paymentIntentId);
            events.publishEvent(new PaymentCompletedEvent(order.getId()));   // 提交后再发“生成发票”任务
        }
        return true;
    }).orElse(false);
}
ⓘ Webhook 要能承受重复

Stripe 在没收到 2xx 响应时会重试，网络抖动时同一事件可能到达多次。书中每次都 payment_completed.delay()，重复投递就会发两份发票。处理 Webhook 的代码必须幂等：这里检查“已付款就不再处理”。

stripe-java 只有在事件的 API 版本与 SDK 一致时，getDataObjectDeserializer().getObject() 才会返回对象；版本不一致时返回空，需要 deserializeUnsafe()。 控制器里先尝试安全方式，失败再退回宽松方式并记日志。更好的做法是在 Stripe 控制台里把 Webhook 端点的 API 版本固定为 SDK 的版本。

在测试里自己签名

Stripe 的签名算法是公开的：t=时间戳,v1=HMAC-SHA256(密钥, "时间戳.请求体")。测试里按同样的规则生成签名头，就能在没有网络的情况下走通真实的校验代码：

static String sign(String payload, String secret) throws Exception {
    long timestamp = System.currentTimeMillis() / 1000;
    Mac mac = Mac.getInstance("HmacSHA256");
    mac.init(new SecretKeySpec(secret.getBytes(UTF_8), "HmacSHA256"));
    String signature = HexFormat.of().formatHex(mac.doFinal((timestamp + "." + payload).getBytes(UTF_8)));
    return "t=" + timestamp + ",v1=" + signature;
}

// PaymentTests
mvc.perform(post("/payment/webhook/").contentType(MediaType.APPLICATION_JSON).content(payload)
                .header("Stripe-Signature", StripeSignatures.sign(payload, stripe.webhookSecret())))
        .andExpect(status().isOk());

Spring · InvoicePdfRenderer
public byte[] render(Order order) {
    Context context = new Context();
    context.setVariable("order", order);
    // ① ≈ render_to_string
    String html = templateEngine.process("orders/order/pdf", context);
    // ② HTML → PDF；基准地址让 <link href="css/pdf.css"> 能找到样式表
    String baseUri = new ClassPathResource("static/")
            .getURL().toExternalForm();
    PdfRendererBuilder builder = new PdfRendererBuilder();
    builder.useFastMode();
    builder.withHtmlContent(html, baseUri);
    builder.toStream(out);
    builder.run();
    return out.toByteArray();
}
⚠ openhtmltopdf 的限制

① 输入必须是 XHTML：所有标签都要闭合，模板里写 <br/>、<link ... />。② 只支持 CSS 2.1 加少量 CSS3，没有 flex/grid， 书中 pdf.css 里让“已付款”印章倾斜的 transform: rotate(-15deg) 不生效（印章会正着显示），其他样式都正常。WeasyPrint 对现代 CSS 的支持要好得多。 需要复杂排版时，也可以用无头 Chrome（Playwright）打印 PDF。

后台的 PDF 视图直接返回字节数组，并设置 Content-Disposition：

@GetMapping("/{id}/pdf/")
@Transactional(readOnly = true)
public ResponseEntity<byte[]> pdf(@PathVariable Long id) {

🔎 通用 vs 显式

书中的 export_to_csv 通过 modeladmin.model._meta.get_fields() 反射出任意模型的字段，一个函数给所有 ModelAdmin 复用。 Java 也能用 JPA 的 Metamodel 或反射做到，但这里选择显式列出列 —— 导出文件往往是给财务、给其他系统用的，列名和格式应该是“契约”，不应随模型字段变化而悄悄改变。 Apache Commons CSV 负责引号和逗号转义，不要自己拼字符串。

差异点评

🔍 第 9 章 Spring 版点评 springboot/Chapter09

做得好 Webhook 幂等、容错

重复事件不会重复发发票；缺少签名头返回 400 而不是 500；发票任务在支付状态提交后才入队。

做得好 类型安全的 Stripe 调用

Builder 让参数名和类型都在编译期检查；longValueExact() 避免金额被悄悄截断。

注意 订单 id 放在会话里

和书中一样，支付页从会话取 order_id。会话过期后顾客就无法再支付这个订单。更完善的做法是给订单生成一个不可猜测的公开令牌（UUID），支付链接里带上它。

注意 PDF 渲染在请求线程里做

后台点“PDF”时同步渲染；发票数量多、模板复杂时可以缓存生成结果，或者在付款时生成一次存进对象存储。

补充知识 为什么不把 Stripe 调用放进事务

PaymentController.process() 没有 @Transactional：远程调用可能耗时数秒，放在事务里会一直占着数据库连接。原则是“事务里只做数据库操作”，外部调用放在事务之外，或者像本章一样用事件在提交后触发。

小结

  • Stripe Checkout：创建 Session → 303 到托管支付页；付款结果以签名 Webhook 为准。
  • 外部服务包在接口后面，测试时替换；Webhook 签名可以在测试里自己生成。
  • Webhook 要读原始请求体、豁免 CSRF、保证幂等。
  • PDF：Thymeleaf 渲染 XHTML → openhtmltopdf；附件用 MimeMessageHelper。
  • 后台的自定义列、管理动作、自定义视图都只是普通的控制器和模板。
