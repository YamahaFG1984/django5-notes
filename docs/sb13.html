Spring Boot 版 · 第 13 章 · 项目四：在线学习平台

内容管理系统

讲师需要一个后台：创建和编辑自己的课程、批量编辑模块、往模块里添加四种不同类型的内容、拖拽调整顺序。 书中大量使用类视图（CBV）和 mixin 组合：OwnerMixin、PermissionRequiredMixin、inlineformset_factory、modelform_factory…… Spring 没有类视图体系，同样的需求用“控制器 + 服务 + 方法级安全”实现。这一章的重点是三层访问控制、把一组子表单绑定成 List、 以及拖拽排序时保留 CSRF 保护。

本章目标

  • 用数据迁移创建 “Instructors” 组；用 @PreAuthorize 实现 PermissionRequiredMixin
  • 理解“只能操作自己的数据”应该放在查询里（OwnerMixin 的本质）
  • 用 rows[0].title 形式的参数把一组子表单绑定成 List，代替 formset
  • 一个表单类处理四种内容类型，按类型校验；安全地保存上传文件
  • 拖拽排序：fetch 发送 JSON，带上 CSRF 请求头，而不是像书中那样关闭 CSRF

对应的 Django 讲解见 Django 版第 13 章；本章代码在 springboot/Chapter13/。

全景：三层访问控制

讲师组与权限

书中在 Admin 里手动创建 “Instructors” 组、勾选 courses 应用的权限，再把讲师加进组。 这种“环境里必须存在的数据”最好随代码一起走，所以写成 Flyway 数据迁移（≈ Django 的 RunPython 数据迁移）：

  • @PreAuthorize 通过 AOP 代理在方法执行前求值 SpEL 表达式；失败时抛 AuthorizationDeniedException，由 Security 过滤器翻译成响应：已登录用户得到 403，匿名用户被重定向去登录 —— 和 PermissionRequiredMixin 的 raise_exception 默认行为一致。
  • 权限代码写成常量拼进注解（Permissions.ADD_COURSE），拼错时编译不通过，比散落的字符串安全。
  • 也可以只在 URL 规则里写：.requestMatchers(POST, "/course/create/").hasAuthority(...)。放在方法上的好处是权限和代码在一起，改 URL 时不会漏。

“只能改自己的课程”放在查询里

OwnerMixin 重写 get_queryset()，给所有查询加上 filter(owner=request.user)； 于是别人的课程在 UpdateView 里“查不到”，自然返回 404。这个思路完全可以照搬：服务层的每个方法都带上 ownerId， 仓库方法名直接表达条件： 

@Transactional(readOnly = true)
public Course getCourse(Long id, Long ownerId) {
    return courses.findByIdAndOwnerId(id, ownerId).orElseThrow(NotFoundException::new);
}

// 模块、内容也一样：条件沿着关联一路走到课程的 owner
Optional<Module> findByIdAndCourseOwnerId(Long id, Long ownerId);
Optional<Content> findByIdAndModuleCourseOwnerId(Long id, Long ownerId);

// 批量更新同样带上 owner 条件：伪造别人的 id 也改不动
@Modifying
@Query("update Module m set m.order = :order where m.id = :id and m.course.owner.id = :ownerId")
int updateOrder(@Param("id") Long id, @Param("order") int order, @Param("ownerId") Long ownerId);

和“先查出来再判断 course.getOwner().equals(me)”相比，把条件放进查询有两个好处：不会忘（没有 ownerId 参数就写不出调用）， 也不会泄露存在性（别人的课程和不存在的课程都是 404）。

批量编辑模块：formset 与 List 绑定

一门课程的所有模块在一个页面上编辑：已有的每个模块一行，外加两个空行用来新增，每行一个“删除”复选框。 Django 用 inlineformset_factory(Course, Module, fields=[...], extra=2, can_delete=True) 一行生成； Spring MVC 的数据绑定天然支持带下标的属性名 —— 请求参数 rows[0].title 会被绑定到 formSet.getRows().get(0).setTitle(...)， 列表不够长时自动扩展。于是 formset 就是一个普通的类：

Django · forms.py + 模板
ModuleFormSet = inlineformset_factory(
    Course, Module,
    fields=['title', 'description'],
    extra=2, can_delete=True)

# 模板
<form method="post">
  {{ formset }}
  {{ formset.management_form }}
  {% csrf_token %}
</form>
Spring · ModuleFormSet.java + 模板
public class ModuleFormSet {
    public static final int EXTRA = 2;
    private List<@Valid Row> rows = new ArrayList<>();

    public static class Row {
        private Long id;            // 已有模块的 id，新行为空
        @Size(max = 200) private String title = "";
        private String description = "";
        private boolean delete;     // can_delete=True
    }
}

<tbody th:each="row, stat : *{rows}">
  <input type="text"
         th:field="*{rows[__${stat.index}__].title}">
  <input type="checkbox"
         th:field="*{rows[__${stat.index}__].delete}">
  <input type="hidden"
         th:field="*{rows[__${stat.index}__].id}">
</tbody>
  • __${stat.index}__ 是 Thymeleaf 的预处理：先算出下标，再把它拼进 *{rows[0].title} 表达式，th:field 才能生成正确的 name、id 并回填值和错误。
  • Django 需要 management_form（TOTAL_FORMS、INITIAL_FORMS 等隐藏字段）告诉服务器有几个子表单；Spring 按下标绑定，不需要这些。
  • “哪一行是已有模块”由隐藏字段 id 决定。保存时只在这门课自己的模块里找这个 id，找不到就 404 —— 用户可以随意修改隐藏字段，不能信任它。
Map<Long, Module> existing = course.getModules().stream()
        .collect(toMap(Module::getId, identity()));
for (ModuleFormSet.Row row : formSet.getRows()) {
    if (row.isEmptyExtra()) continue;                       // 没填的空行忽略
    if (row.getId() == null) {                              // 新行
        if (!row.isDelete()) modules.save(new Module(course, row.getTitle(), row.getDescription()));
        continue;
    }
    Module module = existing.get(row.getId());
    if (module == null) throw new NotFoundException();      // 不是这门课的模块
    if (row.isDelete()) course.getModules().remove(module); // orphanRemoval → DELETE
    else { module.setTitle(row.getTitle()); module.setDescription(row.getDescription()); }
}

校验规则与 Django formset 相同：没勾“删除”的非空行，标题必填（控制器里逐行 rejectValue("rows[" + i + "].title", ...)）； 完全空白的额外行被忽略。

多态内容的表单

书中的 ContentCreateUpdateView 很巧妙：URL 里带着模型名（/module/3/content/video/create/）， 视图用 apps.get_model() 找到模型类，再用 modelform_factory(model, exclude=[...]) 在运行时生成对应的表单。 Java 是静态类型语言，没有这么灵活的元编程；更直接的做法是一个包含所有可能字段的表单类，再按类型决定必填项和显示哪些字段：

Django · 运行时生成表单
def get_model(self, model_name):
    if model_name in ['text', 'video', 'image', 'file']:
        return apps.get_model(app_label='courses',
                              model_name=model_name)
    return None

def get_form(self, model, *args, **kwargs):
    Form = modelform_factory(model,
        exclude=['owner', 'order', 'created', 'updated'])
    return Form(*args, **kwargs)
Spring · 一个表单类 + 按类型校验
public class ItemForm {
    @NotBlank @Size(max = 250) private String title;
    private String content = "";     // text
    private String url = "";         // video
    private MultipartFile file;      // image / file
}

switch (modelName) {
    case "text" -> { if (form.getContent().isBlank())
        result.rejectValue("content", "required", "This field is required."); }
    case "video" -> { if (!form.getUrl().matches("(?i)https?://…"))
        result.rejectValue("url", "invalid", "Enter a valid URL."); }
    default -> { // image / file：新建时必须上传；图片要真的是图片
        if (!form.hasFile() && item == null)
            result.rejectValue("file", "required", ...);
        else if (modelName.equals("image") && !MediaStorage.isImage(bytes))
            result.rejectValue("file", "invalid_image", ...);
    }
}
  • 类型白名单：URL 里的 modelName 必须是四种之一，否则 404（书中 get_model 返回 None 后会在 modelform_factory 里报错，得到 500）。
  • 编辑时类型要一致：/content/video/12/ 指向的其实是文字条目时返回 404，而不是用视频表单去编辑文字。
  • 视频地址只接受 http(s)：Django 的 URLField 同样如此。下一章会把它放进 <a href> 和 <iframe src>，javascript: 地址绝不能进库。
  • 上传文件：沿用第 4 章的 MediaStorage：只保留文件名里的安全字符、加随机后缀、拒绝 ../ 路径穿越；图片用 ImageIO 检查内容（≈ ImageField 用 Pillow 检查）。编辑时不上传新文件就保留原文件（≈ ClearableFileInput）。
  • 新建内容：contents.save(new Content(module, item))，cascade = ALL 让条目一起插入；@OrderField 自动给出序号。

拖拽排序与 CSRF

内容列表页用 html5sortable 实现拖拽，放下时把新的顺序以 JSON 发给服务器。书中的两个排序视图用了 django-braces 的 CsrfExemptMixin —— 直接关闭了 CSRF 保护，理由是“fetch 请求带 CSRF 令牌麻烦”。 其实只需要把令牌放进请求头：

Django · 关闭 CSRF
class ModuleOrderView(CsrfExemptMixin,
                      JsonRequestResponseMixin, View):
    def post(self, request):
        for id, order in self.request_json.items():
            Module.objects.filter(
                id=id, course__owner=request.user
            ).update(order=order)
        return self.render_json_response({'saved': 'OK'})

var options = { method: 'POST', mode: 'same-origin' }
options['body'] = JSON.stringify(modulesOrder);
fetch(moduleOrderUrl, options)
Spring · 保留 CSRF，令牌放进请求头
@PostMapping("/module/order/")
@ResponseBody
public Map<String, String> moduleOrder(
        @RequestBody Map<Long, Integer> order,
        @AuthenticationPrincipal CurrentUser user) {
    service.reorderModules(order, user.id());
    return Map.of("saved", "OK");
}

// base.html 的 meta 标签里有令牌和请求头名
fetch(url, {
  method: 'POST',
  mode: 'same-origin',
  headers: {'Content-Type': 'application/json',
            [csrfHeader]: csrfToken},
  body: JSON.stringify(order)
});
  • @RequestBody Map<Long, Integer>：JSON 对象的键是字符串，Spring 会把它们转换成 Long；值不是整数时返回 400，不用手工解析。
  • @ResponseBody 让返回值直接序列化成 JSON（≈ JsonRequestResponseMixin 的 render_json_response）。
  • CSRF 为什么在这里也重要：没有 CSRF 保护，任何网站都能让已登录的讲师“不知不觉”地打乱自己课程的顺序。危害不大，但开一个口子就会有人照着把危害大的接口也关掉。
  • 模块序号更新后，前端用 textContent 更新页面上的数字（书中用 innerHTML，这里的值是数字，并不危险，但养成习惯更好）。

差异点评

🔍 第 13 章 Spring 版点评 springboot/Chapter13

做得好 拖拽排序保留了 CSRF 保护

书中用 CsrfExemptMixin 关掉了两个接口的 CSRF 校验；这里只多写一个请求头，测试也覆盖了“没带令牌被拒绝”。

做得好 所有入口都要求登录

书中的 CourseModuleUpdateView、ContentCreateUpdateView 等没有继承 LoginRequiredMixin：匿名用户访问时，get_object_or_404(..., owner=request.user) 拿 AnonymousUser 去查询，得到的是 500 而不是登录页。这里 /course/** 在 URL 规则里统一要求登录。

注意 模块和内容的操作不检查权限代码（与书中一致）

它们只检查“是不是自己的课程”。一个讲师被移出 Instructors 组后，仍然能编辑已有课程的模块和内容。需要的话，给这些方法也加上 @PreAuthorize("hasAuthority('courses.change_course')")。

注意 表单类里有“用不上的字段”

一个 ItemForm 装下四种类型的字段，校验规则写在控制器的 switch 里。类型再多时，可以为每种类型写一个表单类，用 Map<String, Class<?>> 按名字选择 —— 这就接近 modelform_factory 的思路了。

补充知识 删除条目时文件还留在磁盘上

Django 删除 FileField 所在的对象时也不会删除文件。要清理可以在删除成功（事务提交）后用 @TransactionalEventListener 删文件，或者定期跑一个清理命令。

小结

  • 三层访问控制：URL 规则（登录）→ @PreAuthorize（权限代码）→ 带 ownerId 的查询（只能碰自己的数据）。
  • “环境里必须有的数据”（讲师组）写成数据迁移。
  • formset = 带下标绑定的 List；隐藏的 id 只能在合法范围内查找。
  • 动态表单用“全字段表单 + 按类型校验”代替；URL 里的类型名要走白名单。
  • fetch 请求带 CSRF 请求头即可，不要为了省事关闭 CSRF。
