构建社交网站

第二个项目是一个“图片书签”社交网站：用户可以从任何网站收藏图片、互相关注、点赞、查看好友动态。 这一章先打地基 —— 用户系统：登录、登出、改密码、找回密码、注册、个人资料。 你会发现 Django 的认证框架已经把 90% 的活干完了。

本章目标

  • 理解认证框架的组成：User/Group/Permission 模型、会话、中间件
  • 分清 authenticate() 与 login()
  • 使用内置的登录、登出、改密码、重置密码视图，并覆盖它们的模板
  • 理解模板查找顺序和 INSTALLED_APPS 顺序的关系
  • 实现用户注册，理解密码哈希
  • 用一对一的 Profile 模型扩展用户，处理图片上传（媒体文件）

先手写一个登录视图

为了看清原理，书里先自己写了一遍登录：

from django.contrib.auth import authenticate, login
from django.http import HttpResponse


def user_login(request):
    if request.method == 'POST':
        form = LoginForm(request.POST)
        if form.is_valid():
            cd = form.cleaned_data
            user = authenticate(request, username=cd['username'], password=cd['password'])
            if user is not None:
                if user.is_active:
                    login(request, user)
                    return HttpResponse('Authenticated successfully')
                return HttpResponse('Disabled account')
            return HttpResponse('Invalid login')
    else:
        form = LoginForm()
    return render(request, 'account/login.html', {'form': form})

用户注册

from django import forms
from django.contrib.auth import get_user_model


class UserRegistrationForm(forms.ModelForm):
    password = forms.CharField(label='Password', widget=forms.PasswordInput)
    password2 = forms.CharField(label='Repeat password', widget=forms.PasswordInput)

    class Meta:
        model = get_user_model()               # 不要直接写 User
        fields = ['username', 'first_name', 'email']

    def clean_password2(self):                 # clean_<字段名>()：单字段校验
        cd = self.cleaned_data
        if cd['password'] != cd['password2']:
            raise forms.ValidationError("Passwords don't match.")
        return cd['password2']

def register(request):
    if request.method == 'POST':
        user_form = UserRegistrationForm(request.POST)
        if user_form.is_valid():
            new_user = user_form.save(commit=False)
            new_user.set_password(user_form.cleaned_data['password'])   # 哈希后再存！
            new_user.save()
            Profile.objects.create(user=new_user)                        # 同时建资料
            return render(request, 'account/register_done.html', {'new_user': new_user})
    else:
        user_form = UserRegistrationForm()
    return render(request, 'account/register.html', {'user_form': user_form})

扩展用户：Profile 模型

内置 User 只有少量字段。想加“生日”“头像”，最简单的办法是建一个与用户一对一的资料模型：

from django.conf import settings
from django.db import models


class Profile(models.Model):
    user = models.OneToOneField(settings.AUTH_USER_MODEL, on_delete=models.CASCADE)
    date_of_birth = models.DateField(blank=True, null=True)
    photo = models.ImageField(upload_to='users/%Y/%m/%d/', blank=True)

    def __str__(self):
        return f'Profile of {self.user.username}'

ⓘ instance= 的作用

传入已有对象时，ModelForm 用它的值作为初始值，save() 时执行 UPDATE 而不是 INSERT。两个表单放在同一个 <form> 里一起提交，只要字段名不冲突就没问题。

代码点评

🔍 第 4 章代码点评 Chapter04/bookmarks

做得好 优先使用内置认证视图，get_user_model() / AUTH_USER_MODEL

认证是安全敏感代码，能用框架的就别自己写 —— 内置视图处理了开放重定向校验、会话轮换、令牌生成、防用户枚举等细节。登出用 POST 表单、媒体文件只在 DEBUG 下由 Django 提供，也都正确。

有问题 新项目没有使用自定义用户模型 TSD：用户模型

Django 官方文档原话是：“如果你在开始一个新项目，强烈建议设置自定义用户模型，即使默认的 User 已经够用。” TSD 的建议完全一致。原因是 AUTH_USER_MODEL 在第一次 migrate 之后几乎无法再改（所有外键都指向 auth_user 表）。 本项目后面需要“邮箱唯一”（第 5 章）、“关注关系”（第 7 章甚至用了猴子补丁往 User 上加字段），这些用自定义模型都能干净地实现。开项目第一步就应该： 

# account/models.py —— 在第一次 migrate 之前！
from django.contrib.auth.models import AbstractUser
from django.db import models


class User(AbstractUser):
    email = models.EmailField('email address', unique=True)


# settings.py
AUTH_USER_MODEL = 'account.User'

# account/admin.py
from django.contrib.auth.admin import UserAdmin
admin.site.register(User, UserAdmin)

有问题 注册表单绕过了密码强度校验 Chapter04/bookmarks/account/forms.py:12

settings.AUTH_PASSWORD_VALIDATORS 配置了“最短 8 位、不能是常见密码、不能全数字”等规则，但这些规则不会自动生效 —— 只有 UserCreationForm、SetPasswordForm 等内置表单会调用它们。自定义的 UserRegistrationForm 直接 set_password()， 用户可以注册密码为 1 的账号。另外 clean_password2 里 cd['password'] 在第一个密码框留空时会抛 KeyError（该字段校验失败就不会出现在 cleaned_data 里），导致 500 错误。 

from django.contrib.auth import password_validation


class UserRegistrationForm(forms.ModelForm):
    # ...
    def clean_password2(self):
        password = self.cleaned_data.get('password')
        password2 = self.cleaned_data.get('password2')
        if password and password2 and password != password2:
            raise forms.ValidationError("Passwords don't match.")
        return password2

    def _post_clean(self):
        super()._post_clean()          # 先构造出 self.instance
        password = self.cleaned_data.get('password2')
        if password:
            try:
                password_validation.validate_password(password, self.instance)
            except forms.ValidationError as error:
                self.add_error('password2', error)

更简单的做法：直接继承 django.contrib.auth.forms.BaseUserCreationForm（或 UserCreationForm），它已经包含两次输入比对和强度校验。

有问题 没有 Profile 的用户访问编辑页会 500 Chapter04/bookmarks/account/views.py:84

Profile 只在 register 视图里创建。通过 createsuperuser 或 Admin 创建的用户没有 Profile， 访问 /account/edit/ 时 request.user.profile 抛出 RelatedObjectDoesNotExist。 书里说“第 7 章可以用信号解决”，但更直接的办法是在使用处兜底： 

profile, _ = Profile.objects.get_or_create(user=request.user)
profile_form = ProfileEditForm(instance=profile, data=request.POST, files=request.FILES)

建议改进 注册和编辑成功后都没有重定向

和第 2 章一样缺少 PRG：register 成功后直接渲染“欢迎”页，刷新会重复提交（此时会因用户名重复而报错）；edit 保存后停留在原页面。更好的体验是注册成功后直接 login(request, new_user) 并 redirect('dashboard')。

建议改进 删除不再使用的代码

user_login 视图、LoginForm、account/login.html 模板和 urls.py 里几十行被注释掉的 URL 都已经被内置视图取代，只是为教学保留。真实项目里死代码会误导维护者，应该删除（Git 历史里永远找得到）。

建议改进 上传文件没有大小和类型限制

ImageField 只校验“是 Pillow 能打开的图片”，不限制大小。可以在表单里校验 photo.size，并设置 DATA_UPLOAD_MAX_MEMORY_SIZE/FILE_UPLOAD_MAX_MEMORY_SIZE；同时在 Nginx 上配置 client_max_body_size。上传目录也不要允许执行脚本。

补充知识 Django 5.1 的 LoginRequiredMiddleware

社交网站几乎每个页面都需要登录。与其给每个视图加 @login_required（忘加一个就是漏洞），不如反过来“默认需要登录，公开页面显式豁免”：

MIDDLEWARE = [
    # ... 放在 AuthenticationMiddleware 之后
    'django.contrib.auth.middleware.LoginRequiredMiddleware',
]

from django.contrib.auth.decorators import login_not_required

@login_not_required
def register(request):
    ...

内置的 LoginView、密码重置视图已经标记为豁免。

小结

  • authenticate() 核对凭据，login() 建立会话；request.user 由认证中间件设置。
  • include('django.contrib.auth.urls') 一次引入全部认证视图，只需在 registration/ 下提供模板。
  • 同名模板按 INSTALLED_APPS 顺序“先到先得”。
  • 密码必须经 set_password() 哈希存储；自定义注册表单要记得调用密码校验器。
  • 扩展用户可用一对一 Profile；新项目应从第一天起使用自定义用户模型。
  • 上传文件需要 MEDIA_URL/MEDIA_ROOT、enctype="multipart/form-data" 和 request.FILES。
