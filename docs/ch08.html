第 8 章 · 项目三：在线商店

构建在线商店

第三个项目是一个完整的电商网站。这一章搭出骨架：商品目录、基于会话的购物车、让购物车在每个页面都可见的上下文处理器、 下单流程，以及用 Celery + RabbitMQ 在后台发送订单确认邮件。

本章目标

  • 设计分类与商品模型，理解金额为什么要用 DecimalField
  • 理解 Django 会话的工作方式与各种存储引擎
  • 用一个 Cart 类把购物车封装在会话里
  • 编写自定义上下文处理器
  • 创建订单与订单项，使用 Admin 内联
  • 理解“生产者 → 消息队列 → 工作进程”模型，用 Celery 执行异步任务并用 Flower 监控

★ 钱永远用 DecimalField

浮点数是二进制近似：0.1 + 0.2 == 0.30000000000000004。几千笔订单累加下来，账就对不上了。 DecimalField 对应 Python 的 decimal.Decimal，按十进制精确计算。max_digits=10, decimal_places=2 表示最大 99,999,999.99。

Django 会话

购物车需要在用户浏览时一直“记住”，而且未登录用户也要能用 —— 这正是会话（session）的用途。

request.session['foo'] = 'bar'     # 写
request.session.get('foo')         # 读
del request.session['foo']         # 删
request.session.modified = True    # 修改了嵌套结构时，要手动告诉 Django “已修改”

SESSION_COOKIE_SECURE只通过 HTTPS 发送False（生产要改 True）

⚠ 登录会换一个新会话

login() 会轮换会话 ID（防会话固定攻击），但会保留原来的数据；logout() 则会清空会话 —— 购物车也就没了。如果需要在登出后保留购物车，得自己在登出前取出、登出后放回。

购物车类

在会话里存一个可以 JSON 序列化的字典。键是商品 ID（JSON 的键只能是字符串），值是数量和加入时的价格：

from decimal import Decimal

from django.conf import settings
from shop.models import Product


class Cart:
    def __init__(self, request):
        self.session = request.session
        cart = self.session.get(settings.CART_SESSION_ID)     # settings 里 CART_SESSION_ID = 'cart'
        if not cart:
            cart = self.session[settings.CART_SESSION_ID] = {}
        self.cart = cart

    def add(self, product, quantity=1, override_quantity=False):
        product_id = str(product.id)
        if product_id not in self.cart:
            self.cart[product_id] = {'quantity': 0, 'price': str(product.price)}
        if override_quantity:
            self.cart[product_id]['quantity'] = quantity
        else:
            self.cart[product_id]['quantity'] += quantity
        self.save()

    def save(self):
        self.session.modified = True          # 改的是嵌套字典，Django 察觉不到，要手动标记

    def remove(self, product):
        product_id = str(product.id)
        if product_id in self.cart:
            del self.cart[product_id]
            self.save()

    def __iter__(self):
        product_ids = self.cart.keys()
        products = Product.objects.filter(id__in=product_ids)
        cart = self.cart.copy()
        for product in products:
            cart[str(product.id)]['product'] = product
        for item in cart.values():
            item['price'] = Decimal(item['price'])
            item['total_price'] = item['price'] * item['quantity']
            yield item

    def __len__(self):
        return sum(item['quantity'] for item in self.cart.values())

    def get_total_price(self):
        return sum(Decimal(item['price']) * item['quantity'] for item in self.cart.values())

    def clear(self):
        del self.session[settings.CART_SESSION_ID]
        self.save()
💡 魔术方法让 Cart 用起来像内置类型

实现了 __iter__，模板里就能 {% for item in cart %}；实现了 __len__，就能 {{ cart|length }}。这是 Python 的“鸭子类型”。

            initial={'quantity': item['quantity'], 'override': True})
    return render(request, 'cart/detail.html', {'cart': cart})

用 Celery 执行异步任务

发邮件可能要好几秒，SMTP 服务器还可能挂掉。让用户在“下单”按钮上干等不是好体验。 解决办法是把这类工作交给后台工作进程，Web 进程只负责“下个任务单”然后立刻返回。

celery -A myshop worker -l info                       # 启动 worker

import os

from celery import Celery

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'myshop.settings')

app = Celery('myshop')
app.config_from_object('django.conf:settings', namespace='CELERY')   # 读取 CELERY_ 开头的设置
app.autodiscover_tasks()                                             # 自动发现各应用的 tasks.py


# myshop/__init__.py —— 保证 Django 启动时就加载 Celery 应用
from .celery import app as celery_app

__all__ = ['celery_app']

from celery import shared_task
from django.core.mail import send_mail

from .models import Order


@shared_task
def order_created(order_id):                   # 只传 ID，执行时再查最新数据
    order = Order.objects.get(id=order_id)
    subject = f'Order nr. {order.id}'
    message = (f'Dear {order.first_name},\n\n'
               f'You have successfully placed an order.'
               f'Your order ID is {order.id}.')
    return send_mail(subject, message, 'admin@myshop.com', [order.email])
💡 为什么只传 ID

任务参数要序列化进消息。传整个对象既可能序列化失败，又会让 worker 拿到“排队那一刻”的旧数据。传 ID，让 worker 执行时从数据库取最新状态。测试或本地不想起 worker 时，可以设 CELERY_TASK_ALWAYS_EAGER = True 让任务同步执行。

代码点评

🔍 第 8 章代码点评 Chapter08/myshop

做得好 金额、价格快照、PRG、异步任务只传 ID

全部金额使用 DecimalField/Decimal；订单项保存成交价；购物车增删都是 POST + 重定向；Celery 任务只接收 ID。这些都是电商代码的基本功。

有问题 订单创建不在事务里，任务可能早于提交执行 Chapter08/myshop/orders/views.py:14

① 创建 Order 和多个 OrderItem 是一个整体，如果中途出错，会留下一个没有明细的“半截订单”，应放进 transaction.atomic()； ② 在事务里调用 .delay()，worker 可能在事务提交之前就开始执行，Order.objects.get(id=…) 查不到订单而失败。 Django 提供 transaction.on_commit()，Celery 5.4 更是直接提供了 delay_on_commit()： 

from django.db import transaction


def order_create(request):
    cart = Cart(request)
    if not len(cart):
        return redirect('cart:cart_detail')              # 空购物车不能下单
    if request.method == 'POST':
        form = OrderCreateForm(request.POST)
        if form.is_valid():
            with transaction.atomic():
                order = form.save()
                OrderItem.objects.bulk_create([
                    OrderItem(order=order, product=item['product'],
                              price=item['price'], quantity=item['quantity'])
                    for item in cart if 'product' in item      # 跳过已被删除的商品
                ])
                order_created.delay_on_commit(order.id)
            cart.clear()
            request.session['order_id'] = order.id
            return redirect('orders:order_created')           # PRG
    ...

有问题 删除商品会级联删除历史订单项 orders/models.py:36

OrderItem.product 用了 on_delete=models.CASCADE：运营在后台删掉一个下架商品，所有包含它的历史订单明细都会消失，订单金额对不上，财务数据被破坏。 订单是法律和财务凭证，应该用 PROTECT（有订单的商品不能删，只能设为 available=False），并在订单项上冗余保存商品名称等快照信息。

有问题 Cart.__iter__ 会污染会话数据 cart/cart.py:25

self.cart.copy() 是浅拷贝，内层的每个 item 字典仍然是会话里的那个对象。于是迭代时写入的 product（模型实例）、Decimal 价格、 cart_detail 里塞进去的表单对象，全都进了会话字典。只要同一请求里会话被标记为已修改（或开启 SESSION_SAVE_EVERY_REQUEST），保存时就会因为无法 JSON 序列化而报错。 另外，购物车里的商品若已被删除，它的 item 没有 'product' 键，下单时 item['product'] 直接 KeyError。 

def __iter__(self):
    products = Product.objects.in_bulk(map(int, self.cart))   # {id: product}
    for product_id, data in self.cart.items():
        product = products.get(int(product_id))
        if product is None:
            continue                                   # 商品已不存在：跳过（或顺手从购物车移除）
        price = Decimal(data['price'])
        yield {                                        # 产出新字典，绝不修改会话里的数据
            'product': product,
            'quantity': data['quantity'],
            'price': price,
            'total_price': price * data['quantity'],
        }

建议改进 每个匿名访客都会被写入一条会话

Cart.__init__ 在购物车不存在时写入空字典，会话随之被标记为已修改。因为上下文处理器在每次渲染时都创建 Cart，结果是每个访客（包括爬虫）第一次访问任何页面都会在 django_session 表插入一行并收到 Set-Cookie，还会让页面无法被 CDN 缓存。只在真正加入商品时才写会话即可：self.cart = self.session.get(settings.CART_SESSION_ID, {})，在 save() 里再写回。

建议改进 其他细节

① Index(fields=['id', 'slug']) 没有意义 —— id 是主键，本身就有唯一索引，按 id 查询永远不会用到这个联合索引； ② cart_add 没有检查 available=True，下架商品也能通过 POST 加入购物车； ③ 邮件发件人 'admin@myshop.com' 写死，应使用 settings.DEFAULT_FROM_EMAIL；任务也没有重试策略，可以加 @shared_task(autoretry_for=(SMTPException,), retry_backoff=True, max_retries=5)； ④ CELERY_BROKER_URL 没有配置，依赖默认的 amqp://guest@localhost//，应当从环境变量读取； ⑤ 模板里写死了 $ 货币符号（第 11 章会本地化）。

补充知识 业务逻辑放哪里 TSD：Fat models / services

“把购物车变成订单”是核心业务规则，现在散落在视图里。TSD 建议把这类逻辑放进模型方法或一个独立的 service 函数，例如 orders/services.py 里的 create_order_from_cart(cart, data)： 视图只负责表单和跳转，service 负责事务、校验库存、创建订单、触发任务，测试时可以绕过 HTTP 直接调用。

小结

  • 金额用 DecimalField；订单项保存成交价快照。
  • 会话数据在服务器端，Cookie 里只有 ID；修改嵌套结构后要设置 session.modified = True。
  • 用一个类封装购物车逻辑，实现 __iter__/__len__ 让它在模板里好用。
  • 上下文处理器给所有模板注入变量，但每次渲染都会执行。
  • Celery + 消息代理把耗时或可能失败的工作移出请求；任务只传 ID，在事务提交后再发送。
