Spring Boot 版 · 第 17 章 · 项目四：在线学习平台

上线部署

最后一章把 Educa 部署到生产环境：配置分环境、换成 PostgreSQL、用 Docker Compose 编排数据库、Redis、应用和 Nginx，配置 HTTPS， 再加上一个自定义中间件（课程子域名）和一个管理命令（选课提醒邮件）。书中的生产架构有五个容器：PostgreSQL、Redis、uWSGI（HTTP）、Daphne（WebSocket）、Nginx。 Spring Boot 应用是一个自带服务器的 jar，HTTP 和 WebSocket 都在里面，少了两个组件；但“生产环境的那些开关”一个也不能少 —— 这一章会逐一对照 Django 的 check --deploy 清单，并在真正的 Docker 环境里走一遍。

本章目标

  • 用 Profile 分离开发和生产配置（≈ settings/base.py + local.py + prod.py），机密从环境变量读取
  • 让同一套 Flyway 迁移和手写 SQL 在 H2 与 PostgreSQL 上都能运行，并用 Testcontainers 验证
  • 写多阶段、分层、非 root 的 Dockerfile；用健康检查代替 wait-for-it.sh
  • 配置 Nginx：HTTPS、WebSocket、上传文件、转发头；理解 forward-headers-strategy
  • 把 SECURE_*、ALLOWED_HOSTS 等安全设置翻译成 Spring 配置，并写测试
  • 用 Servlet 过滤器实现子域名中间件；用 ApplicationRunner 实现 enroll_reminder 命令

对应的 Django 讲解见 Django 版第 17 章；本章代码在 springboot/Chapter17/。

  • 叠加而不是继承：激活 prod 后，Spring 先读 application.yaml，再用 application-prod.yaml 覆盖同名的键 —— 效果等同于 from .base import * 后再改几个值，但没有 Python 的 import 技巧。
  • 机密：${POSTGRES_PASSWORD} 从环境变量读取，没有默认值（缺少时启动失败，而不是悄悄用一个默认密码）。python-decouple 的 config() 也是这个思路。Compose 从 .env 文件注入环境变量，.env 不进代码仓库，只提交一份 .env.example。
  • 自己的配置项用 @ConfigurationProperties 绑定到 record（EducaProperties），有类型、有默认值、IDE 能补全，比散落的 @Value 好维护。

换成 PostgreSQL

书中换数据库只需要改 DATABASES，重新 migrate、loaddata 即可 —— ORM 屏蔽了差异。 我们的迁移是手写 SQL，还有几处原生查询，所以要确认它们在两种数据库上都成立：

  • BIGINT GENERATED BY DEFAULT AS IDENTITY、TIMESTAMP WITH TIME ZONE、CROSS JOIN (VALUES ...) AS p(codename)：SQL 标准写法，H2 和 PostgreSQL 都支持。
  • fixture 导入用的 MERGE INTO ... USING (VALUES ...)：PostgreSQL 15 起支持。
  • 重置自增序列：两边语法不同，LoadDataCommand 里按数据库类型分支（第 12 章）。
  • 加上 org.postgresql:postgresql 驱动和 flyway-database-postgresql（Flyway 10 起各数据库的支持拆成了单独的模块）。

  • 多阶段：编译用带 Maven 和 JDK 的镜像，运行只用 JRE 镜像。最终镜像里没有源码、没有构建工具，更小也更安全。书中的镜像把整个项目目录（包括 .git、本地数据库……）都复制了进去，开发时还用卷挂载源码。
  • 分层：-Djarmode=tools extract --layers 把 fat jar 拆成“依赖 / 加载器 / 快照依赖 / 应用代码”四层，按变化频率从低到高依次 COPY。只改了代码时，只有最上面一层变化，推送和拉取镜像只传几百 KB。
  • 缓存挂载：--mount=type=cache,target=/root/.m2 让 Maven 仓库在多次构建之间复用，依赖只下载一次。
  • 非 root：应用以 uid 1001 运行；/app/media 事先 chown，命名卷第一次创建时会继承这个属主。
  • 管理命令：ENTRYPOINT 是 java，参数追加在后面：docker compose -f compose.prod.yaml run --rm web --loaddata=subjects（≈ docker compose exec web python manage.py loaddata ...）。

  • 本地开发用的 compose.yaml（只有 Redis）不变，mvn spring-boot:run 时由 spring-boot-docker-compose 自动启动；它不会被打进 jar。

Nginx：HTTPS、WebSocket 与转发头

server {
    listen 443 ssl;
    http2  on;
    server_name .${SITE_DOMAIN};           # 主域名和所有子域名
    ssl_certificate     /etc/nginx/certs/educa.crt;
    ssl_certificate_key /etc/nginx/certs/educa.key;
    client_max_body_size 11m;

    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    location / { proxy_pass http://educa; }

    location /ws/ {
        proxy_pass         http://educa;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection "upgrade";
        proxy_set_header   Host              $host;          # 必须重复！见下文
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 1h;
    }

    location /media/   { alias /app/media/; }  # 上传文件由 Nginx 直接返回
    location /actuator/ { return 404; }        # 监控端点不对外
}
server { listen 443 ssl default_server; ... return 444; }   # 其他主机名一律拒绝
⚠ 真实部署时踩到的坑：proxy_set_header 不会“叠加”

第一版的 /ws/ 只写了 Upgrade 和 Connection 两行。在 Docker 里实测时，WebSocket 握手返回 400。 原因是 Nginx 的规则：location 里只要写了任何一条 proxy_set_header，就完全不继承 server 级别的 proxy_set_header。 于是握手请求的 Host 变成了 upstream 的名字 educa，被应用的 ALLOWED_HOSTS 检查（下文）拒绝； X-Forwarded-Proto 也丢了，应用会以为这是 http 请求。在 location 里把几个头重复写一遍就好了。 书中的配置同样只写了两行，只是 Django 版没有做 Host 检查之外的依赖，问题不那么明显。

  • 转发头：应用在 Nginx 后面，看到的连接来自 Nginx、协议是 http。server.forward-headers-strategy=native 让 Tomcat 的 RemoteIpValve 根据 X-Forwarded-Proto/X-Forwarded-For 还原真实的协议和客户端 IP（只信任内网地址发来的这些头），≈ Django 的 SECURE_PROXY_SSL_HEADER。不配置的话，重定向地址、API 分页链接都会是 http://，HTTPS 重定向还会陷入死循环。
  • WebSocket：书中把 /ws/ 转给另一个 daphne 容器；这里转给同一个应用，只是要带上升级头。proxy_read_timeout 调长，否则空闲 60 秒的聊天连接会被 Nginx 断开。
  • 静态文件：Django 需要 collectstatic 把文件收集到一个目录，由 Nginx 提供。Spring 的静态文件在 jar 里，由应用返回；生产环境打开内容哈希（下文），配合一年的缓存头，性能不是问题。
  • 证书：scripts/dev-cert.sh 用 openssl 生成覆盖 educaproject.com 和 *.educaproject.com 的自签名证书，供本机测试；正式环境用 Let's Encrypt。

/** ≈ ALLOWED_HOSTS：Host 头不在白名单里的请求直接返回 400 */
boolean isAllowed(String host) {
    String h = host.toLowerCase(Locale.ROOT);
    for (String pattern : allowedHosts) {
        if (pattern.equals("*") || pattern.equals(h)) return true;
        // '.example.com' 匹配 example.com 以及它的所有子域名
        if (pattern.startsWith(".") && (h.equals(pattern.substring(1)) || h.endsWith(pattern))) return true;
    }
    return false;
}

为什么要检查 Host：应用会用请求的 Host 生成绝对地址（API 分页的 next、将来邮件里的链接）。伪造的 Host 会让这些链接指向攻击者的网站（Host 头注入）。 Django 默认就检查；Spring 需要自己加，这里写成最外层的过滤器（比 Security 还早），localhost 留给容器内部的健康检查。

静态文件的内容哈希（≈ ManifestStaticFilesStorage）：spring.web.resources.chain.strategy.content.enabled=true 后， 模板里 @{/static/css/base.css} 自动输出 /static/css/base-2a7adc75….css；文件内容变了哈希就变，所以可以放心地设置一年的缓存。

自定义中间件 → 过滤器：课程子域名

Django · courses/middleware.py
def subdomain_course_middleware(get_response):
    def middleware(request):
        host_parts = request.get_host().split('.')
        if (len(host_parts) > 2
                and host_parts[0] != 'www'):
            course = get_object_or_404(
                Course, slug=host_parts[0])
            course_url = reverse('course_detail',
                                 args=[course.slug])
            url = '{}://{}{}'.format(request.scheme,
                '.'.join(host_parts[1:]), course_url)
            return redirect(url)
        return get_response(request)
    return middleware
Spring · SubdomainCourseFilter.java
public class SubdomainCourseFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest request,
            HttpServletResponse response, FilterChain chain)
            throws ServletException, IOException {
        String subdomain = subdomainOf(request.getServerName());
        if (subdomain == null) {
            chain.doFilter(request, response);     // get_response(request)
            return;
        }
        if (courses.findBySlug(subdomain).isEmpty()) {
            response.sendError(404);
            return;
        }
        response.sendRedirect(UriComponentsBuilder.newInstance()
                .scheme(request.getScheme()).host(siteDomain)
                .path("/course/{slug}/").buildAndExpand(subdomain)
                .toUriString());
    }

    /** 只处理 <slug>.educaproject.com；www、主域名、无关主机返回 null */
    String subdomainOf(String host) { ... }
}
  • Django 的中间件是一个包住 get_response 的函数；Servlet 过滤器是包住 chain.doFilter() 的方法 —— 结构几乎一样：可以直接返回响应，也可以交给后面的链。
  • 注册与顺序：FilterRegistrationBean 的 setOrder()，数字越小越靠外（≈ 在 MIDDLEWARE 列表里的位置）。
  • 书中的 bug：判断条件是“Host 按点拆开多于两段，且第一段不是 www”。用 IP 访问时（127.0.0.1 拆成 4 段）， '127' 被当作课程 slug，所有请求都 404 —— 包括健康检查。这里改为只处理“配置的主域名之下的一级子域名”，并有测试覆盖。

管理命令：选课提醒

Django · enroll_reminder.py
class Command(BaseCommand):
    def add_arguments(self, parser):
        parser.add_argument('--days', dest='days', type=int)

    def handle(self, *args, **options):
        date_joined = timezone.now().today() - \
            datetime.timedelta(days=options['days'] or 0)
        users = User.objects.annotate(
            course_count=Count('courses_joined')
        ).filter(course_count=0,
                 date_joined__date__lte=date_joined)
        for user in users:
            emails.append((subject, message,
                           settings.DEFAULT_FROM_EMAIL,
                           [user.email]))
        send_mass_mail(emails)
Spring · EnrollReminderCommand.java
@Component
public class EnrollReminderCommand implements ApplicationRunner {
    public void run(ApplicationArguments args) {
        if (!args.containsOption("enroll-reminder")) return;
        int days = args.containsOption("days")
                ? Integer.parseInt(args.getOptionValues("days").getFirst()) : 0;
        System.out.println("Sent " + sendReminders(days) + " reminders");
        ... // 退出
    }

    public int sendReminders(int days) {
        OffsetDateTime cutoff = LocalDate.now(clock).minusDays(days)
                .plusDays(1).atStartOfDay().atOffset(ZoneOffset.UTC);
        SimpleMailMessage[] messages = users.findNotEnrolledJoinedBefore(cutoff)
                .stream().map(this::reminder).toArray(SimpleMailMessage[]::new);
        if (messages.length > 0) mailSender.send(messages);  // ≈ send_mass_mail
        return messages.length;
    }
}

// UserRepository
@Query("""
    select u from User u
    where u.dateJoined < :cutoff and u.email <> '' and u.active = true
      and not exists (select 1 from Course c join c.students s where s = u)
    """)
List<User> findNotEnrolledJoinedBefore(@Param("cutoff") OffsetDateTime cutoff);
  • not exists 子查询比 annotate(Count) + filter(count=0) 更直接，也不需要 group by。
  • 跳过没有邮箱的用户（书中会给空地址发信，SMTP 服务器会拒绝，整批发送可能因此失败）。
  • SimpleMailMessage... 一次调用发送全部邮件，复用同一个 SMTP 连接（≈ send_mass_mail）。没有配置 spring.mail.host 时由 ConsoleMailSender 打印到日志（≈ console 邮件后端）。
  • 定时执行：书中用 cron 调用 manage.py。这里同样可以用 cron 执行 docker compose run --rm web --enroll-reminder --days=20；也可以在应用里用 @Scheduled(cron = "0 0 9 * * *")，但多实例部署时每个实例都会执行一次，需要 ShedLock 之类的分布式锁。

差异点评

🔍 第 17 章 Spring 版点评 springboot/Chapter17

做得好 架构更简单

一个进程处理 HTTP 和 WebSocket，不需要 uWSGI、Daphne 两套服务器和对应的 Nginx 分流；镜像是多阶段构建的只读 JRE 镜像，非 root 运行。

做得好 部署配置经过真实验证

生产安全设置有自动化测试；PostgreSQL 兼容性有 Testcontainers 测试；整套 Compose 在本机实际跑过，并因此发现了 Nginx proxy_set_header 继承的问题。

注意 书中中间件的 IP 地址问题

书中的子域名中间件会把 127.0.0.1 当作子域名，导致用 IP 访问时所有请求 404（包括负载均衡器的健康检查）。这里改为只匹配配置的主域名。

注意 上传文件的存储

媒体文件放在 Docker 卷里，只适合单机部署；多台机器时要换成对象存储（S3、MinIO），MediaStorage 是唯一需要修改的地方 —— 这也是一开始就把文件操作集中到一个类里的好处。

补充知识 不写 Dockerfile 也能构建镜像

mvn spring-boot:build-image 用 Cloud Native Buildpacks 直接生成分层、非 root、带内存计算器的镜像，适合不想维护 Dockerfile 的团队；本章手写 Dockerfile 是为了把每一步讲清楚。另一个方向是 GraalVM 原生镜像（启动毫秒级，内存更少），但要为反射、代理额外配置。

小结

  • Profile 叠加配置，机密来自环境变量；自定义配置项用 @ConfigurationProperties。
  • 手写 SQL 要在目标数据库上测试：Testcontainers 启动真正的 PostgreSQL。
  • Dockerfile：多阶段 + 分层 + 缓存挂载 + 非 root；Compose 用健康检查编排启动顺序。
  • Nginx：HTTPS、WebSocket 升级头、转发头（location 里要重复写）、媒体文件；应用侧 forward-headers-strategy=native。
  • Django 的 SECURE_*、ALLOWED_HOSTS 在 Spring 里有的是默认行为，有的要自己加，逐项对照并写测试。
  • 中间件 → OncePerRequestFilter；管理命令 → ApplicationRunner。

动手练习
