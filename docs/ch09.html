支付与订单

商店能下单了，但还收不到钱。这一章接入 Stripe 支付：用户跳到 Stripe 托管的收银台付款， Stripe 通过 Webhook 通知我们“钱到了”。之后我们扩展管理后台：自定义批量动作导出 CSV、自定义后台页面、 生成 PDF 发票并在付款后自动发邮件。

本章目标

  • 理解支付网关的作用，用 Stripe Checkout 完成收款
  • 理解“跳转回来的成功页”和“Webhook 通知”的区别，校验 Webhook 签名
  • 在订单上保存支付 ID，并在 Admin 中链接到 Stripe 后台
  • 编写自定义 Admin 动作（导出 CSV）和自定义 Admin 视图
  • 用 WeasyPrint 把 HTML 模板渲染成 PDF，并作为邮件附件发送

为什么用支付网关

自己处理信用卡意味着要满足 PCI DSS 合规、防欺诈、对接银行……几乎不可能。 支付网关（Stripe、PayPal、支付宝、微信支付等）替你承担这些：卡号从不经过你的服务器。 本书使用 Stripe Checkout —— 一个由 Stripe 托管的收银页面。

from decimal import Decimal

import stripe
from django.conf import settings
from django.shortcuts import get_object_or_404, redirect, render
from django.urls import reverse
from orders.models import Order

stripe.api_key = settings.STRIPE_SECRET_KEY
stripe.api_version = settings.STRIPE_API_VERSION


def payment_process(request):
    order_id = request.session.get('order_id')
    order = get_object_or_404(Order, id=order_id)

    if request.method == 'POST':
        success_url = request.build_absolute_uri(reverse('payment:completed'))
        cancel_url = request.build_absolute_uri(reverse('payment:canceled'))
        session_data = {
            'mode': 'payment',                      # 一次性付款（另有 subscription、setup）
            'client_reference_id': order.id,        # 用来把 Stripe 的支付对回我们的订单
            'success_url': success_url,
            'cancel_url': cancel_url,
            'line_items': [],
        }
        for item in order.items.all():
            session_data['line_items'].append({
                'price_data': {
                    'unit_amount': int(item.price * Decimal('100')),   # 以“分”为单位的整数
                    'currency': 'usd',
                    'product_data': {'name': item.product.name},
                },
                'quantity': item.quantity,
            })
        session = stripe.checkout.Session.create(**session_data)
        return redirect(session.url, code=303)      # POST 之后用 303 跳转
    else:
        return render(request, 'payment/process.html', locals())


def payment_completed(request):
    return render(request, 'payment/completed.html')


def payment_canceled(request):
    return render(request, 'payment/canceled.html')

Webhook：可靠地接收支付结果

为什么不在 payment_completed 页面里把订单标记为已付款？因为用户付完款可能直接关掉浏览器， 也可能有人直接访问 /payment/completed/。可靠的做法是让 Stripe 主动调用我们的一个 URL —— 这就是 Webhook（回调）。 

import stripe
from django.conf import settings
from django.http import HttpResponse
from django.views.decorators.csrf import csrf_exempt
from orders.models import Order

from .tasks import payment_completed


@csrf_exempt
def stripe_webhook(request):
    payload = request.body
    sig_header = request.META['HTTP_STRIPE_SIGNATURE']
    try:
        event = stripe.Webhook.construct_event(payload, sig_header, settings.STRIPE_WEBHOOK_SECRET)
    except ValueError:                                  # 内容不是合法 JSON
        return HttpResponse(status=400)
    except stripe.error.SignatureVerificationError:     # 签名不对
        return HttpResponse(status=400)

    if event.type == 'checkout.session.completed':
        session = event.data.object
        if session.mode == 'payment' and session.payment_status == 'paid':
            try:
                order = Order.objects.get(id=session.client_reference_id)
            except Order.DoesNotExist:
                return HttpResponse(status=404)
            order.paid = True
            order.stripe_id = session.payment_intent     # 保存支付 ID，便于对账
            order.save()
            payment_completed.delay(order.id)
    return HttpResponse(status=200)                     # 2xx 表示“收到了”，否则 Stripe 会重试

ⓘ 事件顺序不保证

付一次款会收到 payment_intent.created、payment_intent.succeeded、charge.succeeded、checkout.session.completed 等多个事件，顺序不固定，同一事件也可能重复投递。所以只处理你关心的那一种，并让处理逻辑“做两次也没关系”（幂等）。

批量动作：导出 CSV

import csv
import datetime

from django.http import HttpResponse


def export_to_csv(modeladmin, request, queryset):
    opts = modeladmin.model._meta
    response = HttpResponse(content_type='text/csv')
    response['Content-Disposition'] = f'attachment; filename={opts.verbose_name}.csv'
    writer = csv.writer(response)          # HttpResponse 是类文件对象，可以直接写
    fields = [f for f in opts.get_fields() if not f.many_to_many and not f.one_to_many]
    writer.writerow([field.verbose_name for field in fields])     # 表头
    for obj in queryset:
        data_row = []
        for field in fields:
            value = getattr(obj, field.name)
            if isinstance(value, datetime.datetime):
                value = value.strftime('%d/%m/%Y')
            data_row.append(value)
        writer.writerow(data_row)
    return response


export_to_csv.short_description = 'Export to CSV'


@admin.register(Order)
class OrderAdmin(admin.ModelAdmin):
    # ...
    actions = [export_to_csv]

from django.contrib.staticfiles import finders

@shared_task
def payment_completed(order_id):

                         'Please, find attached the invoice for your recent purchase.',
                         'admin@myshop.com', [order.email])

    out = BytesIO()                                              # 内存中的“文件”
    weasyprint.HTML(string=html).write_pdf(
        out, stylesheets=[weasyprint.CSS(finders.find('css/pdf.css'))])
    email.attach(f'order_{order.id}.pdf', out.getvalue(), 'application/pdf')
    email.send()

代码点评

🔍 第 9 章代码点评 Chapter09/myshop

做得好 以 Webhook 为准、校验签名、密钥走环境变量

订单状态只在验签通过的 Webhook 里更新，成功页只做展示；锁定了 Stripe API 版本；POST 后用 303 跳转；PDF 生成放在 Celery 任务里。支付集成的大方向完全正确。

有问题 Webhook 不幂等：重复投递会重复发发票 Chapter09/myshop/payment/webhooks.py:40

Stripe 明确说明同一事件可能投递多次（网络超时、你返回了非 2xx 等）。现在的代码每收到一次 checkout.session.completed 就发一次发票邮件。 用“条件更新”保证只有第一次真正生效： 

from django.db import transaction

updated = Order.objects.filter(
    id=session.client_reference_id, paid=False,          # 只更新“还没付”的订单
).update(paid=True, stripe_id=session.payment_intent)
if updated:                                              # 0 表示已经处理过
    transaction.on_commit(lambda: payment_completed.delay(int(session.client_reference_id)))

另外 request.META['HTTP_STRIPE_SIGNATURE'] 在缺少该请求头时会抛 KeyError 变成 500，应改用 .get()；视图也应加 @require_POST；严谨起见还应核对 session.amount_total 与订单金额一致。

有问题 已付款的订单还能再付一次 payment/views.py:15

payment_process 只根据会话里的 order_id 取订单，不检查 order.paid。用户在浏览器里后退再点“Pay now”，就会创建第二个 Checkout Session 重复扣款。应在开头判断：已付款就重定向到订单完成页。

建议改进 不要用 locals() 传模板上下文 TSD：模板

render(request, 'payment/process.html', locals()) 会把视图里的所有局部变量都塞进模板，模板到底依赖哪些变量不再一目了然，以后在视图里加一个临时变量也可能意外覆盖模板变量。显式写出：{'order': order}。

建议改进 Admin 代码的现代写法：format_html 与装饰器

用 f-string 拼 HTML 再 mark_safe，一旦拼进的值来自外部（这里的 stripe_id 来自 Webhook），就有注入风险。 format_html() 会自动转义参数。另外 Django 3.2 起推荐用 @admin.display 和 @admin.action 装饰器代替给函数设置 short_description 属性： 

from django.utils.html import format_html


@admin.register(Order)

建议改进 自定义后台视图应挂在 Admin 自己的 URL 下

现在的后台视图注册在 orders.urls（地址是 /orders/admin/order/1/），只用 @staff_member_required 保护： 任何 staff 用户都能看任何订单，不管他有没有 “view order” 权限。更好的做法是通过 ModelAdmin.get_urls() 注册，并用 self.admin_site.admin_view() 包装： 

from django.urls import path


class OrderAdmin(admin.ModelAdmin):
    def get_urls(self):
        return [
            path('<int:order_id>/pdf/', self.admin_site.admin_view(self.pdf_view),
                 name='orders_order_pdf'),
        ] + super().get_urls()

    def pdf_view(self, request, order_id):
        order = get_object_or_404(Order, pk=order_id)
        if not self.has_view_permission(request, order):
            raise PermissionDenied

建议改进 CSV 导出的两个隐患

① CSV 公式注入：顾客把名字填成 =HYPERLINK("http://evil…")，运营用 Excel 打开导出文件时会被当作公式执行。导出用户输入的字段时，应给以 = + - @ 开头的值前加单引号。② 大量数据时应使用 StreamingHttpResponse 边查边写，避免一次性占用大量内存；日期格式化丢掉了时间信息，按需保留。

补充知识 金额与货币

int(item.price * Decimal('100')) 对两位小数的价格没问题，但更稳妥的写法是 int((item.price * 100).quantize(Decimal('1')))；货币写死 'usd'，零小数位货币（如日元）不需要乘 100。多币种商店应把币种作为订单字段保存。

小结

  • 支付交给支付网关；Stripe Checkout 让卡号完全不经过你的服务器。
  • 成功页只用于展示，Webhook 才是“已付款”的可信来源；Webhook 必须验签、必须幂等。
  • 用 client_reference_id 把支付和订单关联，保存 payment_intent ID 便于对账。
  • Admin 可通过 list_display 函数、批量动作、自定义视图、覆盖模板四种方式扩展。
  • WeasyPrint 把 HTML 渲染成 PDF，可以写入响应或内存缓冲区作为附件。
