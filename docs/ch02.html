博客进阶：社交功能

上一章的博客能看，但还很“素”。这一章给它加上几乎每个博客平台都有的功能： 搜索引擎友好的网址、分页、通过邮件分享文章、读者评论。 顺带学会 Django 的两大核心工具 —— 表单和类视图。

本章目标

规范 URL：一个对象只有一个“正式地址”

同一篇文章会出现在很多页面上：首页列表、标签页、搜索结果……但它只应有一个规范 URL（canonical URL）， 也就是它“自己的”页面。Django 的约定是在模型上实现 get_absolute_url() 返回这个地址。 

from django.urls import reverse


class Post(models.Model):
    # ...
    def get_absolute_url(self):
        return reverse('blog:post_detail', args=[self.id])

模板里把 {% url 'blog:post_detail' post.id %} 换成 {{ post.get_absolute_url }}。好处是：模板不再需要知道“详情页要几个参数”。Admin 也会用它，在编辑页右上角显示“在站点上查看”按钮。

SEO 友好的 URL

把 /blog/1/ 改成 /blog/2024/1/1/who-was-django-reinhardt/：人一看就知道是什么内容，搜索引擎也更喜欢。

要用“日期 + slug”唯一定位一篇文章，就必须保证同一天没有两篇 slug 相同的文章：

slug = models.SlugField(max_length=250, unique_for_date='publish')

def get_absolute_url(self):
    return reverse('blog:post_detail', args=[
        self.publish.year, self.publish.month, self.publish.day, self.slug,
    ])

path('<int:year>/<int:month>/<int:day>/<slug:post>/', views.post_detail, name='post_detail'),

def post_detail(request, year, month, day, post):
    post = get_object_or_404(
        Post,
        status=Post.Status.PUBLISHED,
        slug=post,
        publish__year=year,
        publish__month=month,
        publish__day=day,
    )
    ...
⚠ unique_for_date 只在表单/Admin 校验，数据库不管

它由 ModelForm 的校验逻辑执行，所以迁移不会产生任何 SQL。 如果你在 shell 里直接 Post.objects.create(...)，照样能插入重复数据。点评部分给出了数据库级约束的写法。

分页

from django.core.paginator import EmptyPage, PageNotAnInteger, Paginator


def post_list(request):
    post_list = Post.published.all()
    paginator = Paginator(post_list, 3)        # 每页 3 篇
    page_number = request.GET.get('page', 1)
    try:
        posts = paginator.page(page_number)
    except PageNotAnInteger:                   # ?page=asdf
        posts = paginator.page(1)
    except EmptyPage:                          # ?page=99
        posts = paginator.page(paginator.num_pages)
    return render(request, 'blog/post/list.html', {'posts': posts})

分页链接做成一个可复用的小模板，用 {% include "pagination.html" with page=posts %} 引入：

<div class="pagination">
  <span class="step-links">
    {% if page.has_previous %}
      <a href="{% querystring page=page.previous_page_number %}">Previous</a>
    {% endif %}
    <span class="current">
      Page {{ page.number }} of {{ page.paginator.num_pages }}.
    </span>
    {% if page.has_next %}
      <a href="{% querystring page=page.next_page_number %}">Next</a>
    {% endif %}
  </span>
</div>
💡 {% querystring %} 比 ?page= 好在哪（Django 5.1+）

书里写的是 href="?page={{ ... }}"，它会丢掉当前 URL 上的其他参数： 比如 /search/?query=django&page=1 点“下一页”就变成了 ?page=2，搜索词没了。 仓库代码已升级为 {% querystring page=... %}，它在保留其他参数的同时只替换 page。

类视图（Class-Based Views）

视图只要是“接收请求、返回响应的可调用对象”就行，所以也可以是类。Django 提供了一系列通用类视图， 把“列表”“详情”“创建”“编辑”这些常见套路封装好了，你只需要填配置。

函数视图（FBV）：流程显式写出来
def post_list(request):
    qs = Post.published.all()
    paginator = Paginator(qs, 3)
    page = request.GET.get('page', 1)
    try:
        posts = paginator.page(page)
    except PageNotAnInteger:
        posts = paginator.page(1)
    except EmptyPage:
        posts = paginator.page(paginator.num_pages)
    return render(request, 'blog/post/list.html',
                  {'posts': posts})
类视图（CBV）：只写“和默认不同的部分”
from django.views.generic import ListView


class PostListView(ListView):
    queryset = Post.published.all()
    context_object_name = 'posts'
    paginate_by = 3
    template_name = 'blog/post/list.html'

# urls.py
path('', views.PostListView.as_view(),
     name='post_list'),
  • queryset：要列出的数据。只写 model = Post 时等价于 Post.objects.all()。
  • context_object_name：模板里的变量名，默认叫 object_list。
  • paginate_by：每页条数。当前页对象放在模板变量 page_obj 里，所以模板要改成 with page=page_obj。
  • template_name：默认是 blog/post_list.html（应用名/模型名_list.html）。
  • 非法页码时 ListView 直接返回 404，而不是像我们手写的那样回退到某一页。

表单：邮件分享文章

Django 有两种表单基类：

  • Form：自己声明字段和校验规则，适合和模型无关的表单（登录、搜索、联系我们）。
  • ModelForm：根据模型自动生成字段，还能直接 save() 成模型对象。
from django import forms


class EmailPostForm(forms.Form):
    name = forms.CharField(max_length=25)
    email = forms.EmailField()                 # 自动校验邮箱格式
    to = forms.EmailField()
    comments = forms.CharField(required=False, widget=forms.Textarea)   # 换控件

一个视图同时负责“显示表单”和“处理提交”

from django.core.mail import send_mail


def post_share(request, post_id):
    post = get_object_or_404(Post, id=post_id, status=Post.Status.PUBLISHED)
    sent = False

    if request.method == 'POST':
        form = EmailPostForm(request.POST)
        if form.is_valid():
            cd = form.cleaned_data                      # 校验并“清洗”后的数据
            post_url = request.build_absolute_uri(post.get_absolute_url())
            subject = f"{cd['name']} ({cd['email']}) recommends you read {post.title}"
            message = f"Read {post.title} at {post_url}\n\n{cd['name']}'s comments: {cd['comments']}"
            send_mail(subject=subject, message=message,
                      from_email=None,                  # None → 使用 DEFAULT_FROM_EMAIL
                      recipient_list=[cd['to']])
            sent = True
    else:
        form = EmailPostForm()

    return render(request, 'blog/post/share.html', {'post': post, 'form': form, 'sent': sent})
  • request.build_absolute_uri() 把相对路径补成带协议和域名的完整 URL —— 邮件里必须是完整链接。
  • cleaned_data 不仅“验过”，还“洗过”：比如 EmailField 会去掉首尾空格。表单无效时它只包含有效的字段。

ⓘ novalidate

现代浏览器会根据 required、type="email" 自己先校验一遍。想测试 Django 的服务端校验时，给 <form> 加 novalidate 关掉浏览器校验（仓库代码里就加了）。测完记得去掉 —— 但记住：浏览器校验只是体验优化，服务端校验才是安全保障。

评论系统

评论系统需要四样东西：评论模型、评论表单、处理提交的视图、在详情页显示评论和表单的模板。

class Comment(models.Model):
    post = models.ForeignKey(Post, on_delete=models.CASCADE, related_name='comments')
    name = models.CharField(max_length=80)
    email = models.EmailField()
    body = models.TextField()
    created = models.DateTimeField(auto_now_add=True)
    updated = models.DateTimeField(auto_now=True)
    active = models.BooleanField(default=True)     # 用来在后台屏蔽不当评论

    class Meta:
        ordering = ['created']
        indexes = [models.Index(fields=['created'])]

    def __str__(self):
        return f'Comment by {self.name} on {self.post}'

不写 related_name 时，反向访问名默认是 comment_set；写了之后就是 post.comments.all()。 记得 makemigrations + migrate，并在 admin.py 注册 CommentAdmin。

ModelForm：从模型生成表单

class CommentForm(forms.ModelForm):
    class Meta:
        model = Comment
        fields = ['name', 'email', 'body']     # 显式列出允许用户填写的字段

处理评论提交

from django.views.decorators.http import require_POST


@require_POST                      # 非 POST 请求返回 405 Method Not Allowed
def post_comment(request, post_id):
    post = get_object_or_404(Post, id=post_id, status=Post.Status.PUBLISHED)
    comment = None
    form = CommentForm(data=request.POST)
    if form.is_valid():
        comment = form.save(commit=False)
        comment.post = post
        comment.save()
    return render(request, 'blog/post/comment.html',
                  {'post': post, 'form': form, 'comment': comment})

代码点评

🔍 第 2 章代码点评 Chapter02/mysite

做得好 ModelForm 显式列出 fields TSD：表单

CommentForm 写的是 fields = ['name', 'email', 'body']。TSD 专门强调：永远不要用 fields = '__all__' 或 exclude，否则将来模型加了个 is_approved 字段，用户就能通过伪造 POST 数据直接改它（批量赋值漏洞）。

做得好 @require_POST、{% querystring %}、凭据走环境变量

评论视图限制了 HTTP 方法；分页模板用了 5.1 的 {% querystring %}；邮件凭据用 decouple 读取且 .env 没有进仓库。都是好习惯。

建议改进 分页用 paginator.get_page() 一行搞定 Chapter02/mysite/blog/views.py:12

Paginator.get_page()（Django 2.0 起）内部已经处理了非整数和越界页码，书里的 try/except 可以整个删掉：

def post_list(request):
    paginator = Paginator(Post.published.all(), 3)
    posts = paginator.get_page(request.GET.get('page'))   # 非法值→第 1 页，越界→最后一页
    return render(request, 'blog/post/list.html', {'posts': posts})

有问题 提交成功后直接 render，而不是重定向（缺少 PRG 模式）

post_comment 和 post_share 成功后都直接渲染页面。用户此时按 F5 刷新，浏览器会提示“重新提交表单”， 确认后就会再发一次邮件 / 再存一条评论。标准做法是 Post/Redirect/Get：成功后重定向，再用消息框架（第 5 章）显示提示。 

from django.contrib import messages
from django.shortcuts import redirect


@require_POST
def post_comment(request, post_id):
    post = get_object_or_404(Post.published, pk=post_id)
    form = CommentForm(data=request.POST)
    if form.is_valid():
        comment = form.save(commit=False)
        comment.post = post
        comment.save()
        messages.success(request, '评论已提交，审核后显示。')
        return redirect(post)                  # ← 成功就重定向
    # 失败时才渲染，带着错误信息
    return render(request, 'blog/post/comment.html', {'post': post, 'form': form})

有问题 邮件分享是一个“开放的发信器”

post_share 允许任何匿名访客向任意邮箱发送内容可自定义的邮件，发件人还是你的域名。 上线后很快会被脚本滥用来发垃圾邮件、钓鱼邮件，你的发信域名会被拉黑。至少要做到：要求登录，或加验证码；按 IP/用户限流（如 django-ratelimit）； 并且邮件发送应该放进后台任务（第 8 章 Celery），不要在请求里同步连 SMTP —— SMTP 慢或挂掉时整个页面会卡住。

建议改进 用数据库约束代替 unique_for_date Chapter02/mysite/blog/models.py:20

unique_for_date 只在表单校验时生效。Django 4.0 起 UniqueConstraint 支持表达式，可以把“同一天 slug 唯一”交给数据库保证：

from django.db.models.functions import TruncDate


class Post(models.Model):
    # ...
    class Meta:
        constraints = [
            models.UniqueConstraint(
                TruncDate('publish'), 'slug',
                name='unique_slug_per_publish_date',
            ),
        ]

注意 TruncDate 在数据库里按 UTC 截取日期，而 URL 里的年月日按 TIME_ZONE 计算；如果你的时区不是 UTC，边界时刻可能不一致，需要统一口径。

建议改进 评论默认直接公开

active = models.BooleanField(default=True) 意味着任何人提交的内容立即显示在页面上。公开站点更稳妥的默认值是 False（先审核后显示），或者接入反垃圾服务。此外 email 是个人信息，存储它意味着要考虑隐私合规。

补充知识 comments.count + for 会查两次库

模板里先 comments.count（一条 COUNT），再 {% for comment in comments %}（一条 SELECT）。反正都要把评论全部取出来，就用 {{ comments|length }}：它会求值 QuerySet 并缓存结果，后面的 for 循环直接用缓存。

建议改进 开发环境默认用控制台邮件后端 Chapter02/mysite/mysite/settings.py:128

config('EMAIL_HOST_USER') 没有默认值，新同事 clone 下来没有 .env 就直接启动失败。可以让“危险配置”没有默认值、“开发便利配置”有安全的默认值：

EMAIL_BACKEND = config('EMAIL_BACKEND', default='django.core.mail.backends.console.EmailBackend')
EMAIL_HOST_USER = config('EMAIL_HOST_USER', default='')
EMAIL_HOST_PASSWORD = config('EMAIL_HOST_PASSWORD', default='')

补充知识 FBV 还是 CBV？ TSD：视图

TSD 的立场很务实：通用的增删改查用 CBV（少写代码），逻辑特殊的用 FBV（一目了然），两者可以共存。 更重要的是“视图要瘦”：业务逻辑放到模型方法、QuerySet 方法或单独的 service 函数里，视图只做“取参数 → 调逻辑 → 返回响应”。 本章 post_share 里拼邮件内容的逻辑就适合抽成一个函数，方便单独测试。

小结

  • get_absolute_url() 定义规范 URL，模板、Admin、站点地图都会用它。
  • 路径转换器（int、slug…）同时完成匹配和类型转换；日期 + slug 让 URL 更友好。
  • Paginator 负责分页；ListView 用几个属性就实现了带分页的列表。
  • 表单处理的核心是 is_valid() 和 cleaned_data；ModelForm 的 save(commit=False) 用来补齐字段。
  • 所有 POST 表单都要 {% csrf_token %}；凭据放环境变量。
  • 生产代码里提交成功后要重定向（PRG），公开的发信功能要限流。
