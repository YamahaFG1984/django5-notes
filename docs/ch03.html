第 3 章 · 项目一：博客

扩展博客

博客项目的最后一章。我们接入第一个第三方应用做标签，用聚合查询推荐相似文章， 写自己的模板标签和过滤器，给搜索引擎提供站点地图、给读者提供 RSS， 最后把数据库迁到 PostgreSQL，做一个支持词干、权重和模糊匹配的全文搜索。

本章目标

  • 集成 django-taggit，理解它背后的“泛型关系”
  • 用 annotate() + Count() 写出“按共同标签数排序”的推荐查询
  • 编写 simple_tag、inclusion_tag 和自定义过滤器
  • 理解模板自动转义和 mark_safe 的安全边界
  • 用 sitemap 框架和 syndication 框架生成 sitemap.xml 和 RSS
  • 用 Docker 跑 PostgreSQL，用 dumpdata/loaddata 迁移数据
  • 用 SearchVector、SearchQuery、SearchRank、TrigramSimilarity 做搜索

按相似度推荐文章

“相似”的定义：共同标签越多越相似；共同标签一样多时，越新的越靠前。

from django.db.models import Count

post_tags_ids = post.tags.values_list('id', flat=True)    # [1, 2, 3]，而不是 [(1,), (2,), (3,)]
similar_posts = Post.published.filter(tags__in=post_tags_ids).exclude(id=post.id)
similar_posts = similar_posts.annotate(
    same_tags=Count('tags')                               # 给每篇文章加一个计算字段
).order_by('-same_tags', '-publish')[:4]
ⓘ aggregate 与 annotate 的区别

aggregate() 对整个 QuerySet 算出一个结果（如“全部文章的平均评论数”），返回字典； annotate() 给每一行附加一个计算值，返回的还是 QuerySet。聚合函数有 Count、Sum、Avg、Max、Min。 taggit 自带的 post.tags.similar_objects() 也能做类似的事。

自定义模板标签和过滤器

内置标签不够用、又想在任何页面都能用某段逻辑（比如侧边栏的“最新文章”）时，就写自定义模板标签。 它们必须放在应用的 templatetags/ 包里，模板中用 {% load 模块名 %} 加载。 

blog/
├── templatetags/
│   ├── __init__.py      ← 必须有，才是 Python 包
│   └── blog_tags.py     ← 模板里写 {% load blog_tags %}
🔢

simple_tag

返回一个值，直接输出：{% total_posts %}；也能存进变量：{% get_most_commented_posts as mcp %}

🧩

inclusion_tag

返回一个字典，用它渲染一小段模板再插入：{% show_latest_posts 3 %}

🔧

filter

加工一个值：{{ post.body|markdown }}，接受 0 或 1 个参数

import markdown
from django import template
from django.db.models import Count
from django.utils.safestring import mark_safe

from ..models import Post

register = template.Library()          # 变量名必须叫 register


@register.simple_tag
def total_posts():
    return Post.published.count()


@register.inclusion_tag('blog/post/latest_posts.html')
def show_latest_posts(count=5):
    latest_posts = Post.published.order_by('-publish')[:count]
    return {'latest_posts': latest_posts}      # 作为 latest_posts.html 的上下文


@register.simple_tag
def get_most_commented_posts(count=5):
    return Post.published.annotate(
        total_comments=Count('comments')
    ).order_by('-total_comments')[:count]


@register.filter(name='markdown')      # 模板里叫 markdown，函数名避开与模块重名
def markdown_format(text):
    return mark_safe(markdown.markdown(text))

自动转义与 mark_safe

书里说“存 Markdown 比存 HTML 更安全”，这句话只对了一半：Python-Markdown 不会过滤原始 HTML， 所以对不可信的作者来说它和直接存 HTML 一样危险。点评部分给出了加上 HTML 清洗的写法。 另外列表页的截断要改用 truncatewords_html，它不会把 HTML 标签截成一半。

⚠ 书中命令的一个笔误

原书的 docker run 写成了 -e POSRGRES_DB=blog（少了个 T），这样数据库名不会生效，会退回到用用户名 blog 作为库名 —— 恰好也叫 blog，所以没出错。自己改名字时要注意。

全文搜索

title__icontains='django' 只是字符串包含，搜 “musical” 找不到 “music”，也没法按相关度排序。 全文搜索会把文本拆成词、还原词根、去掉停用词，然后做匹配和打分。

先把 'django.contrib.postgres' 加进 INSTALLED_APPS。最简单的用法是 search 查找：

Post.objects.filter(title__search='django')                        # 单字段

from django.contrib.postgres.search import SearchVector
Post.objects.annotate(search=SearchVector('title', 'body')).filter(search='django')   # 多字段

搜索视图

搜索表单用 GET 提交：结果页 URL 带着 ?query=…，可以收藏、分享、刷新。

from django.contrib.postgres.search import SearchQuery, SearchRank, SearchVector


def post_search(request):
    form = SearchForm()
    query = None
    results = []
    if 'query' in request.GET:
        form = SearchForm(request.GET)
        if form.is_valid():
            query = form.cleaned_data['query']
            search_vector = SearchVector('title', weight='A') + SearchVector('body', weight='B')
            search_query = SearchQuery(query)          # 可加 config='spanish' 切换语言
            results = (
                Post.published.annotate(
                    search=search_vector,
                    rank=SearchRank(search_vector, search_query),
                )
                .filter(rank__gte=0.3)
                .order_by('-rank')
            )
    return render(request, 'blog/post/search.html',
                  {'form': form, 'query': query, 'results': results})

三元组相似度：容忍拼写错误

三元组（trigram）是连续的三个字符。两个字符串共享的三元组越多就越相似 —— 所以用户把 django 打成 yango 也能搜到。 需要先在数据库启用 pg_trgm 扩展，Django 提供了专门的迁移操作： 

python manage.py makemigrations --name=trigram_ext --empty blog

from django.contrib.postgres.operations import TrigramExtension
from django.db import migrations


class Migration(migrations.Migration):
    dependencies = [('blog', '0004_post_tags')]
    operations = [TrigramExtension()]        # 执行 CREATE EXTENSION pg_trgm

from django.contrib.postgres.search import TrigramSimilarity

results = (
    Post.published.annotate(similarity=TrigramSimilarity('title', query))
    .filter(similarity__gt=0.1)
    .order_by('-similarity')
)

仓库里的 AI 练习：把标签页加进站点地图

书在本章末尾建议借助 ChatGPT 完成一个扩展任务，提示词在 Chapter03/prompts/task.md： “把每个标签的文章列表页也加到 sitemap.xml 里”。参考答案如下： 

from django.contrib.sitemaps import Sitemap
from django.urls import reverse
from taggit.models import Tag

from .models import Post


class TagSitemap(Sitemap):
    changefreq = 'weekly'
    priority = 0.6

    def items(self):
        # 只收录至少有一篇已发布文章的标签
        return Tag.objects.filter(post__status=Post.Status.PUBLISHED).distinct()

    def location(self, tag):
        return reverse('blog:post_list_by_tag', args=[tag.slug])

# mysite/urls.py
sitemaps = {'posts': PostSitemap, 'tags': TagSitemap}

代码点评

🔍 第 3 章代码点评 Chapter03/mysite

做得好 开发环境也用 PostgreSQL TSD：数据库

TSD 明确反对“本地 SQLite、线上 PostgreSQL”：两者在类型、约束、排序规则、全文搜索上都有差别，很多 bug 只在线上出现。本章之后整个项目都跑在 PostgreSQL 上，还用迁移 TrigramExtension() 把扩展纳入版本管理，这些都很专业。

做得好 INSTALLED_APPS 分组、reverse_lazy、truncatewords_html

Django → 第三方 → 本地的分组顺序与 TSD 一致；Feed 的类属性用 reverse_lazy 避免导入期解析 URL；截断 HTML 用 _html 版本。

有问题 markdown 过滤器 + mark_safe 存在 XSS 风险 Chapter03/mysite/blog/templatetags/blog_tags.py:31

Python-Markdown 会把正文里的 <script>、<img onerror=…> 原样输出，mark_safe 又关掉了转义。 只要有一个作者账号被盗或者将来开放了投稿，就能在所有读者浏览器里执行脚本。 正确做法是渲染后再用白名单清洗。bleach 已停止维护，推荐 nh3： 

import markdown
import nh3


@register.filter(name='markdown')
def markdown_format(text):
    html = markdown.markdown(text, extensions=['fenced_code', 'tables'])
    return mark_safe(nh3.clean(html))        # 只保留安全的标签和属性

更进一步：渲染结果可以在保存时算好并缓存到一个字段里，避免每次请求都解析 Markdown。

有问题 “最多评论”把已屏蔽的评论也算进去了 blog_tags.py:24

Count('comments') 统计所有评论，包括 active=False 的垃圾评论。聚合函数支持 filter 参数：

from django.db.models import Count, Q

Post.published.annotate(
    total_comments=Count('comments', filter=Q(comments__active=True))
).order_by('-total_comments')[:count]

建议改进 列表页存在 N+1 查询 blog/templates/blog/post/list.html

列表循环里每篇文章都访问 post.author（外键）和 post.tags.all（多对多），每页 3 篇就多出 6 条 SQL，每页 20 篇就是 40 条。 用 select_related（外键，JOIN 一次取回）和 prefetch_related（多对多，额外一条 IN 查询）解决： 

post_list = Post.published.select_related('author').prefetch_related('tags')

建议改进 侧边栏每次请求都跑三条统计查询

total_posts、show_latest_posts、get_most_commented_posts 放在 base.html 里，意味着每一个页面都要执行它们，其中“最多评论”还是 JOIN + GROUP BY。这类变化不频繁的数据很适合用模板片段缓存（第 14 章）：

{% load cache %}
{% cache 600 blog_sidebar %}
  <h3>Latest posts</h3>
  {% show_latest_posts 3 %}
  ...
{% endcache %}

建议改进 搜索没有索引，查询参数没有长度限制

TrigramSimilarity 和 SearchVector 在没有索引时都要全表扫描并逐行计算。数据多了以后需要建 GIN 索引； 同时 SearchForm.query 应加 max_length，避免超长输入拖慢数据库： 

from django.contrib.postgres.indexes import GinIndex


class Post(models.Model):
    class Meta:
        indexes = [
            models.Index(fields=['-publish']),
            GinIndex(name='post_title_trgm', fields=['title'], opclasses=['gin_trgm_ops']),
        ]


class SearchForm(forms.Form):
    query = forms.CharField(max_length=100)

全文搜索更进一步可以加一个 SearchVectorField 列（配合 5.0 的 GeneratedField 或触发器自动维护）并对它建 GIN 索引。

建议改进 docker-compose 里写死了凭据 Chapter03/docker-compose.yml:5

第 2 章用的是 env_file: .env，第 3 章反而改成在 environment: 里直接写 EMAIL_HOST_PASSWORD: 'xxxxxxxxxxxx'。 虽然这里是占位符，但这种写法会诱导人把真密码提交进仓库。建议保持 env_file，仓库里只放一个 .env.example。 另外 Dockerfile 额外 pip install psycopg[binary]，而 requirements.txt 里是不带 binary 的 psycopg==3.1.18，依赖应该只在一处声明：写成 psycopg[binary]==3.1.18。

补充知识 分页模板又退回了 ?page=

第 2 章仓库代码的 pagination.html 已经用 {% querystring %}，第 3 章又改回 ?page={{ … }}（与书一致）。如果以后给搜索结果加分页，?page=2 会丢掉 query 参数。建议保留 {% querystring %} 版本。

小结

  • 第三方应用通过 pip install + INSTALLED_APPS 接入；taggit 用泛型关系给任意模型打标签。
  • annotate() 给每行加计算字段，配合 Count 能写出推荐类查询。
  • 模板标签有 simple_tag、inclusion_tag 和过滤器三种；mark_safe 只能用在清洗过的内容上。
  • sitemap 和 feed 框架都只需要实现 items() 等少数方法。
  • PostgreSQL 的全文搜索支持词干、停用词、排名、权重；三元组相似度能容忍拼写错误。
