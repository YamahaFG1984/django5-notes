Spring Boot 版 · 第 6 章 · 项目二：图片书签社交网站

分享内容

网站的核心功能来了：用户在任意网页上点一下浏览器书签栏里的按钮，就能把页面上的图片“收藏”到我们的网站； 其他人可以点赞，列表页滚到底部自动加载更多。这一章涉及多对多关系、服务端下载远程图片、缩略图、 前端 fetch 与后端 JSON 接口，以及跨站嵌入的 JavaScript。Spring 版还要额外处理一个书中忽略的安全问题：SSRF。

本章目标

  • 给同一对实体建两种关系：多对一（谁收藏的）和多对多（谁点了赞）
  • 用 JPA 生命周期回调代替重写 save()
  • 用 RestClient 下载远程图片，并加上 SSRF 防护、超时和大小上限
  • 用 Thumbnailator 实现 easy-thumbnails 的“按需生成缩略图”
  • 写 JSON 接口，在 fetch 里正确携带 Spring Security 的 CSRF 令牌
  • 理解书签小工具的工作原理，并去掉硬编码的站点地址
  • 用 Thymeleaf 片段实现无限滚动

对应的 Django 讲解见 Django 版第 6 章；本章代码在 springboot/Chapter06/。

Image 模型：两种指向用户的关系

class Image(models.Model):

        related_name='images_created',
        on_delete=models.CASCADE)

    users_like = models.ManyToManyField(
        settings.AUTH_USER_MODEL,

            self.slug = slugify(self.title)

Spring · images/Image.java（节选）
@Entity
@Table(name = "images_image", indexes = @Index(
        name = "images_image_created_idx", columnList = "created DESC"))
public class Image {

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "user_id")
    private User user;                     // 谁收藏的

    @Column(nullable = false, length = 200) private String title;
    @Column(nullable = false, length = 200) private String slug = "";
    @Column(nullable = false, length = 2000) private String url;
    @Column(nullable = false, length = 100) private String image;
    @Column(nullable = false, columnDefinition = "text")
    private String description = "";
    @CreationTimestamp private OffsetDateTime created;

    @ManyToMany                            // 谁点了赞
    @JoinTable(name = "images_image_users_like",
            joinColumns = @JoinColumn(name = "image_id"),
            inverseJoinColumns = @JoinColumn(name = "user_id"))
    private Set<User> usersLike = new LinkedHashSet<>();

    @PrePersist                            // ≈ 重写 save()
    void prePersist() {
        if (slug == null || slug.isBlank()) {
            slug = Slugs.slugify(title);
        }
    }
}
  • Django 必须给两个关系起不同的 related_name（images_created、images_liked），否则反向名字冲突。JPA 的反向关系是可选的，这里没有在 User 上声明，也就不存在冲突；需要时用仓库查询（countByUserId）。
  • 重写 save() 在 JPA 里对应生命周期回调：@PrePersist（插入前）、@PreUpdate（更新前）、@PostLoad（加载后）等。注意它们和 Django 的 save() 一样，批量 update 语句不会触发。

书签流程全景

下载远程图片：RestClient 与 SSRF

书中在 ImageCreateForm.save() 里直接 requests.get(image_url)。这是一个典型的 SSRF（服务端请求伪造）漏洞：

⚠ 用户能让你的服务器去访问任何地址

url 来自用户提交的表单。攻击者可以提交 http://127.0.0.1:8080/actuator/env.png、http://10.0.0.5/admin.png， 或者云服务器的元数据地址 http://169.254.169.254/latest/meta-data/xx.png。服务器会乖乖去请求 —— 从内网里面。 扩展名检查挡不住，因为 URL 的路径部分可以随便写。

Spring 版把下载单独放进 ImageDownloader，加上了几道防线：

public ImageDownloader(RestClient.Builder builder,
                       @Value("${bookmarks.download.block-private-networks:true}") boolean blockPrivateNetworks) {

            .followRedirects(HttpClient.Redirect.NEVER)   // ① 重定向可能把请求“拐”到内网
            .build();
    JdkClientHttpRequestFactory requestFactory = new JdkClientHttpRequestFactory(httpClient);
    requestFactory.setReadTimeout(Duration.ofSeconds(10));    // ② 超时
    this.restClient = builder.requestFactory(requestFactory).build();
    ...
}

public byte[] download(String url) {
    URI uri = checkUrl(url);
    return restClient.get().uri(uri).exchange((request, response) -> {
        if (!response.getStatusCode().is2xxSuccessful()) {
            throw new DownloadException("The image could not be downloaded ...");
        }
        try (InputStream body = response.getBody()) {
            byte[] bytes = body.readNBytes(MAX_BYTES + 1);      // ③ 最多读 5MB + 1 字节
            if (bytes.length > MAX_BYTES) {
                throw new DownloadException("The image is too large.");
            }
            return bytes;
        }
    });
}

URI checkUrl(String url) {
    ...                                                        // ④ 只允许 http / https
    for (InetAddress address : InetAddress.getAllByName(uri.getHost())) {
        if (address.isLoopbackAddress() || address.isSiteLocalAddress() || address.isLinkLocalAddress()
                || address.isAnyLocalAddress() || address.isMulticastAddress()) {
            throw new DownloadException("Downloading from this address is not allowed.");   // ⑤ 拒绝内网
        }
    }
    return uri;

ⓘ 这还不是完美的 SSRF 防护

检查 IP 和真正发请求之间有时间差，攻击者可以用“DNS 重绑定”让第二次解析返回内网地址。更彻底的做法是自定义 DNS 解析、把连接固定到检查过的 IP， 或者干脆让下载请求经过一个只能访问公网的出口代理。本地调试时想收藏 localhost 上的图片，可以把 bookmarks.download.block-private-networks 设为 false。

表单：@AssertTrue 代替 clean_url

Django
class ImageCreateForm(forms.ModelForm):
    class Meta:
        model = Image
        fields = ['title', 'url', 'description']
        widgets = {'url': forms.HiddenInput}

    def clean_url(self):
        url = self.cleaned_data['url']
        valid_extensions = ['jpg', 'jpeg', 'png']
        extension = url.rsplit('.', 1)[1].lower()
        if extension not in valid_extensions:
            raise forms.ValidationError(
                'The given URL does not match valid image extensions.')
        return url

书中的 url.rsplit('.', 1)[1] 在整个 URL 没有点号时（比如 http://localhost/photo）会抛 IndexError（500 错误），URL 带查询参数（a.jpg?w=800）时又会误判。Spring 版一并处理了。 另外，GET 请求的查询参数可以直接绑定到表单对象：@ModelAttribute("form") ImageCreateForm form 会把 ?url=…&title=… 填进去， 相当于书中的 ImageCreateForm(data=request.GET)（但不触发校验）。

缩略图：按需生成

easy-thumbnails 的做法是：模板里第一次用到 {% thumbnail image.image 300x300 crop="smart" %} 时生成文件并保存，之后直接复用。 我们用 Thumbnailator 写一个同样思路的 ThumbnailService，再通过第 1 章的自定义方言暴露为 #thumbnail： 

public String url(String relativePath, int width, int height, boolean crop) {
    String thumbPath = thumbPath(relativePath, width, height, crop);   // thumbs/images/…/x_300x300_crop.png
    Path source = media.resolve(relativePath);
    Path target = media.resolve(thumbPath);
    if (!Files.exists(target) && Files.exists(source)) {
        Files.createDirectories(target.getParent());
        var builder = Thumbnails.of(source.toFile());
        if (height <= 0) {
            builder.width(width);                                   // 300x0：只限定宽度
        } else if (crop) {
            builder.size(width, height).crop(Positions.CENTER);     // 居中裁剪成正方形
        } else {
            builder.size(width, height);                            // 等比缩放
        }
        builder.toFile(target.toFile());
    }
    return Files.exists(target) ? "/media/" + thumbPath : null;
}

ⓘ crop="smart" 与 CENTER

easy-thumbnails 的 smart 裁剪会根据图像“信息量”（熵）选择裁剪区域；Thumbnailator 没有这个功能，这里用居中裁剪。模板渲染时同步生成缩略图，第一次访问会稍慢 —— 两个库都是这样。流量大时应改为上传后异步生成，或交给图片 CDN。

详情页：避开 N+1

详情页要显示“谁赞过”以及每个人的头像。Django 模板里 {{ user.profile.photo }} 会对每个点赞用户各查一次资料表。Spring 版在 service 里分两步批量取：

@Transactional(readOnly = true)
public ImageDetail detail(Long id, String slug, Long currentUserId) {
    Image image = images.findWithLikesByIdAndSlug(id, slug)                 // @EntityGraph("usersLike")：一条 JOIN
            .orElseThrow(() -> new NotFoundException("No Image matches the given query."));
    List<User> likedBy = image.getUsersLike().stream().sorted(comparing(User::getId)).toList();
    Map<Long, String> photos = profiles.findByUserIdIn(ids(likedBy)).stream()   // 一条 IN 查询
            .collect(toMap(p -> p.getUser().getId(), Profile::getPhoto));
    ...
    boolean likedByMe = likedBy.stream().anyMatch(u -> u.getId().equals(currentUserId));
    return new ImageDetail(image, likers, likedByMe);
}

返回的 ImageDetail 是一个 record，把模板需要的数据一次准备好 —— 这就是常说的“视图模型”。它让模板不再触发任何数据库查询，也方便在测试里直接断言。

⚠ Set 里的实体与 equals

Django 的 users_like.add(user) 会自动忽略已存在的关系。JPA 的 Set.add() 依赖 equals：User 没有重写 equals 时按对象身份比较， 如果集合里的用户对象和 getReferenceById 返回的不是同一个实例，就会被当成“新元素”，Hibernate 再插一行，撞上中间表的主键约束。 所以这里按 id 显式判断。另一种做法是给实体实现基于业务键或 id 的 equals/hashCode（要小心“保存前 id 为 null”的情况）。

前端：把 CSRF 令牌放进请求头

Django 把令牌放在名为 csrftoken 的 cookie 里，书中用 js-cookie 读出来放进 X-CSRFToken 头。 Spring Security 默认把令牌放在会话里（不是 cookie），推荐的做法是渲染到 <meta> 标签： 

<meta name="_csrf" th:content="${_csrf.token}">
<meta name="_csrf_header" th:content="${_csrf.headerName}">   <!-- X-CSRF-TOKEN -->
...
<script>
  const csrfToken = document.querySelector('meta[name="_csrf"]').content;
  const csrfHeader = document.querySelector('meta[name="_csrf_header"]').content;
</script>
<!-- ≈ {% block domready %} -->
<script layout:fragment="domready"></script>

<script layout:fragment="domready" th:inline="javascript">
  const url = /*[[@{/images/like/}]]*/ '/images/like/';     // 内联表达式：输出安全的 JS 字符串
  document.querySelector('a.like').addEventListener('click', function (e) {

  • th:inline="javascript" 让 /*[[ ... ]]*/ 里的表达式输出成经过转义的 JS 字面量，注释后面的 '/images/like/' 是用浏览器直接打开模板时的占位值（“自然模板”）。

书签小工具

书中把站点地址 //127.0.0.1:8000 硬编码在两个地方：启动器和 bookmarklet.js。换端口、换域名、上线都要改代码。Spring 版做了两处改动：

/** 根据当前请求地址生成 javascript: 链接，交给仪表盘模板 th:href="${bookmarklet}" */
public String href() {
    String base = ServletUriComponentsBuilder.fromCurrentContextPath().toUriString();
    String scriptUrl = base.replaceFirst("^https?:", "") + "/static/js/bookmarklet.js";   // //host:port/...
    return "javascript:(function(){"
            + "if(!window.bookmarklet){"
            + "var s=document.body.appendChild(document.createElement('script'));"
            + "s.src='" + scriptUrl + "?r='+Math.floor(Math.random()*9999999999999999);"
            + "window.bookmarklet=true;"
            + "}else{bookmarkletLaunch();}"
            + "})();";
}

ⓘ 为什么书签小工具需要 HTTPS

书签脚本运行在第三方页面里。如果那个页面是 HTTPS，而脚本从 http:// 加载，浏览器会以“混合内容”为由拦截。这正是第 5 章要在本地跑 HTTPS 的另一个原因。用 //host 这种“协议相对”地址，脚本会跟随当前页面的协议。

无限滚动：返回 HTML 片段

列表页滚动到底部时，前端请求 ?images_only=1&page=N，服务器只返回图片卡片的 HTML 片段，追加到列表末尾；页码超出范围时返回空内容，前端据此停止。

@GetMapping("/")
public String list(@RequestParam(name = "page", required = false) String pageParam,
                   @RequestParam(name = "images_only", required = false) String imagesOnly,
                   Model model) {
    int pageNumber = parsePage(pageParam);
    Page<Image> page = images.findAllByOrderByCreatedDesc(PageRequest.of(pageNumber - 1, PAGE_SIZE));
    if (page.getContent().isEmpty() && page.getTotalPages() > 0 && imagesOnly == null) {
        page = images.findAllByOrderByCreatedDesc(PageRequest.of(page.getTotalPages() - 1, PAGE_SIZE));
    }
    model.addAttribute("images", page.getContent());
    // 同一份数据，两种渲染方式：完整页面或只有片段
    return imagesOnly != null ? "images/image/list_images" : "images/image/list";
}

差异点评

🔍 第 6 章 Spring 版点评 springboot/Chapter06

做得好 补上了 SSRF 防护

书中的 requests.get(image_url) 没有任何限制。Spring 版限制协议、拒绝内网地址、不跟随重定向、设置超时和大小上限，并有单元测试覆盖。这些措施在 Django 版里同样应该加上。

做得好 去掉了硬编码的站点地址

启动器由服务端按当前地址生成，bookmarklet.js 通过 document.currentScript 推算地址，本地、测试、生产都不用改代码。

注意 列表页仍有 N+1 的可能

图片卡片只用到图片自身的字段，所以没有问题；如果将来要显示“收藏者头像”，记得像详情页一样批量取数据，或者用 @EntityGraph。

注意 同步下载会占用请求线程

下载最多等 15 秒，期间一个 Tomcat 线程被占着。Java 21 的虚拟线程可以大大缓解这个问题：设置 spring.threads.virtual.enabled=true，阻塞 IO 就不再占用平台线程。Django 的同步视图没有这个选项。

补充知识 为什么点赞接口返回 Map 而不是 DTO

为了和 JsonResponse({'status': 'ok'}) 一一对应。正式的 API 建议用 record 定义响应类型（第 15 章），类型明确，文档工具也能识别。

小结

  • JPA 的 @ManyToMany + @JoinTable 对应 ManyToManyField；@PrePersist 对应重写 save()。
  • RestClient 下载远程资源时要做 SSRF 防护：协议、目标地址、重定向、超时、大小。
  • 缩略图用 Thumbnailator 按需生成并缓存到磁盘，通过自定义方言在模板里调用。
  • @ResponseBody 返回 JSON；前端 fetch 从 <meta> 取 CSRF 令牌放进请求头。
  • 同一份模板既可以作为片段被引入，也可以单独渲染，实现无限滚动。
