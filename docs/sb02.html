博客进阶：社交功能

这一章给博客加上“对 SEO 友好的规范 URL”、分页、邮件分享和评论。 在 Spring 里，它们分别落到 JPQL 范围查询、Spring Data 的 Page、表单对象 + Bean Validation、MailSender 和一对多关系上。 表单是本章重点：Django 的 Form 一个类包办了字段、校验、渲染，Spring 把这三件事拆给了三个角色。

本章目标

  • 实现 /blog/2025/1/31/slug/ 这样的规范 URL，并用范围条件代替 publish__year
  • 自己实现 unique_for_date 校验，理解它为什么不是数据库约束
  • 用 PageRequest / Page<T> 分页，处理页码越界；写一个 {% querystring %} 的替代品
  • 用表单对象 + @Valid + BindingResult 处理表单，用 Thymeleaf 片段复用字段渲染
  • 用 MailSender 发邮件，开发时像 Django 的 console 后端一样只打印到日志
  • 用 @ConfigurationProperties 和 .env 管理配置
  • 建模一对多的评论，做评论审核后台；在测试里用 Mock 替换邮件发送

对应的 Django 讲解见 Django 版第 2 章；本章代码在 springboot/Chapter02/。

一篇文章可能出现在列表、标签页、搜索结果、RSS 里，但它应该只有一个“正式地址”。和 Django 一样，我们让实体自己负责生成这个地址：

按日期查找：范围条件，而不是取年月日

Django 写 publish__year=year, publish__month=month, publish__day=day，生成的 SQL 是对列做 EXTRACT（或者 Django 较新版本会优化成范围）。 在 JPA 里我们直接写成“当天 0 点 ≤ publish < 次日 0 点”，这种写法一定能用上 publish 列的索引： 

@EntityGraph(attributePaths = "author")
@Query("""
        select p from Post p
        where p.status = :status and p.slug = :slug
          and p.publish >= :start and p.publish < :end
        """)
Optional<Post> findBySlugPublishedBetween(@Param("status") PostStatus status, @Param("slug") String slug,
                                          @Param("start") OffsetDateTime start, @Param("end") OffsetDateTime end);

default Optional<Post> findPublishedBySlugAndDate(String slug, LocalDate date) {
    return findBySlugPublishedBetween(PostStatus.PUBLISHED, slug, startOf(date), startOf(date.plusDays(1)));
}

private static OffsetDateTime startOf(LocalDate date) {      // 接口里也能写 private 方法（Java 9+）
    return date.atStartOfDay().atOffset(ZoneOffset.UTC);
}

@GetMapping("/{year}/{month}/{day}/{slug}/")
public String postDetail(@PathVariable int year, @PathVariable int month, @PathVariable int day,
                         @PathVariable String slug, Model model) {
    Post post = posts.findPublishedBySlugAndDate(slug, dateOrNotFound(year, month, day))
            .orElseThrow(() -> new NotFoundException("No Post matches the given query."));
    model.addAttribute("post", post);
    model.addAttribute("comments", comments.findByPostAndActiveTrueOrderByCreatedAsc(post));
    model.addAttribute("form", new CommentForm());
    return "blog/post/detail";
}

private static LocalDate dateOrNotFound(int year, int month, int day) {
    try {
        return LocalDate.of(year, month, day);
    } catch (DateTimeException e) {          // /blog/2025/13/40/... 这种非法日期 → 404
        throw new NotFoundException("Invalid date");
    }
}

unique_for_date：自己写校验

Django 的 SlugField(unique_for_date='publish') 要求“同一天内 slug 不重复”。很多人以为它是数据库约束， 其实它只在 ModelForm / admin 校验时生效，数据库层面没有任何限制（所以 0002_alter_post_slug 迁移也不改表结构）。 Spring 里没有这个开箱即用的选项，我们在后台控制器里补上同样的检查，并把错误挂到 slug 字段上： 

private void validateUniqueForDate(PostForm form, Long excludeId, BindingResult errors) {
    if (form.getSlug() == null || form.getPublish() == null || errors.hasFieldErrors("slug")) {
        return;
    }
    if (posts.slugTakenOn(form.getSlug(), form.getPublish().toLocalDate(), excludeId)) {
        errors.rejectValue("slug", "unique_for_date", "Slug must be unique for Publish date.");
    }
}

excludeId 用于编辑已有文章时“不和自己冲突”。对应的查询：

@Query("""
        select count(p) > 0 from Post p
        where p.slug = :slug and p.publish >= :start and p.publish < :end
          and (:excludeId is null or p.id <> :excludeId)
        """)
boolean slugTakenBetween(...);
⚠ 应用层校验挡不住并发

两个管理员同时保存同一天同 slug 的文章，两边的检查都可能通过。Django 的 unique_for_date 有同样的问题。 需要绝对保证时，可以加一列 publish_date 并建唯一索引 (slug, publish_date)，让数据库兜底。

分页：Pageable 与 Page

Django 的 Paginator 在 Spring Data 里对应两个类型：Pageable（“我要第几页、每页几条”）和 Page<T>（“这一页的数据 + 总页数等信息”）。

Django · 函数视图
def post_list(request):
    post_list = Post.published.all()
    paginator = Paginator(post_list, 3)
    page_number = request.GET.get('page', 1)
    try:
        posts = paginator.page(page_number)
    except PageNotAnInteger:
        posts = paginator.page(1)
    except EmptyPage:
        posts = paginator.page(paginator.num_pages)
    return render(request, 'blog/post/list.html',
                  {'posts': posts})
Spring · BlogController
@GetMapping({"", "/"})
public String postList(
        @RequestParam(name = "page", required = false)
        String pageParam, Model model) {
    int pageNumber = parsePage(pageParam);   // 非整数 → 1
    Page<Post> page = posts.findPublished(
            PageRequest.of(pageNumber - 1, PAGE_SIZE));
    if (page.getContent().isEmpty()
            && page.getTotalPages() > 0) {    // 越界 → 最后一页
        page = posts.findPublished(
            PageRequest.of(page.getTotalPages() - 1, PAGE_SIZE));
    }
    model.addAttribute("posts", page);
    return "blog/post/list";
}

🔎 为什么不直接在方法参数里写 Pageable

Spring MVC 可以直接注入 Pageable pageable，自动解析 ?page=&size=&sort=，看起来更简洁。 但那样客户端可以传 size=100000，或者 sort= 任意字段名（排到不存在的字段会报错）。 对公开页面，更稳妥的做法是只读 page，每页大小和排序由服务端固定 —— 这也和 Django ListView(paginate_by=3) 的行为一致。 第 15 章写 API 时会讲怎么限制 Pageable 的最大 size。

ListView 呢？

Django 书里又用 ListView 把同样的逻辑写了一遍：queryset、paginate_by、template_name 几个属性就完成了。 Spring MVC 没有类视图 / 通用视图的概念，每个控制器方法都是“函数视图”。 想复用逻辑，靠的是普通 Java 手段：抽一个 service 方法、一个工具方法，或者父类。第 13 章讲 Django 的 CBV + Mixin 时我们会再比较一次。

Django 5.1 的 {% querystring page=2 %} 会保留当前 URL 的其他查询参数（比如搜索词），只替换 page。 Thymeleaf 没有现成的等价物，我们在第 1 章的自定义方言里再加一个表达式对象 #querystring： 

public class Querystring {
    private final Map<String, String[]> params;     // 当前请求的全部查询参数

    public String with(String name, Object value) {
        UriComponentsBuilder builder = UriComponentsBuilder.newInstance();
        params.forEach((key, values) -> {
            if (!key.equals(name)) {
                builder.queryParam(key, (Object[]) values);
            }
        });
        builder.queryParam(name, value);
        return builder.build().encode().toUriString();   // "?q=django&page=2"
    }
}

// 方言里：每次渲染时从 Thymeleaf 的 Web 上下文拿到当前请求参数
public Object buildObject(IExpressionContext context, String name) {
    if ("querystring".equals(name)) {
        Map<String, String[]> params = context instanceof IWebContext web
                ? web.getExchange().getRequest().getParameterMap()
                : Map.of();
        return new Querystring(params);
    }
    return filters;       // #text
}

⚠ @Email 允许空字符串

Bean Validation 的约定是“除了 @NotNull/@NotBlank，其他约束都认为 null 或空值是合法的”。 所以必填的邮箱要写 @NotBlank @Email 两个注解。Django 的 EmailField() 默认 required=True，一个就够了。

@PostMapping("/{postId}/share/")
public String share(@PathVariable Long postId,
                    @Valid @ModelAttribute("form") EmailPostForm form,
                    BindingResult errors,                 // 必须紧跟在被校验的参数后面！
                    Model model) {
    Post post = publishedPost(postId);
    boolean sent = false;
    if (!errors.hasErrors()) {                            // form.is_valid()
        // request.build_absolute_uri(post.get_absolute_url())
        String postUrl = ServletUriComponentsBuilder.fromCurrentContextPath()
                .path(post.getAbsoluteUrl()).toUriString();
        SimpleMailMessage message = new SimpleMailMessage();
        message.setFrom(properties.defaultFromEmail());
        message.setTo(form.getTo());
        message.setSubject("%s (%s) recommends you read %s".formatted(
                form.getName(), form.getEmail(), post.getTitle()));
        message.setText("Read %s at %s%n%n%s's comments: %s".formatted(
                post.getTitle(), postUrl, form.getName(), form.getComments()));
        mailSender.send(message);
        sent = true;
    }
    model.addAttribute("post", post);
    model.addAttribute("sent", sent);
    return "blog/post/share";
}
⚠ 忘了 BindingResult 会怎样

如果参数列表里没有紧跟一个 BindingResult，校验失败时 Spring 会直接抛 MethodArgumentNotValidException，用户看到 400 错误页，而不是带错误提示的表单。 这是初学者最常踩的坑之一。

模板：th:object、th:field 与字段片段

th:object="${form}" 指定表单绑定的对象，之后 th:field="*{name}" 会一次生成 id、name、value 三个属性， 校验失败重新渲染时还会自动回填用户输入的值。Django 5.0 的 as_field_group 把“标签 + 错误 + 控件”打包渲染，我们用一个带参数的片段做同样的事： 

<th:block th:fragment="field(name, label, type)">
  <div class="field">
    <label th:for="${name}" th:text="|${label}:|">Label:</label>
    <ul class="errorlist" th:if="${#fields.hasErrors(name)}">
      <li th:each="err : ${#fields.errors(name)}" th:text="${err}">error</li>
    </ul>
    <!-- __${name}__ 是“预处理”：先把变量值代入，再解析 *{...} 表达式 -->
    <textarea th:if="${type == 'textarea'}" th:field="*{__${name}__}" rows="6"></textarea>
    <input th:unless="${type == 'textarea'}" th:type="${type}" th:field="*{__${name}__}">
  </div>
</th:block>
Django · share.html
<form method="post" novalidate>
  {{ form.as_p }}
  {% csrf_token %}
  <input type="submit" value="Send e-mail">
</form>
Thymeleaf · share.html
<form method="post" th:action="@{/blog/{id}/share/(id=${post.id})}"
      th:object="${form}" novalidate>
  <div th:replace="~{fragments/forms :: field('name', 'Name', 'text')}"></div>
  <div th:replace="~{fragments/forms :: field('email', 'Email', 'email')}"></div>
  <div th:replace="~{fragments/forms :: field('to', 'To', 'email')}"></div>

发送邮件

Spring 的邮件抽象有两层：简单的 MailSender（只能发纯文本 SimpleMailMessage）和功能完整的 JavaMailSender（支持 HTML、附件）。本章只需要前者。

开发环境：console 后端

Django 可以把 EMAIL_BACKEND 设成 console 后端，邮件只打印到终端。Spring Boot 没有内置这个， 但因为控制器依赖的是 MailSender 接口，我们自己写一个“打印到日志”的实现即可： 

@Component
@Profile("!smtp")          // 没有激活 smtp profile 时才创建
public class ConsoleMailSender implements MailSender {

    private static final Logger log = LoggerFactory.getLogger(ConsoleMailSender.class);

    @Override
    public void send(SimpleMailMessage... messages) {
        for (SimpleMailMessage message : messages) {
            log.info("""

                    ---------- 邮件（console 后端，未真正发送）----------
                    From: {}
                    To: {}
                    Subject: {}

                    {}
                    -----------------------------------------------------""",
                    message.getFrom(), String.join(", ", message.getTo()),
                    message.getSubject(), message.getText());
        }
    }
}

@ConfigurationProperties：有类型的自定义设置

Django 里在 settings.py 随手加一个变量，用的时候 settings.DEFAULT_FROM_EMAIL。Spring 推荐把自定义配置绑定到一个类上：

@ConfigurationProperties(prefix = "mysite")
public record MysiteProperties(String defaultFromEmail) {   // 绑定 mysite.default-from-email
}

入口类上加 @ConfigurationPropertiesScan 后，它就是一个普通 Bean，可以注入到控制器里使用。好处是有类型、IDE 能补全、拼错键名时能被发现，还可以加 @Validated 在启动时校验必填项。

}
🔎 为什么不把请求直接绑定到 Comment 实体上

Spring 允许 @ModelAttribute Comment comment 直接绑定实体，省掉 CommentForm。但这样攻击者多提交一个 active=false 或 id=5， 就可能改到不该改的字段（“批量赋值”漏洞）。Django 的 ModelForm 用 fields = [...] 白名单解决这个问题， Spring 里的对应做法就是：请求只绑定到专门的表单对象，再由代码决定哪些值写进实体。

模板里的 forloop 与 pluralize

Django · detail.html
{% with comments.count as total_comments %}
  <h2>{{ total_comments }} comment{{ total_comments|pluralize }}</h2>
{% endwith %}
{% for comment in comments %}
  <p class="info">
    Comment {{ forloop.counter }} by {{ comment.name }}
  </p>
{% empty %}
  <p>There are no comments yet.</p>
{% endfor %}
{% include "blog/post/includes/comment_form.html" %}
Thymeleaf · detail.html
<h2 th:with="total=${#lists.size(comments)}"
    th:text="|${total} comment${total == 1 ? '' : 's'}|"></h2>

<div class="comment" th:each="comment, stat : ${comments}">
  <p class="info">
    Comment <span th:text="${stat.count}">1</span>
    by <span th:text="${comment.name}">name</span>
  </p>
</div>
<p th:if="${#lists.isEmpty(comments)}">There are no comments yet.</p>

<div th:replace="~{blog/post/includes/comment_form :: commentForm}"></div>
  • th:each="comment, stat : ${comments}" 的第二个变量是状态对象：stat.count（从 1 开始）≈ forloop.counter，stat.index（从 0 开始）≈ forloop.counter0，还有 stat.first、stat.last。
  • th:with ≈ {% with %}，在当前元素内定义局部变量。
  • |...| 是“字面量替换”语法，可以在字符串里直接嵌 ${...}。

评论审核后台

对应 Django 的 CommentAdmin，后台多了一个 /admin/blog/comment/ 列表页：按姓名/邮箱/内容搜索，按 active 过滤并显示数量， 每行一个“屏蔽/启用”按钮。切换状态的代码展示了 JPA 的脏检查： 

@PostMapping("/{id}/toggle/")
@Transactional
public String toggle(@PathVariable Long id, RedirectAttributes flash) {
    Comment comment = comments.findById(id)
            .orElseThrow(() -> new NotFoundException("Comment " + id + " does not exist"));
    comment.setActive(!comment.isActive());   // 没有调用 save！
    flash.addFlashAttribute("message", ...);
    return "redirect:/admin/blog/comment/";
}

在事务内查出来的实体处于“受管理”状态，事务提交时 Hibernate 会比较它和查出时的快照，发现 active 变了就自动发 UPDATE。 Django 没有这个机制，必须显式 comment.save()（或 save(update_fields=['active'])）。

测试：Mock 掉邮件发送

Django 测试时会自动把邮件后端换成内存后端，发出的邮件都在 mail.outbox 里。 Spring 里用 @MockitoBean 把容器里的 MailSender 替换成 Mockito 的假对象，再捕获调用参数： 

@MockitoBean
MailSender mailSender;

@Test
void shareSendsEmailWithAbsoluteUrl() throws Exception {
    mvc.perform(post("/blog/{id}/share/", published.getId()).with(csrf())
                    .param("name", "Alice")
                    .param("email", "alice@example.com")
                    .param("to", "bob@example.com")
                    .param("comments", "Worth reading"))
            .andExpect(status().isOk())
            .andExpect(content().string(containsString("E-mail successfully sent")));

    ArgumentCaptor<SimpleMailMessage> sent = ArgumentCaptor.forClass(SimpleMailMessage.class);
    verify(mailSender).send(sent.capture());                     // ≈ len(mail.outbox) == 1
    assertThat(sent.getValue().getTo()).containsExactly("bob@example.com");
    assertThat(sent.getValue().getText()).contains("http://localhost/blog/2025/1/31/hello-spring/");
}

差异点评

🔍 第 2 章 Spring 版点评 springboot/Chapter02

做得好 表单对象与实体分离

请求数据只进入 EmailPostForm、CommentForm、PostForm，实体字段由代码显式赋值，天然避免批量赋值漏洞。代价是比 ModelForm 多写一遍字段。

做得好 面向接口编程让“换邮件后端”变得简单

控制器只依赖 MailSender 接口；开发用 ConsoleMailSender，生产用 SMTP，测试用 Mock，业务代码一行不改。这就是依赖注入的价值。

建议改进 分享和评论提交后没有重定向（与原书一致）

POST 成功后直接渲染页面，用户刷新会弹出“重新提交表单”，可能重复发邮件或重复评论。 更好的做法是 PRG 模式（Post/Redirect/Get）：成功后 return "redirect:..."， 用 RedirectAttributes.addFlashAttribute 把提示带到下一页 —— 第 5 章讲消息框架时会用到。

建议改进 同步发送邮件会拖慢请求

SMTP 往往要一两秒甚至超时。生产环境应该异步发送：最简单的是给发送方法加 @Async，更可靠的是放进消息队列（第 8 章用 RabbitMQ 做异步任务）。

补充知识 校验消息是英文的默认文本

页面上看到的“must not be blank”来自 Hibernate Validator 的默认消息。可以在注解上写 message = "..."，或在 ValidationMessages.properties 里统一翻译 —— 第 11 章讲国际化时再处理。

小结

  • 规范 URL 由实体的 getAbsoluteUrl() 生成；按日期查找用范围条件，能走索引。
  • unique_for_date 是应用层校验，Spring 里用 BindingResult.rejectValue 自己实现。
  • 分页：仓库方法加 Pageable 参数、返回 Page；Spring 的页码从 0 开始。
  • 表单：表单对象 + Bean Validation 注解 + @Valid + 紧随的 BindingResult；模板用 th:object/th:field。
  • 邮件：依赖 MailSender 接口，按 profile 切换 console / SMTP 实现；配置用占位符和 @ConfigurationProperties。
  • 一对多用 @ManyToOne + 可选的 @OneToMany(mappedBy)；受管理实体的修改会被自动保存。
