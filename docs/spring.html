同样四个项目，用 Spring Boot 再做一遍

这一部分把《Django 5 By Example》配套仓库里 17 章的代码，逐章用 Spring Boot 4.1 + Java 21 重写， 每章一个可以独立运行、带测试的 Maven 项目，放在仓库的 springboot/ChapterNN/ 目录。 教程页面始终把 Django 5.2 的写法放在左边、Spring 的写法放在右边，讲清楚“同一个需求，两个框架各自怎么想”。

为什么要对照着学

Django 和 Spring Boot 解决的是同一类问题：接收 HTTP 请求、读写数据库、渲染页面或 JSON、处理登录和权限。 但两者的“性格”很不一样：

🔋

Django：电池全包

ORM、迁移、表单、Admin、认证、缓存、国际化都在一个框架里，约定大于配置，一个 models.py 就能生成表、表单和后台。

🧩

Spring Boot：拼装式

核心是依赖注入容器；Web、数据、安全、消息各是独立项目，Boot 负责“自动配置”把它们拼好。更显式，也更啰嗦。

🛡

类型与编译期检查

Java 的静态类型让很多 Django 里运行时才暴露的错误（拼错字段名、传错参数类型）在编译时就被发现。

🔧

要自己动手的地方

Spring 生态没有 Django Admin、没有自动生成迁移、没有 ModelForm。这些“差距”正是对照学习时最有收获的部分。

🔑 读法建议

每一章的 Spring 页面都假设你已经读过（或大致了解）对应的 Django 章节。 概念第一次出现时会解释清楚，但 Django 那一侧的原理不再重复 —— 需要时点页面里的“Django 版第 N 章”链接回去看。

如何运行每章的代码

准备 JDK 21、Maven 3.9+ 和 Docker（第 3 章起用来跑 PostgreSQL、Redis 等服务，测试也用它启动一次性数据库）。每个章节目录都是一个独立的 Maven 项目：

cd springboot/Chapter01
mvn test                 # 运行测试（≈ python manage.py test）
mvn spring-boot:run      # 启动开发服务器，默认 http://localhost:8080（≈ runserver）

# 打包成可执行 jar，再用它执行“管理命令”：创建超级用户
mvn package -DskipTests
java -jar target/mysite-1.0.0.jar --spring.main.web-application-type=none \
     --createsuperuser --username=admin --email=admin@example.com --password=change-me
ⓘ 从第 3 章起需要 Docker

项目里有 compose.yaml。用 mvn spring-boot:run 启动时，spring-boot-docker-compose 会自动执行 docker compose up，并把数据库地址注入到应用配置里；应用停止时再把容器停掉。 测试则用 Testcontainers 临时起一个 PostgreSQL，测完就删 —— 不需要你手动准备任何数据库。

重构时遵循的几条原则

  1. 一章一个快照。和原书仓库一样，每个 ChapterNN 都是在上一章基础上演进出来的完整项目，可以单独运行、单独测试。
  2. URL、表名、页面尽量和 Django 版一致。比如文章表叫 blog_post、用户表叫 auth_user、后台地址是 /admin/blog/post/，方便两边对照。
  3. 顺手修掉 Django 版代码点评里指出的问题。比如第 1 章“收藏”改成 POST + 登录校验、第 3 章 Markdown 默认转义原始 HTML。页面里会标出这些地方。
  4. 每章都有测试。Django 仓库里的 tests.py 基本是空的；Spring 版每章都有覆盖核心流程的测试，既是验收，也是“怎么在 Spring 里写测试”的示范。
  5. 不追求“最 Spring”的写法，追求讲得清楚。比如第 1 章先不引入 service 层，控制器直接调用仓库，和 Django 的视图函数一一对应；需要事务的时候再引入。
