构建社交网站

第二个项目从“用户系统”开始：登录、登出、修改密码、找回密码、注册、扩展用户资料、上传头像。 Django 的 django.contrib.auth 把这些视图、表单、模板名都准备好了，你只需要 include('django.contrib.auth.urls')； Spring Security 负责最核心的“认证”，但注册、改密码、找回密码这些页面都要自己写。这一章会把 Spring Security 的工作原理完整地走一遍。

本章目标

  • 画出 Spring Security 表单登录的完整流程，认识过滤器链、AuthenticationManager、UserDetailsService、PasswordEncoder
  • 自定义登录页、登出、“必须登录”的规则，对应 Django 的 LOGIN_URL、LOGIN_REDIRECT_URL、@login_required
  • 自己实现修改密码和找回密码，理解 Django 无状态重置令牌的原理
  • 实现注册：密码哈希、唯一性检查、两次密码一致
  • 用一对一的 Profile 扩展用户，用两个表单对象同时编辑，处理文件上传
  • 用 Spring 事件更新 last_login，用 @ControllerAdvice 让模板访问当前用户

对应的 Django 讲解见 Django 版第 4 章；本章代码在 springboot/Chapter04/（Maven 项目名 bookmarks）。

ⓘ 书中先手写了 user_login 视图

Django 书先写了一个 user_login 视图，自己调用 authenticate() 和 login()，再换成内置的 LoginView。 Spring 里也能在控制器里注入 AuthenticationManager 手动登录，但那样还得自己处理会话固定攻击防护、保存 SecurityContext 等细节。 实践中几乎总是用 formLogin()：你只提供登录页面，POST 交给过滤器。

登录、登出与“必须登录”

@Bean
@ConditionalOnWebApplication
SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/account/login/", "/account/register/", "/account/logged-out/",
                             "/account/password-reset/**").permitAll()
            .requestMatchers("/static/**", "/media/**", "/error").permitAll()
            .anyRequest().authenticated())             // 其余一律要求登录
        .formLogin(form -> form
            .loginPage("/account/login/")               // ≈ LOGIN_URL = 'login'
            .defaultSuccessUrl("/account/")             // ≈ LOGIN_REDIRECT_URL = 'dashboard'
            .permitAll())
        .logout(logout -> logout
            .logoutUrl("/account/logout/")              // 只接受 POST
            .logoutSuccessUrl("/account/logged-out/"));
    return http.build();
}

模板里的当前用户

Django 模板能直接用 {{ request.user }}，因为 auth 上下文处理器每次请求都把用户加载好。 Spring 会话里保存的 CurrentUser 只是登录那一刻的快照，用户改了名字它不会变。 我们用一个 @ControllerAdvice 在每个请求里放一个最新的 requestUser： 

@ControllerAdvice
public class CurrentUserAdvice {

    @ModelAttribute("requestUser")     // 所有控制器渲染的页面都会有这个属性
    public User requestUser(@AuthenticationPrincipal CurrentUser me) {
        return me == null ? null : users.findById(me.id()).orElse(null);
    }
}

<th:block th:if="${requestUser}">
  Hello <span th:text="${requestUser.displayName}">user</span>,   <!-- first_name|default:username -->
  <form th:action="@{/account/logout/}" method="post">
    <button type="submit">Logout</button>
  </form>
</th:block>
<a th:unless="${requestUser}" th:href="@{/account/login/}">Log-in</a>

@ControllerAdvice + @ModelAttribute 就是 Spring 版的“上下文处理器”，第 8 章做购物车时还会用到。

修改密码

Django 内置 PasswordChangeView 和 PasswordChangeForm。Spring Security 不提供这类页面，自己写一个表单对象和两个控制器方法：

@PostMapping("/password-change/")
public String passwordChange(@AuthenticationPrincipal CurrentUser me,
                             @Valid @ModelAttribute("form") PasswordChangeForm form, BindingResult errors) {
    if (!errors.hasFieldErrors("oldPassword") && !accounts.checkPassword(me.id(), form.getOldPassword())) {
        errors.rejectValue("oldPassword", "password_incorrect",
                "Your old password was entered incorrectly. Please enter it again.");
    }
    if (!errors.hasFieldErrors("newPassword2") && !form.passwordsMatch()) {
        errors.rejectValue("newPassword2", "password_mismatch", "The two password fields didn't match.");
    }
    if (errors.hasErrors()) {
        return "registration/password_change_form";
    }
    accounts.setPassword(me.id(), form.getNewPassword1());
    return "redirect:/account/password-change/done/";
}

错误信息沿用了 Django 表单的原文，方便对照。注意 errors.hasFieldErrors(...) 的检查：字段本身已经有“必填”之类的错误时，就不再叠加业务错误 —— Django 的 clean_<field>() 也只在字段基础校验通过后才调用。

找回密码：无状态令牌

找回密码是四个页面：输入邮箱 → “已发送” → 点邮件里的链接设置新密码 → “已完成”。最有意思的是链接里的令牌。

public String make(User user) {
    long timestamp = clock.instant().getEpochSecond();
    return Long.toString(timestamp, 36) + "-" + hash(user, timestamp);
}

public boolean check(User user, String token) {
    ...
    boolean signatureOk = MessageDigest.isEqual(            // 常量时间比较，防计时攻击
            hash(user, timestamp).getBytes(UTF_8), parts[1].getBytes(UTF_8));
    long age = clock.instant().getEpochSecond() - timestamp;
    return signatureOk && age >= 0 && age <= timeout.toSeconds();   // ≈ PASSWORD_RESET_TIMEOUT
}

private String hash(User user, long timestamp) {
    String lastLogin = user.getLastLogin() == null ? "" : String.valueOf(user.getLastLogin().toEpochSecond());
    String value = user.getId() + user.getPassword() + lastLogin + timestamp + user.getEmail();
    Mac mac = Mac.getInstance("HmacSHA256");
    mac.init(new SecretKeySpec(key, "HmacSHA256"));
    byte[] digest = mac.doFinal(("bookmarks.PasswordResetTokens" + value).getBytes(UTF_8));
    return HexFormat.of().formatHex(digest).substring(0, 32);
}

链接格式和 Django 一样：/account/password-reset/<uidb64>/<token>/，其中 uidb64 是 URL 安全的 Base64 编码的用户 id。控制器把几个步骤串起来：

/** 无论邮箱是否存在都跳到同一个页面，避免被用来探测哪些邮箱注册过。 */
@PostMapping("/")

    ...
    for (User user : users.findByEmailIgnoreCaseAndActiveTrue(form.getEmail())) {
        String link = "%s/account/password-reset/%s/%s/".formatted(baseUrl, tokens.uid(user), tokens.make(user));
        mailSender.send(message);   // 开发时由 ConsoleMailSender 打印到日志

private User resolve(String uidb64, String token) {
    return tokens.decodeUid(uidb64)
            .flatMap(users::findById)
            .filter(User::isActive)
            .filter(user -> tokens.check(user, token))
            .orElse(null);                  // null → 模板显示“链接无效”（validlink = false）
}
💡 为什么要注入 Clock

令牌逻辑依赖“现在几点”。把 Clock 作为构造参数传进来，测试时就能传一个固定时间的 Clock.fixed(...)， 轻松验证“3 天后过期”，不用真的等 3 天，也不用 mock 静态方法。Django 里通常用 freezegun 或 time-machine 做同样的事。 

@Test
void validTokenExpiresAfterTimeout() {
    User user = user();
    String token = at("2025-01-01T00:00:00Z").make(user);
    assertThat(at("2025-01-03T23:59:00Z").check(user, token)).isTrue();
    assertThat(at("2025-01-04T00:00:01Z").check(user, token)).isFalse();
}
ⓘ Spring Security 自己的方案：一次性令牌登录

Spring Security 6.4 起提供了“一次性令牌登录”（oneTimeTokenLogin()）：给用户发一个“魔法链接”直接登录。 它和“重置密码”不完全一样，令牌默认存在内存或数据库里，不是无状态的。本章为了和 Django 对照，自己实现了 Django 的做法。

注册

Django
class UserRegistrationForm(forms.ModelForm):
    password = forms.CharField(widget=forms.PasswordInput)
    password2 = forms.CharField(widget=forms.PasswordInput)

    class Meta:
        model = get_user_model()
        fields = ['username', 'first_name', 'email']

    def clean_password2(self):
        cd = self.cleaned_data
        if cd['password'] != cd['password2']:
            raise forms.ValidationError(
                "Passwords don't match.")
        return cd['password2']

def register(request):
    ...
    new_user = user_form.save(commit=False)
    new_user.set_password(
        user_form.cleaned_data['password'])
    new_user.save()
    Profile.objects.create(user=new_user)
Spring
@PostMapping("/register/")
public String register(
        @Valid @ModelAttribute("userForm") UserRegistrationForm form,
        BindingResult errors, Model model) {
    // ModelForm 会自动检查 username 唯一
    if (!errors.hasFieldErrors("username")
            && users.existsByUsername(form.getUsername())) {
        errors.rejectValue("username", "unique",
            "A user with that username already exists.");
    }
    // clean_password2
    if (!errors.hasFieldErrors("password2")
            && !form.passwordsMatch()) {
        errors.rejectValue("password2", "mismatch",
            "Passwords don't match.");
    }
    if (errors.hasErrors()) {
        return "account/register";
    }
    model.addAttribute("newUser", accounts.register(form));
    return "account/register_done";
}

// AccountService（@Transactional）
public User register(UserRegistrationForm form) {
    User user = new User(form.getUsername(),
        passwordEncoder.encode(form.getPassword()),  // set_password
        form.getEmail());
    user.setFirstName(form.getFirstName());
    users.save(user);
    profiles.save(new Profile(user));
    return user;
}
  • passwordEncoder.encode(...) ≈ set_password。存进库的是 {bcrypt}$2a$10$...：大括号里的前缀标明算法，将来换算法时旧哈希仍能验证 —— 和 Django 哈希字符串开头的 pbkdf2_sha256$ 是同一个思路。
  • “建用户 + 建资料”放在一个 @Transactional 方法里：任何一步失败都会整体回滚。Django 默认每条 SQL 自动提交，要达到同样效果需要 transaction.atomic()。
  • 用户名规则用 @Pattern(regexp = "[\\w.@+-]+") 表达，对应 Django 的 UnicodeUsernameValidator；密码至少 8 位对应 MinimumLengthValidator（书中的表单其实没有调用密码校验器）。
⚠ 密码框不能回填

校验失败重新显示表单时，th:field 会把用户输入写回 value 属性。对密码框来说这等于把明文密码塞回 HTML。 我们的字段片段对 password 和 file 类型只生成 id/name，不写 value；测试里专门断言了响应中不包含输入的密码。

🔎 自定义用户模型的问题在 Spring 里不存在

Django 的 User 是框架自带的模型，想加字段只能用 Profile 或在项目一开始就换成自定义用户模型（AUTH_USER_MODEL），中途更换非常痛苦。 Spring Security 根本不提供用户实体 —— User 从第一天起就是你自己的类，想加字段直接加。 本项目仍然使用 Profile，是为了和原书保持一致，也因为“认证信息”和“展示资料”分开存放本身就是合理的设计。

    if (!userErrors.hasErrors() && !profileErrors.hasErrors()) {

        } catch (InvalidImageException e) {

}

保存上传文件

上传的文件绑定为 MultipartFile（≈ request.FILES['photo']）。Django 的 ImageField 会用 Pillow 确认它真的是图片，并按 upload_to 保存； 我们写一个 MediaStorage 做同样的事： 

public String saveImage(String uploadTo, String filename, byte[] content) {
    if (!isImage(content)) {                 // ImageIO 读不出来 → 不是图片（≈ Pillow 校验）
        throw new InvalidImageException("Upload a valid image. ...");
    }
    String safeName = sanitize(filename);    // 只保留安全字符，并加随机后缀避免重名覆盖
    String relative = uploadTo + "/" + LocalDate.now().format(DATE_DIRS) + "/" + safeName;
    Path target = root.resolve(relative).normalize();
    if (!target.startsWith(root)) {          // 防止 ../../ 路径穿越
        throw new InvalidImageException("Invalid file name.");
    }
    Files.createDirectories(target.getParent());
    Files.write(target, content);
    return relative;                         // 数据库里只存 users/2025/01/31/me_1a2b3c4d.png
}

登录成功事件：更新 last_login

Django 登录成功后会发出 user_logged_in 信号，内置的接收者 update_last_login 更新 last_login。 Spring Security 登录成功时会发布 AuthenticationSuccessEvent，用 @EventListener 监听即可 —— 这是我们第一次接触 Spring 的事件机制，第 7 章会用它替代 Django 的信号： 

@Component
public class LastLoginListener {

    @EventListener
    public void onSuccess(AuthenticationSuccessEvent event) {
        users.updateLastLogin(event.getAuthentication().getName(), OffsetDateTime.now(ZoneOffset.UTC));
    }
}

// UserRepository：只更新一列，不必先查出实体
@Transactional
@Modifying(flushAutomatically = true, clearAutomatically = true)
@Query("update User u set u.lastLogin = :now where u.username = :username")
int updateLastLogin(@Param("username") String username, @Param("now") OffsetDateTime now);
⚠ 批量更新会绕过一级缓存

@Modifying 的 JPQL update 直接发 SQL，不经过持久化上下文。如果同一个事务里之前已经加载过这个用户，缓存里的对象还是旧值。 clearAutomatically = true 让它执行完就清空缓存。测试里正是因为少了这一项，“登录后 last_login 不为空”的断言才失败 —— 对应 Django 里 QuerySet.update() 之后要 refresh_from_db()。

anyRequest().authenticated() 让“忘了加 @login_required”这类漏洞不再可能。Django 直到 5.1 才提供 LoginRequiredMiddleware 实现同样的策略。

做得好 修掉了原书的几个小问题

超级用户也会自动创建 Profile（原书中 admin 访问编辑页会报 RelatedObjectDoesNotExist）；profileOf() 找不到资料时自动补建；上传文件名做了清洗和防穿越；密码至少 8 位。

注意 认证相关页面全部要自己写

Django 的 django.contrib.auth.urls 一行代码带来 8 个视图；Spring 版为此写了 3 个控制器、6 个表单类和一个令牌类。好处是每一步都清清楚楚，坏处是容易漏掉细节（比如防止账号探测、常量时间比较）。

建议改进 编辑资料后仍然没有提示

和原书第 4 章一样，保存成功后只是重新显示表单。第 5 章会引入“消息”，并改成 PRG（保存后重定向）。

补充知识 登录限流

两边都没有防暴力破解。Django 常用 django-axes；Spring 可以监听 AuthenticationFailureBadCredentialsEvent 计数，或在网关/Nginx 层限流（见 专题 6）。

小结

  • 表单登录 = 过滤器拦截 POST → AuthenticationManager → UserDetailsService + PasswordEncoder → SecurityContext 存进会话。
  • loginPage、defaultSuccessUrl、anyRequest().authenticated() 分别对应 LOGIN_URL、LOGIN_REDIRECT_URL、@login_required。
  • 改密码、找回密码、注册要自己写；找回密码用 HMAC 做无状态令牌，改密码后自动失效。
  • 用一对一实体扩展用户；一个 HTML 表单可以绑定多个表单对象；上传文件是 MultipartFile。
  • @ControllerAdvice + @ModelAttribute ≈ 上下文处理器；@EventListener ≈ 信号接收者。

动手练习

  1. 给登录加上“记住我”：http.rememberMe(...)，观察浏览器里多出的 cookie，并思考它和 Django 的 SESSION_EXPIRE_AT_BROWSER_CLOSE 的区别。
  2. 把密码校验提升到 Django 默认的四个校验器的水平：最少 8 位、不能全是数字、不能和用户名太像、不能是常见密码（可以放一个小的常见密码列表）。
  3. 用 @EventListener 监听 AuthenticationFailureBadCredentialsEvent，同一用户名 5 分钟内失败 5 次就暂时拒绝登录。
  4. 把邮件正文改成用 Thymeleaf 的 TEXT 模式渲染（提示：再配置一个 SpringTemplateEngine，模板解析器的 templateMode 设为 TEXT）。
