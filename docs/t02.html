项目起步：第一天就做对的事

书里的项目从 django-admin startproject 直接开始：一个 settings.py、写死的 SECRET_KEY、默认的 User， 到第 17 章才拆分设置。这些做法在教学中很合理，但真实项目里有几件事越晚做越贵，最贵的是自定义用户模型：一旦执行过第一次 migrate，再换就很痛苦。 这一篇用大约半小时，搭一个以后不用返工的项目骨架。

本篇目标

  • 用 uv（或 venv + pip）管理 Python 版本和依赖，锁定版本
  • 从第一天起按环境拆分设置，机密放进 .env 和环境变量
  • 在第一次 migrate 之前建好自定义用户模型，并知道在各处如何引用它
  • 用 TimeStampedModel 抽象基类统一时间戳字段
  • 配置 ruff 和 pre-commit，让格式、导入顺序、常见错误在提交前就被拦下
  • 用 Docker Compose 只跑数据库和 Redis，Django 仍在本机运行，方便调试

书中的起步方式与推荐骨架

Python 环境与依赖

uv 是一个用 Rust 写的 Python 包与项目管理器：一个命令就能装 Python、建虚拟环境、装依赖，还会生成锁文件 uv.lock， 保证你、同事和服务器装的是完全一样的版本。它比 pip 快得多，是近两年社区最常用的新选择。 

# 安装 uv（macOS / Linux；Windows 见 uv 官方文档）
curl -LsSf https://astral.sh/uv/install.sh | sh

mkdir mysite && cd mysite
uv init                                   # 生成 pyproject.toml、.python-version（示例 main.py 可删掉）
uv add "django~=5.2" django-environ "psycopg[binary]"
uv add --dev pytest-django factory-boy ruff pre-commit django-debug-toolbar

uv run django-admin startproject config .  # 注意最后的点：manage.py 放在当前目录
uv run python manage.py runserver         # uv run = 在项目虚拟环境里执行
ⓘ 不想用 uv？

经典做法完全可行：python -m venv .venv，激活后 python -m pip install ...。 按 Two Scoops 的建议把依赖分成 requirements/base.txt、local.txt（-r base.txt 加开发工具）、production.txt，并写上精确版本（pip freeze 的输出）。下文所有 uv run 去掉前缀即可。

项目布局：config 与设置包

startproject config . 让项目配置包叫 config，而不是和项目同名的 mysite/mysite/。一眼就能分清“这是配置”和“这是业务应用”。 接着把 settings.py 变成一个包： 

mkdir config/settings
mv config/settings.py config/settings/base.py
touch config/settings/__init__.py config/settings/local.py \

自定义用户模型

Django 官方文档的原话是：新项目强烈建议设置自定义用户模型，哪怕默认的 User 已经够用。原因看下图：

uv run python manage.py startapp users
uv run python manage.py startapp core

from django.contrib.auth.models import AbstractUser


class User(AbstractUser):
    pass          # 先空着也完全可以，重要的是“有”

from django.contrib import admin
from django.contrib.auth.admin import UserAdmin

from .models import User

admin.site.register(User, UserAdmin)

from django.contrib.auth.forms import UserCreationForm

from .models import User


class SignUpForm(UserCreationForm):          # 自带两次密码输入和 AUTH_PASSWORD_VALIDATORS 校验
    class Meta(UserCreationForm.Meta):
        model = User
        fields = ('username', 'email')

uv run python manage.py makemigrations users
uv run python manage.py migrate               # 这是整个项目的第一次 migrate
uv run python manage.py createsuperuser

在各处怎样引用用户模型

场景写法不要写
模型的外键、多对多models.ForeignKey(settings.AUTH_USER_MODEL, ...)ForeignKey(User, ...)
视图、表单、服务函数、管理命令get_user_model()，或直接用 request.userfrom django.contrib.auth.models import User
模型信号的 sendersender=settings.AUTH_USER_MODEL（字符串会被惰性解析）sender=User
注册表单继承 UserCreationForm，Meta.model = User自己写密码字段再 set_password
💡 想用邮箱登录？

在 User 上加 email = models.EmailField('email address', unique=True)，让数据库保证邮箱唯一，再配合第 5 章的邮箱认证后端（或 django-allauth）。在第一次 migrate 之前决定，最省事。

ⓘ 应用放在哪里

附录里的骨架把应用放进 apps/ 目录，适合应用很多的项目，但需要额外修改每个 apps.py 的 name。小项目像本篇这样放在根目录更简单，两种都符合 Two Scoops 的建议。

代码检查：ruff 与 pre-commit

ruff 一个工具同时做代码检查（lint）和格式化，速度极快。pre-commit 在每次 git commit 前自动运行这些检查，不合格就拒绝提交。 规则写在配置里，团队不用再争论代码风格。 

[tool.ruff]
line-length = 88
target-version = "py312"
extend-exclude = ["*/migrations/*"]

[tool.ruff.lint]
# E/F: 基础错误  I: 导入排序  B: 常见 bug  UP: 新语法  DJ: Django 专用规则
select = ["E", "F", "I", "B", "UP", "DJ"]

[tool.pytest.ini_options]
DJANGO_SETTINGS_MODULE = "config.settings.test"
python_files = ["tests.py", "test_*.py"]

# rev 写的是示例版本，运行 pre-commit autoupdate 更新到最新
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0
    hooks:
      - id: check-added-large-files
      - id: check-merge-conflict
      - id: detect-private-key          # 第 17 章提交进仓库的 TLS 私钥会被它拦下
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.12.0
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
  - repo: https://github.com/adamchainz/django-upgrade
    rev: 1.25.0
    hooks:
      - id: django-upgrade
        args: [--target-version, "5.2"]

git init
uv run pre-commit install            # 装进 .git/hooks，以后每次 commit 自动运行
uv run pre-commit run --all-files    # 手动对全部文件跑一遍
uv run ruff check .                  # 单独运行检查
💡 DJ 规则能抓到什么

例如给 CharField 加 null=True（DJ001，应该用空字符串表示“无”）、模型没有 __str__（DJ008）、ModelForm 用 exclude 或 __all__（DJ006、DJ007）。这些正是 Two Scoops 反复强调的约定。

开发用的数据库与 Redis

书里第 3 章起就换成了 PostgreSQL，推荐开发环境也用和线上相同的数据库。用 Docker Compose 只跑“服务”，Django 本身仍在本机运行，这样 breakpoint()、IDE 调试、自动重载都最方便：

services:
  db:
    image: postgres:17
    environment:
      POSTGRES_DB: mysite
      POSTGRES_USER: mysite
      POSTGRES_PASSWORD: mysite      # 只在本机使用的弱密码，线上绝不能这样
    ports: ["5432:5432"]
    volumes: [pgdata:/var/lib/postgresql/data]
  redis:
    image: redis:7
    ports: ["6379:6379"]

第一天清单

  1. uv init，uv add Django 5.2 和必要依赖，开发工具用 --dev。
  2. django-admin startproject config .，把设置拆成 base / local / test / production，改好三个入口文件的默认值。
  3. 写 .env.example，复制成 .env，生成随机 SECRET_KEY；.env 加进 .gitignore。
  4. docker compose up -d 启动 PostgreSQL 和 Redis。
  5. 建 users 应用和 User(AbstractUser)，设置 AUTH_USER_MODEL，然后才第一次 migrate。
  6. 建 core 应用放 TimeStampedModel 等公共代码。
  7. 配置 ruff、pre-commit，运行 pre-commit install。
  8. 配置 pytest-django，写第一个测试（见专题 1），确认 uv run pytest 能跑通。
  9. git commit 第一个版本。之后再 startapp blog，从第 1 章开始写业务。

ⓘ 用这个骨架跟着书学，需要改什么

几乎不用改：书中的模型大多已经用 settings.AUTH_USER_MODEL 引用用户（第 12 章例外，见其点评）。 需要留意的只有两处：书中 shell 示例里的 from django.contrib.auth.models import User 换成 get_user_model()； 书中的 --settings=mysite.settings 换成 config.settings.local。

小结

  • 依赖声明（pyproject.toml）与锁定（uv.lock）分开，都提交到 git。
  • 设置按环境拆分；代码里只写“读哪个变量”，值来自 .env 或环境；三个入口各有明确的默认设置。
  • 自定义用户模型必须在第一次 migrate 之前建好；引用时用 AUTH_USER_MODEL / get_user_model()。
  • ruff + pre-commit 让风格和常见错误在提交前就被处理；django-upgrade 自动把旧写法升级到 5.2。
  • 开发时服务放容器、Django 在本机，和线上一致又方便调试。
