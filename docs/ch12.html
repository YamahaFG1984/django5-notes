构建在线学习平台

最后一个项目是在线学习平台 Educa：讲师发布课程，课程分模块，模块里有文字、图片、文件、视频等各种内容。 这一章专注于数据建模：用 fixture 准备初始数据、用模型继承处理“多种类型的内容”、写一个自定义模型字段来自动维护顺序。

本章目标

  • 设计“学科 → 课程 → 模块 → 内容”的层级模型
  • 用 dumpdata/loaddata 和 fixture 提供初始数据
  • 分清三种模型继承：抽象基类、多表继承、代理模型
  • 用“抽象基类 + 泛型外键”实现多态内容
  • 编写自定义模型字段 OrderField，理解 pre_save()

💡 fixture、数据迁移、工厂 —— 各有其用 TSD：测试与数据

系统运行必需的数据（学科、国家列表）更适合写成数据迁移（RunPython），它随代码版本一起走、自动执行； 演示数据用 fixture 很方便；测试数据 TSD 推荐用 factory_boy 在测试里现造，因为 fixture 写死了主键和字段，模型一改就全部失效。

三种模型继承

ⓘ TSD 对继承的建议

TSD 推荐优先使用抽象基类（如 TimeStampedModel），尽量避免多表继承 —— 它的隐式 JOIN 和隐式一对一字段容易带来性能问题和困惑。需要“可以统一查询的父表”时，显式地写一个 OneToOneField 或外键，比多表继承更清楚。

多态内容：抽象基类 + 泛型外键

from django.contrib.contenttypes.fields import GenericForeignKey
from django.contrib.contenttypes.models import ContentType


class Content(models.Model):
    module = models.ForeignKey(Module, related_name='contents', on_delete=models.CASCADE)
    content_type = models.ForeignKey(
        ContentType, on_delete=models.CASCADE,
        limit_choices_to={'model__in': ('text', 'video', 'image', 'file')},
    )
    object_id = models.PositiveIntegerField()
    item = GenericForeignKey('content_type', 'object_id')


class ItemBase(models.Model):
    owner = models.ForeignKey(User, related_name='%(class)s_related', on_delete=models.CASCADE)
    title = models.CharField(max_length=250)
    created = models.DateTimeField(auto_now_add=True)
    updated = models.DateTimeField(auto_now=True)

    class Meta:
        abstract = True

    def __str__(self):
        return self.title


class Text(ItemBase):
    content = models.TextField()

class File(ItemBase):
    file = models.FileField(upload_to='files')

class Image(ItemBase):
    file = models.FileField(upload_to='images')

class Video(ItemBase):
    url = models.URLField()

自定义模型字段：OrderField

模块和内容都需要一个顺序号。我们希望：不指定时自动取“同组里最大值 + 1”，而“同组”可以配置（模块按课程分组，内容按模块分组）。

from django.core.exceptions import ObjectDoesNotExist
from django.db import models


class OrderField(models.PositiveIntegerField):
    def __init__(self, for_fields=None, *args, **kwargs):
        self.for_fields = for_fields                  # 按哪些字段分组计算顺序
        super().__init__(*args, **kwargs)

    def pre_save(self, model_instance, add):          # 保存前由 Django 调用
        if getattr(model_instance, self.attname) is None:
            try:
                qs = self.model.objects.all()
                if self.for_fields:
                    query = {field: getattr(model_instance, field) for field in self.for_fields}
                    qs = qs.filter(**query)           # 只看同一课程 / 同一模块
                last_item = qs.latest(self.attname)
                value = getattr(last_item, self.attname) + 1
            except ObjectDoesNotExist:
                value = 0                             # 第一个
            setattr(model_instance, self.attname, value)
            return value
        else:
            return super().pre_save(model_instance, add)


# 使用
class Module(models.Model):
    # ...
    order = OrderField(blank=True, for_fields=['course'])

    class Meta:
        ordering = ['order']

class Content(models.Model):
    # ...
    order = OrderField(blank=True, for_fields=['module'])

    class Meta:
        ordering = ['order']

代码点评

🔍 第 12 章代码点评 Chapter12/educa

做得好 抽象基类 + %(class)s 的 related_name

四种内容共享字段又各自独立成表，避免了多表继承的隐式 JOIN；'%(class)s_related' 让抽象基类里的外键在每个子类上都有不冲突的反向名称。这是 TSD 推荐的继承用法。

有问题 直接引用 User 而不是 AUTH_USER_MODEL Chapter12/educa/courses/models.py:1

前两个项目都用的是 settings.AUTH_USER_MODEL，这里却 from django.contrib.auth.models import User。一旦项目换成自定义用户模型，这些外键就指向了错误的表。应当统一写成 models.ForeignKey(settings.AUTH_USER_MODEL, …)。

有问题 自定义字段缺少 deconstruct() courses/fields.py:5

Django 文档明确要求：自定义字段在 __init__ 里新增了参数，就必须在 deconstruct() 里把它写回，否则迁移系统“看不见”这个参数。 仓库生成的迁移文件里就是 courses.fields.OrderField(blank=True, default=0) —— for_fields 丢了。后果：在数据迁移里使用历史模型时顺序会按全表计算；以后修改 for_fields，makemigrations 也检测不到。 

class OrderField(models.PositiveIntegerField):
    def __init__(self, for_fields=None, *args, **kwargs):
        self.for_fields = for_fields
        super().__init__(*args, **kwargs)

    def deconstruct(self):
        name, path, args, kwargs = super().deconstruct()
        if self.for_fields is not None:
            kwargs['for_fields'] = self.for_fields
        return name, path, args, kwargs

建议改进 OrderField 的并发与查询方式

“先查最大值再 +1”不是原子的：两个请求同时给同一模块添加内容，会得到相同的 order。影响不大时可以接受；要严格一些，可以在事务里对父对象加锁（Module.objects.select_for_update().get(pk=…)）再计算。 另外 qs.latest() 会取回整行对象，用聚合更轻：qs.aggregate(m=Max(self.attname))['m']。

建议改进 limit_choices_to 没限定应用 courses/models.py:66

{'model__in': ('text', 'video', 'image', 'file')} 只按模型名过滤。项目里只要别的应用也有叫 Image、File 的模型（第二个项目就有 images.Image！），它们也会出现在可选列表里。应加上 'app_label': 'courses'。

建议改进 泛型关系的“孤儿数据”与主键类型

删除一个 Text，指向它的 Content 行不会被删除（泛型外键没有数据库级 CASCADE），反之亦然。在 ItemBase 上加 GenericRelation 可以让删除内容时级联删除 Content： contents = GenericRelation('Content')（放在抽象基类里对每个子类生效）。 同时，object_id 应与 BigAutoField 主键匹配，改用 PositiveBigIntegerField（与第 7 章同理）。

建议改进 上传文件的类型与安全

Image 用的是 FileField 而非 ImageField，任何文件都能作为“图片”上传；File 也没有扩展名白名单（可用 FileExtensionValidator）。 更要注意的是：讲师上传的 .html、.svg 如果和网站同域名提供，就能在学员浏览器里以你的域名执行脚本。生产环境应把用户上传文件放在独立域名或对象存储上，并设置 Content-Disposition: attachment。

小结

  • fixture 是 Django 的数据序列化格式，dumpdata/loaddata 可用于初始数据和演示数据。
  • 抽象基类复用字段不建父表；多表继承父子各一张表；代理模型只改变行为。
  • “抽象基类 + 泛型外键”可以实现多态内容。
  • 自定义字段可以重写 pre_save() 在保存前计算值；新增构造参数时必须实现 deconstruct()。
